# 📚 정보처리기사 대비 학습 자료: 1과목. 소프트웨어 설계
## 🌟 2장. 화면 설계 (Screen Design / UI/UX Design)

### 📌 1. 화면 설계란 무엇인가? (Definition)
화면 설계는 시스템의 기능을 사용자 인터페이스(UI)를 통해 사용자가 **직관적이고 효율적으로 사용할 수 있도록** 구조화하고 시각화하는 과정입니다. 단순히 예쁜 디자인을 넘어, **정보를 명확하게 전달하고, 사용자의 인지 부하를 최소화**하는 논리적 구조를 설계하는 것이 핵심입니다.

*   **핵심 목표:** 사용자가 '어떻게' 시스템을 조작할지(사용성)와 '어떤 정보'를 언제 볼지(정보구조)를 정의하는 것.
*   **관련 분야:** UI/UX 디자인 원칙 이해가 필수적입니다.

---

### 💡 2. 화면 설계의 핵심 요소 및 원칙
화면은 단순히 요소를 나열하는 것이 아니라, 일련의 원칙을 따라야 사용성이 확보됩니다.

#### **A. 정보구조 설계 (Information Architecture, IA)**
*   **목표:** 사용자가 원하는 정보에 도달하는 **논리적인 경로(Navigation)**를 설계하는 것.
*   **주요 활동:** 메뉴 구조 정의, 정보의 계층(Hierarchy) 설정, 검색 및 분류 체계 확립.
*   **핵심 개념:** **'정보 아키텍처 맵'**을 통해 사이트맵(Sitemap)을 만듭니다.

#### **B. 사용자 경험/인터페이스 설계 (UX/UI Design)**
*   **사용자 경험 (UX: User Experience):** 사용자가 시스템을 사용하면서 **느끼는 모든 감정적 경험**의 총체. (사용의 편리성, 만족도, 효율성 포함)
*   **사용자 인터페이스 (UI: User Interface):** 사용자가 시스템과 **실제로 상호작용하는 접점** (버튼, 레이아웃, 색상, 폰트 등 시각적 요소).

*   **핵심 원칙:**
    1.  **일관성 (Consistency):** 동일한 기능은 항상 동일한 위치와 방식으로 보여야 한다. (예: '저장' 버튼은 항상 오른쪽 하단에 위치)
    2.  **단순성 (Simplicity):** 한 화면에 너무 많은 정보를 담지 않고, 가장 중요한 정보부터 보여준다.
    3.  **피드백 (Feedback):** 사용자의 모든 행동에 대해 시스템이 즉각적으로 반응해야 한다. (예: 버튼 클릭 시 버튼 색상이 잠시 어두워짐)

### 🛠️ 3. 화면 설계 도구 및 산출물
| 산출물 이름 | 목적 | 주로 활용하는 기술/도구 | 적합한 단계 |
| :--- | :--- | :--- | :--- |
| **와이어프레임 (Wireframe)** | 화면의 **뼈대(레이아웃, 배치)**를 와이어(막대)로 단순하게 구조화. (색상/이미지 배제)
| **프로토타입 (Prototype)** | 실제 작동하는 **시뮬레이션 버전**. 사용 흐름(User Flow) 테스트에 사용. | Figma, Adobe XD 등 | 테스트 및 검증 단계 |
| **사용자 스토리 (User Story)** | 기능 개발 시 **관점 기반의 요구사항**으로 기술. (예: '사용자로서 나는 ~하고 싶다.') | 애자일 방법론 | 요구사항 정의 단계 |

---

### 🚀 4. 학습 요약 및 체크 포인트 (Self-Test)

1.  **가장 중요한 목표:** 화면 설계의 궁극적인 목표는? (👉 사용자가 **직관적이고 효율적으로** 시스템을 사용하도록 만드는 것)
2.  **UX와 UI의 관계:** 둘의 가장 큰 차이점은? (👉 **UX는 경험(Experience)** 전체, **UI는 상호작용하는 화면 요소(Interface)** 그 자체)
3.  **와이어프레임의 의미:** 와이어프레임에서 절대 고려해서는 안 되는 것은? (👉 **색상, 실제 폰트, 최종 이미지** 등 시각적 요소)
4.  **사용성 원칙 위반:** 버튼을 누를 때 아무런 반응이 없으면 어떤 원칙을 위반한 것인가? (👉 **피드백(Feedback)** 원칙 위반)
