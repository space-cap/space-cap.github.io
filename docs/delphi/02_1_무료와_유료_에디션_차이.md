# 무료와 유료 에디션 차이

> 작성 기준일: 2026-05-19  
> 목표: Delphi Community Edition과 유료 에디션의 차이를 입사 전 학습자 관점에서 이해한다.  
> 주의: 이 문서는 구매/법무 판단을 대신하지 않는다. 최종 기준은 Embarcadero License Agreement, 공식 Feature Matrix, 회사 보유 라이선스다.

## 1. 먼저 결론

Delphi Community Edition은 "Delphi를 배워보고 작은 개인 프로젝트를 시작하는 문"으로는 좋다. 그러나 회사 업무 개발 도구로는 매우 조심해야 한다.

유료 에디션은 단순히 기능이 더 많은 버전이 아니다. 회사 업무에서 필요한 라이선스 안정성, 기술 지원, 원격 DB 접근, 서버/멀티티어 기능, 업데이트 구독, 빌드 환경 운용 같은 문제와 연결된다.

짧게 정리하면 이렇다.

| 상황 | 적합한 방향 |
| --- | --- |
| 개인 학습, 취미 프로젝트 | Community Edition 검토 가능 |
| 개인 매출이 US$5,000 미만인 제한된 상업적 사용 | Community Edition 조건 확인 후 검토 |
| 회사 매출이 US$5,000 초과 | Professional 이상 필요 가능성이 높음 |
| 개발팀이 5명 초과 | Professional 이상 필요 |
| 원격 DB, 엔터프라이즈 DB, 서버 기능 필요 | Enterprise 또는 Architect 검토 |
| 공식 기술 지원과 업데이트 구독 필요 | 유료 에디션 검토 |

## 2. Delphi 에디션 종류

Embarcadero의 Delphi 제품 페이지와 FAQ 기준 Delphi는 다음 에디션으로 안내된다.

| 에디션 | 대략적인 위치 |
| --- | --- |
| Community | 무료, 제한된 상업적 사용, 개인/학습/초기 단계용 |
| Professional | 일반 상용 개발용 기본 유료 에디션 |
| Enterprise | 원격 DB, 서버/멀티티어, 엔터프라이즈 개발 기능이 필요한 팀용 |
| Architect | Enterprise 기능에 더해 아키텍처, 모델링, 추가 도구/라이선스가 필요한 조직용 |

RAD Studio는 Delphi와 C++Builder를 함께 포함할 수 있는 제품군이며, RAD Studio 자체는 Professional, Enterprise, Architect 에디션으로 안내된다. 반면 Community Edition은 RAD Studio CE가 아니라 Delphi CE와 C++Builder CE 형태로 제공된다고 공식 FAQ가 설명한다.

## 3. Community Edition의 성격

Community Edition은 무료지만 "아무 제한 없는 무료"가 아니다.

공식 FAQ 기준 핵심은 다음과 같다.

- 무료 다운로드 가능
- 개인, 학생, 취미 개발자, 오픈소스 기여자, 초기 스타트업에 적합
- 연간 매출이 US$5,000에 도달하면 유료 라이선스 필요
- 회사 내부 앱 개발/배포는 회사 총 매출 조건과 연결됨
- 개발팀이 5명을 초과하면 유료 라이선스 필요
- 1년 기간 라이선스
- CE 설치는 Web 기반 GetIt installer 사용
- 유료 에디션과 달리 기술 지원과 업데이트/운영 조건에 차이가 있음

가장 중요한 문장은 이것이다.

> Community Edition은 학습용으로 시작하기 좋지만, 일반적인 회사 업무용 무료 라이선스로 보면 안 된다.

## 4. Professional Edition의 위치

Professional은 상용 개발을 위한 기본 유료 에디션으로 이해하면 된다.

Community Edition과 비교했을 때 Professional을 선택하는 핵심 이유는 기능 몇 개보다도 제한 해제에 가깝다.

| 관점 | Community | Professional |
| --- | --- | --- |
| 비용 | 무료 | 유료 |
| 매출 제한 | 있음 | CE의 연간 매출 제한 없음 |
| 기간 | 1년 기간으로 안내 | 유료 라이선스/구독 조건 적용 |
| 기술 지원 | 제한적 | 유료 지원/업데이트 구독 가능 |
| 회사 업무 | 조건에 따라 제한 | 일반 상용 개발에 적합 |
| 빌드 환경 운용 | 제한 있음 | 명령줄 컴파일러/빌드 환경 운용 여지가 큼 |

회사에서 Windows 업무 프로그램을 만들고, 원격 DB나 서버 기능이 크지 않으며, 기본적인 상용 개발 라이선스가 필요하다면 Professional이 출발점이 될 수 있다.

다만 DB 기능은 반드시 확인해야 한다. 많은 ERP/MES/업무 프로그램은 Microsoft SQL Server, Oracle, MySQL 같은 원격 DB와 연결된다. 이 경우 Professional만으로 충분한지, Enterprise 이상이 필요한지 Feature Matrix와 회사 실제 연결 방식을 확인해야 한다.

## 5. Enterprise Edition의 위치

Enterprise는 이름 그대로 기업 업무 시스템 개발에 더 가까운 에디션이다.

공식 제품 설명과 FAQ를 종합하면 Enterprise 영역에서 중요하게 봐야 할 것은 다음이다.

- 원격 DB, Client/Server DB 접근
- FireDAC의 더 넓은 DB 드라이버 범위
- DataSnap 같은 멀티티어 애플리케이션 기술
- RAD Server 배포 라이선스 일부
- Linux 서버 애플리케이션 개발 지원
- 더 복잡한 기업 시스템 연동

ERP, MES, 그룹웨어, 물류, 생산관리처럼 DB가 중심인 업무 시스템에서는 Enterprise급 기능이 필요한 경우가 많다. 특히 "개발 PC에서 직접 MS-SQL/Oracle 운영 또는 개발 DB에 붙는다"는 환경이라면 에디션 차이를 가볍게 보면 안 된다.

## 6. Architect Edition의 위치

Architect는 Enterprise의 상위 에디션이다. 단순히 IDE 기능 하나 더 있는 버전이 아니라, 조직 단위의 설계/모델링/데이터 도구/추가 라이선스가 필요한 경우를 겨냥한다.

공식 Delphi 제품 에디션 설명은 Architect가 Enterprise와 Professional 기능을 포함하고, RAD Server multi-site deployment license, Sencha Ext JS Professional license, InterBase ToGo license, 고급 데이터 모델링/디자인 기능 등을 포함한다고 안내한다.

일반 신입 개발자가 당장 Architect 기능을 직접 만질 가능성은 낮다. 하지만 회사가 Architect를 쓰고 있다면 이유가 있다.

- 여러 지점/사이트에 서버를 배포한다.
- 데이터 모델링과 설계 도구가 중요하다.
- 웹/REST/서버 기능과 함께 묶어 쓴다.
- 복잡한 기업 시스템을 장기 운영한다.

## 7. 기능 차이를 볼 때의 기준

에디션 비교표를 볼 때는 "체크가 몇 개 더 많다"보다, 내 회사 프로젝트에 직접 필요한 기능을 중심으로 읽어야 한다.

| 확인 기준 | 질문 |
| --- | --- |
| 플랫폼 | Win32만 쓰는가, Win64도 쓰는가, 모바일/서버도 필요한가? |
| UI 프레임워크 | VCL인가, FireMonkey인가? |
| DB | 로컬 DB인가, 원격 DB인가, 어떤 DBMS인가? |
| 서버 기능 | REST 서버, DataSnap, RAD Server가 필요한가? |
| 빌드 | 개발자 PC에서만 빌드하는가, 빌드 서버가 있는가? |
| 배포 | 단일 실행 파일 복사인가, 설치 프로그램/자동 업데이트인가? |
| 지원 | 공식 기술 지원이 필요한 조직인가? |
| 업데이트 | 최신 버전과 패치를 꾸준히 받아야 하는가? |
| 외부 컴포넌트 | 유료 컴포넌트가 특정 에디션을 요구하는가? |

업무 시스템에서는 DB와 배포가 특히 중요하다. Delphi 화면은 CE에서 열려도, 실제 회사 DB 드라이버나 배포 조건 때문에 유료 에디션이 필요할 수 있다.

## 8. DB 기능 차이를 특히 조심해야 하는 이유

Delphi 업무 프로그램은 DB와 붙어 있는 경우가 많다. 화면만 고치는 것처럼 보여도 실제로는 다음 코드가 뒤에 있다.

```pascal
Query.ParamByName('CUSTOMER_ID').AsString := CustomerId;
Query.Open;
```

또는 저장 버튼 뒤에 이런 흐름이 있을 수 있다.

```text
입력값 검증
-> Transaction 시작
-> INSERT/UPDATE 실행
-> Commit
-> Grid 새로고침
```

공식 FAQ는 Community Edition에 로컬/임베디드 DB 연결 기능이 포함된다고 설명하면서, Microsoft SQL Server, Oracle, Sybase, SQL Anywhere, InterBase, DB2, Informix, MongoDB, MySQL, ODBC 등 넓은 범위의 원격 DB 접근은 Enterprise 또는 Architect 구매 대상으로 안내한다.

그래서 입사 후에는 다음을 꼭 확인해야 한다.

1. 회사 DBMS가 무엇인가?
2. Delphi에서 FireDAC을 쓰는가, ADO를 쓰는가, 다른 컴포넌트를 쓰는가?
3. DB 드라이버가 어느 에디션에서 지원되는가?
4. 개발 DB 접속은 로컬인가, 원격인가?
5. 운영 DB 접속 설정은 어디에 저장되는가?

## 9. 무료와 유료의 차이를 실무 문장으로 바꾸기

제품 비교표만 보면 추상적이다. 실무 문장으로 바꾸면 훨씬 선명하다.

| 상황 | 의미 |
| --- | --- |
| 집에서 Delphi 문법을 공부한다 | CE로 시작해도 괜찮은 영역 |
| 개인 토이 프로젝트를 만든다 | CE 조건 확인 후 가능성이 높은 영역 |
| 회사 PC에 CE를 설치한다 | 회사 정책과 라이선스 확인 필요 |
| 회사 프로젝트를 CE로 연다 | 위험. 회사 라이선스 확인 필요 |
| 회사 고객에게 납품할 프로그램을 CE로 빌드한다 | 매우 위험. 유료 라이선스 확인 필요 |
| 회사가 MS-SQL/Oracle 기반 업무 시스템을 만든다 | Enterprise 이상 필요 여부 확인 |
| 개발자가 6명 이상 같은 회사에서 개발한다 | CE 사용 조건에서 벗어날 가능성이 높음 |

도구가 실행된다고 해서 라이선스가 허용된 것은 아니다. 이 차이를 이해하는 개발자가 실무에서 신뢰를 얻는다.

## 10. 입사 전 개인 학습용 추천 판단

입사 전 개인 학습이라면 다음 순서가 좋다.

1. 개인 PC에 CE 설치 가능 여부를 공식 FAQ 기준으로 확인한다.
2. CE가 현재 어떤 버전으로 제공되는지 확인한다.
3. VCL Forms Application을 기준으로 IDE 화면과 이벤트 흐름을 익힌다.
4. DB는 처음부터 회사 DB를 흉내 내지 말고 간단한 로컬 예제로 시작한다.
5. 회사 입사 후에는 회사가 제공하는 정식 개발 환경으로 갈아탄다.

이렇게 하면 학습과 실무 라이선스가 섞이지 않는다.

## 11. 입사 후 회사 업무용 추천 판단

입사 후에는 개인 판단으로 CE를 쓰지 말고 회사 기준을 따른다.

회사에 아래처럼 물어보면 된다.

```text
Delphi 학습용으로는 개인 PC에 Community Edition을 설치했습니다.
회사 프로젝트를 열거나 빌드할 때는 회사 라이선스를 사용해야 할 것 같은데,
회사 표준 Delphi 버전과 에디션, 설치 절차를 알려주실 수 있을까요?
```

이 문장은 세 가지를 동시에 보여준다.

- 이미 공부하고 있다.
- 라이선스 리스크를 알고 있다.
- 회사 표준 환경을 존중한다.

## 12. 공식 Feature Matrix 읽는 법

Feature Matrix는 처음 보면 길고 피곤하다. 다음 순서로 보면 된다.

1. 내가 쓰는 제품이 Delphi 단독인지 RAD Studio인지 확인한다.
2. Community Edition이 현재 어느 버전 기준인지 주석을 확인한다.
3. `Professional / Community`, `Enterprise`, `Architect` 열을 비교한다.
4. `Database`, `FireDAC`, `DataSnap`, `RAD Server`, `Target Platforms`, `Build Tools` 항목을 먼저 본다.
5. 회사 프로젝트에서 쓰는 기능에 체크가 있는지 확인한다.
6. 애매하면 회사 라이선스 담당자 또는 선배에게 물어본다.

특히 최신 Feature Matrix는 최신 유료 제품 기준 기능을 함께 보여줄 수 있다. CE가 그 최신 제품과 동일하다고 가정하지 않는다.

## 바로 해볼 실습

1. 공식 Community Edition FAQ에서 매출 제한, 개발자 수 제한, 1년 기간 내용을 찾는다.
2. 공식 Product Editions 페이지에서 Community, Professional, Enterprise, Architect 설명을 비교한다.
3. Feature Matrix PDF를 열고 `FireDAC`, `RAD Server`, `DataSnap` 키워드를 찾아본다.
4. 내가 입사할 회사가 원격 DB를 쓸 가능성이 있는지 메모한다.
5. 회사에 물어볼 라이선스 질문 5개를 적어본다.

## 입사 후 확인할 질문

1. 회사 표준 Delphi 에디션은 무엇인가요?
2. 현재 프로젝트는 어떤 DBMS와 어떤 컴포넌트로 연결하나요?
3. Professional로 충분한가요, Enterprise/Architect 기능을 쓰나요?
4. 개발자별 라이선스가 지급되나요, 공용 빌드 PC가 있나요?
5. Update Subscription이나 유지보수 계약이 있나요?
6. Community Edition으로 회사 프로젝트를 열면 안 되는 정책이 있나요?

## 자주 막히는 지점

- CE를 평가판처럼 생각한다. 공식 FAQ는 CE가 Trial이 아니라고 설명한다.
- RAD Studio CE가 있다고 착각한다. 공식 FAQ 기준 CE는 Delphi CE와 C++Builder CE 형태다.
- 회사 매출 제한을 "내 개인 수입"으로만 생각한다.
- DB 기능 차이를 IDE 화면 기능 차이 정도로 가볍게 본다.
- 최신 Feature Matrix의 기능을 내 CE 설치본에도 있다고 가정한다.
