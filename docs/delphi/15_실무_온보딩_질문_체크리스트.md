# 실무 온보딩 질문 체크리스트

> 작성 기준일: 2026-05-19  
> 대상 독자: Delphi 개발 환경으로 입사 예정이거나 입사 초기인 개발자  
> 목표: 선배 개발자, 팀장, PM, 운영 담당자에게 물어볼 질문을 정리해 실무 맥락과 위험 지점을 빠르게 파악한다.

## 1. 먼저 질문하는 태도

입사 초기 질문의 목적은 "모르는 것을 들키지 않기"가 아니다. 위험한 실수를 줄이고, 팀의 기존 방식을 빨리 흡수하는 것이다.

Delphi 프로젝트는 오래 운영된 업무 시스템일 가능성이 높다. IDE 버전, 외부 컴포넌트, DB 접속, 빌드 순서, 배포 방식이 서로 연결되어 있다. 그래서 질문을 잘하는 것이 곧 생산성이다.

좋은 질문은 이렇게 생겼다.

```text
제가 개인 학습용으로는 Delphi Community Edition을 설치해봤습니다.
회사 프로젝트는 라이선스와 컴포넌트가 다를 것 같아서,
표준 Delphi 버전/에디션과 설치 순서를 먼저 확인하고 싶습니다.
```

이런 질문은 준비성과 신중함을 동시에 보여준다.

## 2. Delphi 버전과 라이선스 질문

- 회사에서 사용하는 정확한 제품명은 무엇인가? Delphi인가, RAD Studio인가?
- 버전은 무엇인가? 예: 10.4, 11.x, 12.1, 12.3 등
- 에디션은 무엇인가? Community, Professional, Enterprise, Architect 중 무엇인가?
- 회사 업무에 Community Edition 사용이 허용되는가?
- 개발자별 개인 라이선스가 지급되는가?
- 라이선스 서버 또는 네트워크 라이선스를 사용하는가?
- Update Subscription 또는 유지보수 계약이 있는가?
- 빌드 PC와 개발자 PC의 Delphi 버전이 같은가?
- 외부 컴포넌트 라이선스는 별도 관리되는가?
- 퇴사/입사 시 라이선스 회수와 재발급 절차가 있는가?

## 3. IDE와 개발환경 질문

- IDE 설치 파일은 어디에 있는가?
- 설치 순서 문서가 있는가?
- IDE 설정을 팀 표준으로 맞추는 방법이 있는가?
- 기본 테마, 폰트, 레이아웃 권장값이 있는가?
- Library Path, Search Path 설정을 수동으로 해야 하는가?
- 환경 변수나 레지스트리 설정이 필요한가?
- GetIt으로 설치해야 하는 항목이 있는가?
- IDE를 관리자 권한으로 실행해야 하는 경우가 있는가?
- 32-bit IDE/64-bit IDE 관련 주의사항이 있는가?
- 개발 PC 초기 세팅에 보통 얼마나 걸리는가?

## 4. 프로젝트 구조 질문

- 메인 Form은 무엇인가?
- Login Form, Main Form, DataModule 생성 순서는 어떻게 되는가?
- 자동 생성 Form과 수동 생성 Form을 어떻게 구분하는가?
- 공통 unit과 업무별 unit은 어떤 폴더에 있는가?
- 고객사별 커스터마이징 소스는 어떻게 분리되는가?
- 운영 중인 버전과 개발 중인 버전의 소스 브랜치는 어떻게 나뉘는가?
- 현재 가장 자주 수정하는 화면/모듈은 무엇인가?

## 5. UI 프레임워크와 화면 개발 질문

- 기존 프로젝트는 VCL인가, FireMonkey인가?

- 공통 상단/하단 버튼 패널이 있는가?
- 화면 이름 규칙이 있는가?
- 컴포넌트 이름 규칙이 있는가? 예: `btnSave`, `edtName`, `qryList`
- 화면 문구는 코드에 직접 쓰는가, 리소스/상수/DB로 관리하는가?
- 화면 권한 제어는 어디에서 처리하는가?
- 다국어 지원이 있는가?
- 고해상도 DPI나 폰트 크기 이슈가 있는가?
- 화면 변경 후 반드시 테스트해야 하는 기본 해상도가 있는가?

## 6. 외부 컴포넌트와 패키지 질문

- 설치 파일과 라이선스 키는 어디에서 받는가?
- design-time package와 runtime package를 구분해 관리하는가?
- 사내 공통 패키지 `.dpk` 빌드 순서가 있는가?

- Form Designer에서 `Class not found`가 나면 누구에게 문의해야 하는가?

## 7. 빌드와 실행 질문

- 기본 Build Configuration은 Debug인가, Release인가?
- 운영 배포는 어떤 Configuration으로 빌드하는가?
- 기본 Target Platform은 Win32인가, Win64인가?
- Win32/Win64를 모두 지원해야 하는가?
- Clean/Build 순서가 정해져 있는가?
- 빌드 산출물 output directory는 어디인가?

## 바로 해볼 실습

1. 위 질문 중 입사 첫날 반드시 물어볼 질문 10개를 고른다.
2. 개발환경 관련 질문, DB 관련 질문, 배포 관련 질문을 색깔별로 나눈다.
3. 답변을 받은 뒤 개인 온보딩 노트에 정리한다.
4. 모호한 답변은 실제 파일 경로, 화면명, 담당자 이름까지 보강한다.
5. 일주일 뒤 다시 읽고 빠진 질문을 추가한다.

## 자주 막히는 지점

- 라이선스와 설치 질문을 뒤로 미룬다.
- 운영 DB와 개발 DB 구분을 대충 넘긴다.
- 외부 컴포넌트 버전을 정확히 기록하지 않는다.
- 빌드/배포 절차를 "나중에 보면 되겠지"라고 생각한다.
- `.dfm`, `.dproj` 변경이 왜 중요한지 묻지 않는다.
- 첫 작업 범위를 스스로 크게 잡는다.
