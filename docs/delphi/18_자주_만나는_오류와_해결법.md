# 자주 만나는 오류와 해결법

> 작성 기준일: 2026-05-19  
> 대상 독자: Delphi 프로젝트를 열고 빌드/실행하다가 오류를 만난 입사 초기 개발자  
> 목표: 오류 메시지를 보고 코드 문제, 경로 문제, 패키지 문제, DB 문제를 빠르게 구분한다.

## 1. 오류를 만나면 먼저 할 일

오류가 나면 바로 코드를 고치지 말고 다음을 먼저 기록한다.

```text
오류 메시지 원문:
발생 시점: IDE 열기 / Form 열기 / Build / Run / DB 조회 / 배포 후 실행
Build Configuration:
Target Platform:
최근 변경 파일:
관련 Form/Unit:
재현 절차:
```

Delphi 오류는 코드 문제가 아니라 환경 문제인 경우가 많다.

## 2. 오류 유형 빠른 분류

| 증상 | 가능성이 큰 원인 |
| --- | --- |
| `Unit not found` | Search Path, Library Path, 파일 누락 |
| `Class xxx not found` | 외부 컴포넌트 미설치 |
| `Package xxx.bpl not found` | BPL 경로/설치 문제 |
| `compiled with a different version` | DCU/DCP 버전 충돌 |
| Form Designer가 안 열림 | `.dfm` 컴포넌트/패키지 문제 |
| 브레이크포인트가 안 걸림 | Debug 설정, 다른 EXE 실행, 이벤트 연결 |
| DB 연결 실패 | 서버/계정/드라이버/방화벽 |
| 운영에서는 되는데 내 PC에서 안 됨 | 환경 설정/컴포넌트/드라이버 차이 |

## 3. `Unit xxx not found`

예:

```text
Unit CommonUtils not found
File not found: 'CommonUtils.dcu'
```

가능한 원인:

- 소스 파일이 없다.
- 공통 라이브러리 저장소를 받지 않았다.
- Search Path가 빠졌다.
- Library Path가 빠졌다.
- 패키지를 먼저 빌드하지 않았다.
- Win32/Win64 산출물 경로가 다르다.

해결 순서:

1. 파일명으로 전체 폴더 검색한다.
2. 파일이 없으면 별도 저장소/서브모듈인지 확인한다.
3. 파일이 있으면 Search Path에 포함되어 있는지 확인한다.
4. 패키지 빌드 순서를 확인한다.
5. Clean 후 Build한다.

## 4. `Identifier not found`

예:

```text
Undeclared identifier: 'ShowMessage'
```

가능한 원인:

- `uses`에 필요한 unit이 없다.
- 이름 오타가 있다.
- 조건부 컴파일 때문에 코드가 빠졌다.
- Delphi 버전 차이로 API가 없다.
- 컴포넌트 이름을 바꿨는데 코드 참조가 남았다.

해결:

1. 오타 확인
2. 필요한 unit 확인
3. 컴포넌트 `Name` 변경 여부 확인
4. 조건부 define 확인
5. 같은 코드가 다른 PC에서 빌드되는지 확인

## 5. `Class xxx not found`

예:

```text
Class TcxGrid not found
Class TAdvStringGrid not found
```

가능한 원인:

- 외부 컴포넌트가 IDE에 설치되지 않았다.
- design-time package가 로드되지 않았다.
- 컴포넌트 버전이 다르다.
- `.dfm`에는 컴포넌트가 있는데 IDE가 클래스를 모른다.

해결:

1. 오류 메시지의 class 이름을 기록한다.
2. 어떤 컴포넌트 제품/사내 패키지인지 확인한다.
3. 회사 표준 버전을 설치한다.
4. IDE를 재시작한다.
5. Form Designer를 다시 연다.

주의: `.dfm`에서 해당 object를 직접 삭제하지 않는다.

## 6. `Package xxx.bpl not found`

가능한 원인:

- runtime package가 없다.
- BPL 경로가 PATH에 없다.
- Win32/Win64 BPL을 혼동했다.
- Debug/Release BPL이 섞였다.
- 다른 Delphi 버전으로 빌드된 BPL이다.

해결:

1. BPL 파일이 실제로 있는지 찾는다.
2. EXE와 같은 폴더 또는 PATH에서 찾을 수 있는지 확인한다.
3. Target Platform과 BPL 비트 수가 맞는지 확인한다.
4. 패키지를 회사 표준 순서로 다시 빌드한다.
5. 운영 배포 파일 목록에 BPL이 포함되는지 확인한다.

## 7. `compiled with a different version`

예:

```text
Unit CommonUtils was compiled with a different version of System.SysUtils
```

가능한 원인:

- 오래된 `.dcu`를 참조한다.
- 다른 Delphi 버전 산출물이 섞였다.
- Win32/Win64 산출물이 섞였다.
- Library Path 우선순위가 잘못됐다.
- 패키지 전체를 다시 빌드하지 않았다.

해결:

1. Clean 한다.
2. 관련 `.dcu`, `.dcp`, `.bpl`을 확인한다.
3. output 경로를 비운다.
4. 공통 패키지부터 순서대로 Build한다.
5. Library Path에 같은 파일명이 여러 곳에 있는지 확인한다.

## 8. `Unsatisfied forward declaration`

예:

```text
Unsatisfied forward or external declaration: TMainForm.ValidateInput
```

원인:

- class 선언부에 메서드를 선언했지만 구현부가 없다.
- 메서드 시그니처가 선언과 구현에서 다르다.
- 파라미터 타입이나 이름 변경 중 꼬였다.

해결:

1. 선언부와 구현부 이름을 비교한다.
2. 반환 타입과 파라미터를 비교한다.
3. `Ctrl+Shift+C` Class Completion으로 구현부를 생성한다.

## 9. Form Designer가 안 열림

증상:

```text
Error reading MainForm.dfm
Property xxx does not exist
Class xxx not found
```

가능한 원인:

- 컴포넌트 미설치
- 컴포넌트 버전 불일치
- `.dfm` 충돌 해결 실패
- 이벤트 메서드 삭제/이름 변경

해결:

1. 오류 메시지를 저장한다.
2. `.dfm` Git diff를 확인한다.
3. 외부 컴포넌트 설치 여부를 확인한다.
4. 같은 프로젝트가 선배 PC에서 열리는지 확인한다.
5. 직접 `.dfm`을 수정하기 전 리뷰를 요청한다.

## 10. 브레이크포인트가 안 걸림

가능한 원인:

- Release로 실행 중이다.
- 내가 보는 소스와 실행 EXE가 다르다.
- 이벤트가 연결되지 않았다.
- 해당 코드 경로가 실행되지 않는다.
- 패키지/BPL 디버그 정보가 없다.

해결:

1. Debug 구성 확인
2. Target Platform 확인
3. EXE 생성 시간 확인
4. Object Inspector에서 이벤트 연결 확인
5. 이벤트 첫 줄에 브레이크포인트 설정
6. Clean 후 Build

## 11. DB 연결 실패

예:

```text
Login failed
Connection is not established
Network-related or instance-specific error
```

가능한 원인:

- DB 서버 주소가 틀렸다.
- 계정/비밀번호가 틀렸다.
- 방화벽/VPN 문제다.
- DB 클라이언트 드라이버가 없다.
- 32비트/64비트 드라이버가 Target Platform과 다르다.
- 운영/개발 설정 파일을 혼동했다.

해결:

1. 개발 DB인지 운영 DB인지 확인한다.
2. 설정 파일 경로를 확인한다.
3. DB 클라이언트/ODBC 드라이버 비트 수를 확인한다.
4. 같은 계정으로 DB 도구에서 접속해본다.
5. 선배에게 표준 접속 설정을 확인한다.

## 12. SQL 오류

자주 보는 오류:

| 오류 | 원인 |
| --- | --- |
| invalid column name | 컬럼명 오타, DB 버전 차이 |
| table does not exist | 테이블명/스키마/권한 문제 |
| primary key violation | 중복 키 |
| foreign key violation | 참조 데이터 없음 |
| string or binary data would be truncated | 컬럼 길이 초과 |

확인:

1. SQL 원문
2. ParamByName 값
3. 접속 DB
4. 테이블/컬럼 존재 여부
5. 테스트 데이터

## 13. 배포 후 실행 오류

가능한 원인:

- DLL/BPL 누락
- 설정 파일 누락
- DB 드라이버 누락
- Win32/Win64 불일치
- 운영 PC 권한 문제
- 상대 경로 기준이 다름

해결:

1. 배포 파일 목록과 실제 폴더를 비교한다.
2. EXE와 같은 폴더의 DLL/BPL을 확인한다.
3. 설정 파일 경로를 확인한다.
4. 운영 PC의 DB 드라이버 설치 여부를 확인한다.
5. 롤백 절차를 따른다.

## 14. Git 충돌 후 이상 동작

가능한 원인:

- `.dfm` 충돌을 잘못 해결했다.
- `.dproj` 설정이 사라졌다.
- 이벤트 연결이 끊겼다.
- 컴포넌트 이름이 바뀌었다.

확인:

1. Git diff에서 `.dfm`, `.dproj` 확인
2. Form Designer로 열리는지 확인
3. Object Inspector의 이벤트 연결 확인
4. Build 후 실행 테스트

## 15. 오류 대응 원칙

1. 원문 메시지를 보존한다.
2. 첫 번째 실제 Error부터 본다.
3. 코드/경로/패키지/DB 문제를 구분한다.
4. 최근 변경을 확인한다.
5. Clean/Build는 하되 원인 기록을 남긴다.
6. 운영 DB나 배포 환경에서는 혼자 실험하지 않는다.

3. Form Designer 오류는 누구에게 먼저 물어보나요?
4. DB 연결 실패 시 확인할 표준 체크리스트가 있나요?
5. 배포 후 DLL/BPL 누락을 확인하는 절차가 있나요?
