# 입사 초기 30일 학습 로드맵

> 작성 기준일: 2026-05-19  
> 대상 독자: Delphi IDE를 처음 쓰는 입사 초기 개발자  
> 목표: 30일 동안 IDE, 프로젝트 구조, 디버깅, DB, 빌드, 배포 흐름을 단계적으로 익히고 작은 실무 수정까지 도달한다.

## 1. 30일의 현실적인 목표

30일 안에 Delphi를 완전히 마스터하는 것은 목표가 아니다. 30일의 목표는 다음이다.

1. 회사 표준 Delphi 개발환경을 설치하고 설명할 수 있다.
2. 기존 프로젝트를 올바른 파일로 열 수 있다.
3. 메인 Form과 주요 화면의 이벤트 코드를 찾을 수 있다.
4. 브레이크포인트를 걸고 변수 값을 확인할 수 있다.
5. DB 조회/저장 코드의 기본 흐름을 읽을 수 있다.
6. Debug 빌드와 Release 빌드 차이를 이해한다.
7. 작은 화면 수정 또는 버그 수정을 리뷰받아 완료한다.
8. 내가 모르는 것과 위험한 것을 구분해 질문할 수 있다.

30일이 지나도 모르는 것은 많다. 괜찮다. 중요한 것은 혼자 위험한 결정을 하지 않는 감각이다.

## 3. 1~3일차: 개발환경과 큰 그림

목표:

- 회사 표준 개발환경을 설치한다.
- Delphi/RAD Studio 버전과 에디션을 확인한다.
- 프로젝트를 어떤 파일로 여는지 확인한다.
- 라이선스와 CE 사용 가능 여부를 명확히 한다.

해야 할 일:

1. 회사 표준 Delphi 설치 절차를 따른다.
2. `Help > About`에서 버전/에디션을 기록한다.
3. 외부 컴포넌트 설치 목록을 받는다.
4. Project Group 또는 메인 `.dproj` 위치를 확인한다.
5. Git 저장소를 클론한다.
6. README, 설치 문서, 빌드 문서를 먼저 읽는다.
7. 운영 DB 접속 가능 여부와 금지 사항을 확인한다.

## 5. 2주차: 코드 탐색과 디버깅

목표:

- 이벤트 시작점에서 실제 업무 로직까지 따라갈 수 있다.

해야 할 일:

5. Call Stack을 확인한다.
6. 같은 패턴의 다른 화면을 찾아 비교한다.
7. 자주 쓰는 공통 함수 목록을 만든다.

6. `.dfm` 충돌이나 변경 예시를 읽어본다.
7. Git 커밋 전 체크리스트를 만든다.

## 7. 4주차: 작은 실무 수정 따라가기

목표:

- 작은 수정 요청을 받아 영향 범위를 확인한다.
- 수정, 빌드, 테스트, 리뷰 요청까지 한 사이클을 경험한다.
- 운영 반영 절차를 관찰한다.

좋은 첫 작업 후보:

| 작업 | 이유 |
| --- | --- |
| 화면 문구 수정 | `.dfm` 변경을 익히기 좋다. |
| 버튼 Enabled 조건 수정 | 이벤트/상태 흐름을 익힐 수 있다. |
| 조회 조건 하나 추가 | 입력값, SQL 파라미터, Grid 갱신을 익힐 수 있다. |
| null 체크 추가 | 작은 버그 수정에 적합하다. |
| 로그 보강 | 운영 대응 흐름을 이해하기 좋다. |

피해야 할 첫 작업:

- DB 스키마 변경
- 대량 리팩터링
- 공통 패키지 구조 변경
- 운영 DB 직접 수정
- 배포 스크립트 수정
- 마감/정산/확정 로직 변경

해야 할 일:

1. 수정 요청을 한 문장으로 정리한다.
2. 관련 화면과 이벤트를 찾는다.
3. DB 영향 여부를 확인한다.
4. 수정 전 현재 동작을 재현한다.
5. 작은 단위로 수정한다.
6. Debug 빌드 후 테스트한다.
7. Git diff에서 `.pas`, `.dfm`, `.dproj`를 확인한다.
8. 선배에게 리뷰를 요청한다.
9. 리뷰 반영 후 다시 테스트한다.
10. 배포 절차를 관찰하거나 기록한다.

산출물:

```text
첫 수정 이슈 정리
수정 전/후 동작 메모
테스트 결과
리뷰 피드백
배포 관찰 메모
```
