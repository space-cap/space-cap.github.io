# 01. Elixir의 탄생과 철학: 왜 Elixir인가?

안녕하세요! 30년 BEAM(Erlang VM) 생태계의 여정을 걸어온 선배로서, 여러분을 Elixir의 세계로 안내하게 되어 매우 기쁩니다. 첫 번째 장에서는 우리가 왜 Elixir라는 언어에 주목해야 하는지, 그리고 이 언어가 탄생하게 된 흥미로운 배경과 그 밑바탕에 흐르는 철학을 살펴보겠습니다.

---

## 1. Elixir의 탄생: 호세 발림(José Valim)의 고민

Elixir는 2011년, Ruby on Rails의 핵심 기여자인 **호세 발림**에 의해 세상에 나왔습니다. 당시 그는 현대적인 하드웨어(멀티코어 CPU)의 성능을 최대한 활용하면서도, 개발자가 생산성을 잃지 않는 언어를 찾고 있었습니다.

하지만 당시 대중적이었던 언어들은 다음과 같은 한계가 있었죠:
- **멀티코어 활용의 어려움**: 한 번에 하나의 일만 처리하는 구조(GIL 등) 때문에 코어가 많아져도 속도가 비례해서 빨라지지 않았습니다.
- **가용성(Availability) 확보**: 시스템의 일부가 고장 나면 전체가 멈춰버리는 문제가 잦았습니다.

이때 호세 발림은 통신 업계에서 20년 넘게 무중단 시스템(99.9999999% 가용성)을 구축하는 데 사용되었던 **Erlang(얼랭)**이라는 언어와 **BEAM 가상 머신**을 발견하게 됩니다.

> "Erlang의 강력한 동시성 제어 능력에 Ruby의 아름답고 생산적인 문법을 입힐 수는 없을까?"

이 질문이 바로 Elixir의 시작이었습니다.

## 2. Elixir의 핵심 철학 (Three Pillars)

Elixir는 단순히 예쁜 문법을 가진 언어가 아닙니다. 그 밑바탕에는 세 가지 강력한 기둥이 있습니다.

### ① 확장성 (Scalability)
Elixir 코드는 수천, 수만 개의 **경량 프로세스**에서 실행됩니다. 각 프로세스는 서로 완전히 독립적이며, 하드웨어의 모든 CPU 코어를 남김없이 사용하도록 설계되었습니다. 서버 한 대에서 시작해 수백 대의 분산 환경으로 확장하는 것이 Elixir에서는 매우 자연스럽습니다.

### ② 결함 허용 (Fault Tolerance)
시스템에 문제가 생겼을 때, "절대 죽지 않는 코드"를 짜는 대신 Elixir는 **"죽어도 괜찮은 코드"**를 지향합니다. 문제가 발생한 프로세스는 죽게 내버려 두고, 감시자(Supervisor)가 이를 감지하여 즉시 깨끗한 상태로 다시 살려냅니다. 이를 통해 전체 시스템은 중단 없이 계속 작동합니다.

### ③ 생산성 (Productivity)
개발자는 행복해야 합니다. Elixir는 현대적인 도구들(Mix, IEx, Hex)과 파이프 연산자(`|>`) 같은 우아한 문법을 제공하여, 복잡한 로직을 마치 시를 쓰듯 명확하게 표현할 수 있게 도와줍니다.

## 3. Elixir가 해결하는 현대적 과제

오늘날 우리가 만드는 애플리케이션은 수많은 사용자가 동시에 접속하고, 실시간으로 데이터를 주고받아야 합니다.
- **채팅 서비스 (WhatsApp, Discord)**: 디스코드는 수억 명의 동시 접속자를 관리하기 위해 Elixir를 사용합니다.
- **실시간 데이터 대시보드**: 끊김 없는 데이터 업데이트가 필수인 곳에서 빛을 발합니다.
- **고가용성 API 서버**: 한순간도 멈춰서는 안 되는 금융, 통신 시스템에 최적입니다.
