# 19. 디버깅 기술: 에러의 실타래 풀기

아무리 노련한 개발자라도 버그는 피할 수 없습니다. 중요한 것은 그 버그를 얼마나 빠르고 정확하게 찾아내느냐입니다. Elixir가 제공하는 강력한 디버깅 도구들을 소개합니다.

---

## 1. IO.inspect: 가장 친숙한 무기

값을 출력해서 확인하는 기본 도구입니다. 파이프라인 중간에 넣어 결과를 가로챌 수 있다는 점이 매력적입니다.

```elixir
[1, 2, 3]
|> Enum.map(&(&1 * 2))
|> IO.inspect(label: "곱셈 결과") # 여기서 값을 확인하고 다음으로 넘깁니다.
|> Enum.sum()
```

---

## 2. dbg: Elixir 1.14의 혁명

`IO.inspect`보다 훨씬 진화한 도구입니다. 코드의 어떤 줄에서 어떤 값이 나왔는지 시각적으로 보여줍니다.

```elixir
# iex에서 실행 중일 때
"  elixir  " |> String.trim() |> String.upcase() |> dbg()
```
실행 결과가 각 단계별로 예쁘게 출력되어 흐름을 한눈에 알 수 있습니다.

---

## 3. IEx.pry: 코드 중간에 뛰어들기

코드 실행을 특정 지점에서 멈추고, 그 시점의 변수들을 자유롭게 조사하고 싶을 때 사용합니다.

```elixir
def my_function(data) do
  require IEx
  IEx.pry() # 여기서 실행이 멈추고 IEx 셸이 열립니다.
  # 데이터 조사 시작...
end
```
> [!NOTE]
> `IEx.pry`를 사용하려면 프로젝트를 `iex -S mix`로 실행해야 합니다.

---

## 4. Observer: 시스템 전체 조망하기 (GUI)

Elixir가 돌아가고 있는 BEAM 엔진 내부를 시각적으로 보여주는 강력한 도구입니다. 수천 개의 프로세스가 어떻게 움직이는지, 메모리는 얼마나 쓰는지 한눈에 볼 수 있습니다.

```bash
# IEx 셸에서 입력
iex> :observer.start()
```
- **Processes 탭**: 모든 프로세스 리스트와 상태 확인.
- **Load Charts 탭**: CPU, 메모리 사용량 실시간 그래프.

---

## 노련한 선배의 한마디 👴

> "진정한 마스터는 `IO.inspect`만으로 모든 문제를 해결하지 않습니다. 시스템이 복잡해지면 **Observer**를 켜서 프로세스 간의 메시지 흐름을 관찰하세요. 버그는 대부분 우리가 예상한 흐름과 실제 흐름이 다를 때 발생합니다. 도구를 활용해 그 차이를 시각화하는 습관을 들이세요."
