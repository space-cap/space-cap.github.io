# 22. 메타프로그래밍 맛보기: 코드를 짜는 코드

Elixir의 많은 마법(예: `if`, `case`, 심지어 프레임워크의 문법들)은 사실 **매크로(Macros)**로 만들어져 있습니다. 메타프로그래밍은 프로그램이 자기 자신의 코드를 생성하거나 조작하는 기술입니다.

---

## 1. 추상 구문 트리 (AST)

Elixir 코드는 컴파일되기 전에 내부적으로 튜플 형태의 데이터 구조(AST)로 변환됩니다.

```elixir
# 코드를 데이터로 변환하기 (quote)
iex> quote do: 1 + 2
{:+, [context: Elixir, import: Kernel], [1, 2]}
```

---

## 2. Quote와 Unquote

- **`quote`**: Elixir 코드를 AST 데이터 구조로 바꿉니다. (코드를 '얼리는' 과정)
- **`unquote`**: `quote` 안에서 외부 변수 값을 주입할 때 사용합니다. (얼어붙은 코드 속에 실시간 값을 '녹여 넣는' 과정)

```elixir
number = 10
quoted = quote do: 1 + unquote(number)
# 결과: 1 + 10에 해당하는 AST
```

---

## 3. 매크로 (Macros) 정의하기

매크로는 호출된 시점에 코드를 **'확장(Expansion)'**하여 다른 코드로 갈아 끼웁니다.

```elixir
defmodule MyMacros do
  defmacro say_hello(name) do
    quote do
      IO.puts("안녕하세요, #{unquote(name)}님!")
    end
  end
end

# 사용 시
require MyMacros
MyMacros.say_hello("호세")
```

---

## 4. 메타프로그래밍의 대원칙 (중요!)

30년 베테랑의 가장 중요한 조언입니다:
**"매크로를 쓰지 않고 해결할 수 있다면, 쓰지 마세요."**

매크로는 코드를 마법처럼 만들어주지만, 남발하면 코드를 읽기 어렵게 만들고 디버깅을 지옥으로 만듭니다. 하지만 라이브러리 제작자나 반복되는 보일러플레이트 코드를 줄여야 할 때는 가장 강력한 무기가 됩니다.
