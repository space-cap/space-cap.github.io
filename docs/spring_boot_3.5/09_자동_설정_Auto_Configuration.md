# 자동 설정 Auto Configuration

## 이번 장에서 배울 것

이 장에서는 Spring Boot의 자동 설정을 배운다.

자동 설정은 Spring Boot를 Spring Boot답게 만드는 핵심 기능이다. Starter가 필요한 라이브러리를 가져온다면, 자동 설정은 그 라이브러리를 사용할 수 있도록 Bean과 설정을 준비한다.

## 자동 설정이 필요한 이유

웹 애플리케이션을 만들려면 많은 설정이 필요하다.

예를 들어 Spring MVC를 직접 설정한다면 다음과 같은 일을 해야 한다.

- DispatcherServlet 등록
- JSON 변환기 등록
- 정적 리소스 처리 설정
- 에러 처리 설정
- 내장 서버 설정
- 메시지 컨버터 설정

Spring Boot는 클래스패스와 설정 값을 보고 "이 프로젝트는 웹 애플리케이션이구나"라고 판단한 뒤 필요한 설정을 자동으로 적용한다.

## 클래스패스가 힌트가 된다

클래스패스는 애플리케이션이 사용할 수 있는 클래스와 라이브러리의 목록이라고 생각하면 된다.

`spring-boot-starter-web`을 추가하면 Spring MVC와 Tomcat 관련 클래스가 클래스패스에 들어온다. Spring Boot는 이것을 보고 웹 애플리케이션에 필요한 자동 설정을 활성화한다.

즉 자동 설정은 마법이 아니라 조건 판단이다.

```text
Spring MVC가 있네?
Tomcat도 있네?
그럼 웹 서버와 MVC 기본 설정을 준비하자.
```

## 조건부 설정

자동 설정은 아무 때나 무조건 적용되지 않는다. 조건이 맞을 때만 적용된다.

대표적인 조건은 다음과 같다.

- 특정 클래스가 있을 때
- 특정 Bean이 없을 때
- 특정 설정 값이 있을 때
- 웹 애플리케이션일 때

예를 들어 개발자가 직접 어떤 Bean을 등록하면, Spring Boot는 기본 Bean을 만들지 않고 개발자의 설정을 우선할 수 있다.

이 철학이 중요하다.

"Spring Boot가 기본값을 제공하되, 개발자가 직접 정하면 개발자의 선택을 존중한다."

## 자동 설정 확인하기

자동 설정이 어떻게 적용됐는지 보고 싶다면 `debug` 설정을 켤 수 있다.

`src/main/resources/application.yml`:

```yaml
debug: true
```

애플리케이션을 실행하면 조건 평가 보고서가 로그에 출력된다.

처음 보면 길고 복잡하지만, 다음 두 가지를 찾으면 된다.

- 적용된 자동 설정
- 적용되지 않은 자동 설정과 그 이유

나중에 Actuator를 배우면 `/actuator/conditions` 엔드포인트로도 확인할 수 있다.

## 자동 설정과 수동 설정의 관계

Spring Boot를 쓰면 설정을 전혀 하지 않아도 되는 것처럼 보인다. 정확히는 "기본 설정으로 충분할 때는 설정하지 않아도 된다"가 맞다.

예를 들어 서버 포트를 바꾸고 싶으면 직접 설정한다.

```yaml
server:
  port: 8081
```

JSON 날짜 형식을 바꾸거나, 데이터베이스 연결 정보를 넣거나, 보안 규칙을 바꾸는 것도 가능하다.

자동 설정은 출발점을 제공한다. 실무 애플리케이션은 그 출발점 위에 필요한 설정을 얹는다.

## 간단한 예: 포트 설정

아무 설정도 없으면 Spring Boot 웹 애플리케이션은 기본적으로 8080 포트를 사용한다.

8081로 바꾸려면 다음처럼 설정한다.

```yaml
server:
  port: 8081
```

다시 실행하면 로그에 다음과 비슷한 내용이 나온다.

```text
Tomcat started on port 8081
```

## 자주 하는 실수

### 자동 설정을 마법이라고 생각한다

자동 설정은 조건 기반 설정이다. 클래스패스, Bean 존재 여부, 설정 값 등을 보고 적용 여부가 결정된다.

### Bean 충돌을 이해하지 못한다

같은 타입이나 같은 이름의 Bean이 여러 개 있으면 충돌이 날 수 있다. 이때는 어떤 Bean이 등록됐는지 확인해야 한다.

### `debug: true`를 운영에 켜 둔다

조건 평가 로그는 길다. 학습이나 디버깅에는 좋지만 운영 환경에서 상시로 켜 둘 필요는 없다.
