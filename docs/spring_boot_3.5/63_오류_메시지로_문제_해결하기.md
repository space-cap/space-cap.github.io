# 오류 메시지로 문제 해결하기

## 이번 장에서 배울 것

이번 장에서는 Spring Boot 애플리케이션에서 오류가 났을 때 메시지를 읽고 원인을 찾는 방법을 배운다.

초보자는 오류가 나면 "빨간 글씨가 너무 많다"고 느낀다. 하지만 대부분의 오류는 몇 가지 단서만 잘 보면 방향을 잡을 수 있다.

## 오류를 읽는 기본 순서

오류가 나면 위에서부터 전부 읽으려고 하지 말고 다음 순서로 본다.

1. 애플리케이션이 시작 중 실패했는가, 요청 처리 중 실패했는가?
2. `APPLICATION FAILED TO START`가 있는가?
3. `Description`과 `Action`이 있는가?
4. 가장 아래쪽 `Caused by`는 무엇인가?
5. 내 코드 패키지명이 보이는가?
6. 설정 파일 이름과 line 정보가 있는가?

Spring Boot는 시작 실패에 대해 `FailureAnalyzer`를 제공한다. 그래서 일부 오류는 설명과 조치까지 친절하게 보여준다.

## 포트 충돌

대표 메시지:

```text
APPLICATION FAILED TO START

Description:
Embedded servlet container failed to start. Port 8080 was already in use.

Action:
Identify and stop the process that is listening on port 8080 or configure this application to listen on another port.
```

뜻:

```text
이미 다른 프로그램이 8080 포트를 사용하고 있다.
```

해결:

```yaml
server:
  port: 8081
```

또는 실행 인자:

```bash
java -jar app.jar --server.port=8081
```

Windows에서 포트 찾기:

```powershell
netstat -ano | findstr :8080
```

## Bean 중복

대표 메시지:

```text
No qualifying bean of type ...
expected single matching bean but found 2
```

뜻:

```text
같은 타입의 Bean이 여러 개라 Spring이 무엇을 주입해야 할지 모른다.
```

해결 방법:

- `@Qualifier` 사용
- `@Primary` 지정
- 불필요한 Bean 제거
- 타입을 더 구체적으로 나누기

예:

```java
public NotificationService(@Qualifier("emailSender") MessageSender sender) {
    this.sender = sender;
}
```

## Bean을 찾을 수 없음

대표 메시지:

```text
Parameter 0 of constructor in ... required a bean of type ... that could not be found.
```

뜻:

```text
생성자에 필요한 Bean이 Spring 컨테이너에 없다.
```

확인할 것:

- 클래스에 `@Component`, `@Service`, `@Repository`가 붙어 있는가?
- 패키지가 `@SpringBootApplication` 하위에 있는가?
- `@Bean` 등록을 빠뜨리지 않았는가?
- test slice에서 필요한 Bean을 제외한 것은 아닌가?

## 순환 참조

대표 메시지:

```text
The dependencies of some of the beans in the application context form a cycle
```

뜻:

```text
A가 B를 필요로 하고, B가 다시 A를 필요로 한다.
```

예:

```text
OrderService -> PaymentService -> OrderService
```

해결:

- 책임을 분리한다.
- 공통 로직을 별도 서비스로 뺀다.
- 이벤트 기반으로 끊는다.
- 정말 필요한 경우 설계를 다시 본다.

순환 참조는 설정으로 억지로 허용하기보다 구조 문제로 보는 편이 좋다.

## DB 연결 실패

대표 메시지:

```text
Connection refused
```

또는:

```text
FATAL: password authentication failed
```

확인할 것:

- DB가 실행 중인가?
- host와 port가 맞는가?
- database 이름이 맞는가?
- username/password가 맞는가?
- Docker Compose 네트워크에서 host 이름이 맞는가?

로컬 PostgreSQL 예:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/todo
    username: todo
    password: todo
```

Docker Compose 안에서 app이 db 컨테이너를 볼 때:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://db:5432/todo
```

## JPA Entity 오류

대표 메시지:

```text
Not a managed type
```

뜻:

```text
Repository가 다루려는 클래스가 JPA Entity로 등록되지 않았다.
```

확인할 것:

- `@Entity`가 붙어 있는가?
- `jakarta.persistence.Entity`를 import했는가?
- Entity 패키지가 scan 범위 안에 있는가?
- `@Id`가 있는가?

## Validation 오류가 안 잡힘

증상:

```text
@NotBlank를 붙였는데 빈 값이 통과한다.
```

확인할 것:

- `spring-boot-starter-validation` 의존성이 있는가?
- 컨트롤러 파라미터에 `@Valid`가 붙어 있는가?
- `jakarta.validation.*`를 import했는가?

예:

```java
@PostMapping("/todos")
public TodoResponse create(@Valid @RequestBody CreateTodoRequest request) {
    ...
}
```

## 404 오류

확인할 것:

- URL 경로가 맞는가?
- HTTP 메서드가 맞는가?
- `context-path`가 설정되어 있는가?
- trailing slash가 붙어 있는가?
- 컨트롤러가 scan되고 있는가?

Spring Framework 6부터 trailing slash 매칭 기본 동작이 달라졌다. `/todos`와 `/todos/`를 같은 경로로 기대하면 문제가 생길 수 있다.

## 401과 403

401:

```text
인증되지 않았다.
```

403:

```text
인증은 되었지만 권한이 없다.
```

확인할 것:

- Authorization 헤더가 있는가?
- 토큰이 만료되지 않았는가?
- SecurityFilterChain 설정이 맞는가?
- CSRF가 필요한 요청인가?
- Role 이름에 `ROLE_` prefix가 어떻게 처리되는가?

## 조건 평가 보고서 보기

자동 설정이 왜 적용되었는지 보고 싶다면 debug를 켠다.

```bash
java -jar app.jar --debug
```

또는:

```yaml
debug: true
```

Spring Boot는 어떤 자동 설정이 적용되었고 어떤 조건 때문에 제외되었는지 보여준다. 자동 설정 문제를 찾을 때 유용하다.

## 로그를 질문으로 바꾸기

오류를 볼 때 다음 질문을 던진다.

```text
무엇을 만들려다 실패했나?
어떤 Bean이 필요한가?
어떤 설정값을 읽으려 했나?
내 코드가 stack trace에 어디서 등장하나?
가장 안쪽 Caused by는 무엇인가?
```

이렇게 질문으로 바꾸면 오류 메시지가 덜 무섭다.

## 자주 하는 실수

### stack trace의 맨 위만 본다

맨 아래 `Caused by`가 진짜 원인인 경우가 많다.

### 에러 메시지를 검색하기 전에 읽지 않는다

Spring Boot는 `Description`과 `Action`을 제공하는 경우가 있다. 먼저 읽자.

### 설정 파일을 고쳤는데 profile을 착각한다

`application-local.yml`을 고쳤지만 실제로는 `prod` profile로 실행 중일 수 있다.

### 임시 해결책을 영구 설정으로 남긴다

예를 들어 순환 참조 허용 같은 설정은 설계 문제를 숨길 수 있다.

## 확인 문제

1. `APPLICATION FAILED TO START` 아래에서 먼저 봐야 할 두 항목은 무엇인가?
2. 포트 충돌이 났을 때 바꿀 수 있는 설정은 무엇인가?
3. Bean이 두 개라 주입할 수 없을 때 사용할 수 있는 애너테이션은 무엇인가?
4. 자동 설정 조건 평가 보고서를 보려면 어떻게 실행할 수 있는가?
