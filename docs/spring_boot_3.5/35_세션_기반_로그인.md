# 세션 기반 로그인

## 이번 장에서 배울 것

이 장에서는 세션 기반 로그인을 배운다.

세션 기반 로그인은 전통적인 웹 애플리케이션에서 많이 쓰는 방식이다. 사용자가 아이디와 비밀번호로 로그인하면 서버는 로그인 상태를 세션에 저장하고, 브라우저는 세션 쿠키를 들고 다닌다.

## 세션 기반 로그인 흐름

흐름은 다음과 같다.

```text
1. 사용자가 로그인 폼에 아이디와 비밀번호 입력
2. 서버가 사용자 인증
3. 인증 성공 시 서버 세션에 로그인 정보 저장
4. 브라우저에 세션 쿠키 전달
5. 이후 요청마다 브라우저가 세션 쿠키 전송
6. 서버가 세션을 보고 로그인 사용자 확인
```

브라우저 기반 웹 서비스에서는 이 방식이 자연스럽다.

## 기본 Form Login

Security 설정:

```java
package com.example.todo.security;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http)
            throws Exception {
        http
                .authorizeHttpRequests(auth -> auth
                        .requestMatchers("/", "/login").permitAll()
                        .requestMatchers("/admin/**").hasRole("ADMIN")
                        .anyRequest().authenticated()
                )
                .formLogin(Customizer.withDefaults());

        return http.build();
    }
}
```

이 설정만으로 Spring Security의 기본 로그인 페이지를 사용할 수 있다.

로그인 경로:

```text
GET /login
```

기본 로그인 처리 경로:

```text
POST /login
```

기본 파라미터:

```text
username
password
```

## 커스텀 로그인 페이지

직접 로그인 페이지를 만들려면 설정을 바꾼다.

```java
http.formLogin(form -> form
        .loginPage("/login")
        .loginProcessingUrl("/login")
        .defaultSuccessUrl("/", true)
        .failureUrl("/login?error")
        .permitAll()
);
```

각 의미:

- `loginPage`: 로그인 화면 경로
- `loginProcessingUrl`: 로그인 요청을 처리할 경로
- `defaultSuccessUrl`: 로그인 성공 후 이동할 경로
- `failureUrl`: 로그인 실패 후 이동할 경로
- `permitAll`: 로그인 관련 경로는 누구나 접근 가능

## 세션 확인 API

학습용으로 현재 로그인 사용자를 확인하는 API를 만들 수 있다.

```java
package com.example.todo.user;

import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class MeController {

    @GetMapping("/me")
    public MeResponse me(
            @AuthenticationPrincipal UserDetails userDetails
    ) {
        return new MeResponse(
                userDetails.getUsername(),
                userDetails.getAuthorities()
                        .stream()
                        .map(Object::toString)
                        .toList()
        );
    }
}
```

DTO:

```java
package com.example.todo.user;

import java.util.List;

public record MeResponse(
        String username,
        List<String> authorities
) {
}
```

로그인 후 `/me`를 호출하면 현재 사용자 정보를 볼 수 있다.

## CSRF란 무엇인가

CSRF는 Cross-Site Request Forgery의 줄임말이다. 사용자가 로그인한 상태를 악용해 원치 않는 요청을 보내게 만드는 공격이다.

세션 기반 인증에서는 브라우저가 쿠키를 자동으로 보내기 때문에 CSRF 방어가 중요하다.

Spring Security는 기본적으로 CSRF 보호를 활성화한다.

그래서 Form Login 기반 웹에서는 CSRF 토큰을 폼에 포함해야 한다.

## REST API에서 CSRF

순수 REST API 서버에서 세션을 사용하지 않고 Authorization 헤더의 Bearer 토큰만 사용한다면 CSRF 위험이 상대적으로 낮다. 이런 경우 CSRF를 비활성화하는 설정을 자주 사용한다.

하지만 세션 쿠키 기반 인증을 쓰는 REST API라면 CSRF를 함부로 끄면 안 된다.

초보자가 기억할 기준:

```text
브라우저 쿠키 기반 인증: CSRF 고려 필요
Authorization 헤더 기반 토큰 인증: 보통 CSRF 비활성화 검토
```

## 로그아웃

기본 로그아웃 경로:

```text
POST /logout
```

설정:

```java
http.logout(logout -> logout
        .logoutUrl("/logout")
        .logoutSuccessUrl("/")
        .invalidateHttpSession(true)
        .deleteCookies("JSESSIONID")
);
```

세션을 무효화하고 세션 쿠키를 삭제한다.

## 세션 관리

동시 로그인 제어 같은 설정도 가능하다.

```java
http.sessionManagement(session -> session
        .maximumSessions(1)
        .maxSessionsPreventsLogin(false)
);
```

의미:

- 한 사용자당 최대 세션 1개
- 새 로그인을 허용하고 기존 세션을 만료

처음부터 깊게 다룰 필요는 없지만, 관리자 시스템이나 사내 서비스에서는 자주 필요하다.

## API 서버와 세션 로그인

모바일 앱이나 SPA 백엔드에서는 JWT 같은 토큰 인증을 선택하는 경우가 많다.

하지만 서버 렌더링 웹, 관리자 페이지, 사내 시스템에서는 세션 로그인이 여전히 좋은 선택일 수 있다.

기술 선택 기준:

- 브라우저 중심 화면: 세션 로그인 적합
- 서버 렌더링 MVC: 세션 로그인 적합
- 모바일 앱 API: 토큰 인증 고려
- 여러 서비스 간 인증 공유: OAuth2/OIDC 고려

## 자주 하는 실수

### 세션 로그인에서 CSRF를 무조건 끈다

브라우저 쿠키 기반 인증에서는 CSRF가 중요하다. 끄기 전에 인증 방식과 위험을 이해해야 한다.

### 로그인 처리 Controller를 직접 만들려고 한다

Spring Security의 Form Login은 기본적으로 `POST /login`을 필터에서 처리한다. 직접 Controller를 만들 필요가 없는 경우가 많다.

### GET으로 로그아웃을 처리한다

상태를 바꾸는 요청은 GET으로 처리하지 않는다. 기본적으로 Spring Security는 POST 로그아웃을 사용한다.
