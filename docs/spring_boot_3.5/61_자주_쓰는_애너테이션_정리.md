# 자주 쓰는 애너테이션 정리

## 이번 장에서 배울 것

이번 장에서는 Spring Boot 프로젝트에서 자주 사용하는 애너테이션을 역할별로 정리한다.

애너테이션은 외우려고 하면 끝이 없다. 대신 "어느 계층에서, 어떤 의도로 쓰는가"를 기준으로 묶어서 이해하면 훨씬 쉽다.

## 시작 애너테이션

### `@SpringBootApplication`

Spring Boot 애플리케이션의 시작점에 붙인다.

```java
@SpringBootApplication
public class TodoApplication {

    public static void main(String[] args) {
        SpringApplication.run(TodoApplication.class, args);
    }
}
```

내부적으로 다음 역할을 함께 한다.

- 자동 설정 활성화
- 컴포넌트 스캔
- 설정 클래스 역할

보통 루트 패키지에 둔다.

## 컴포넌트 계층

### `@Component`

Spring이 관리하는 Bean으로 등록한다.

```java
@Component
public class PasswordEncoderAdapter {
}
```

특별한 계층 의미가 없을 때 사용한다.

### `@Controller`

웹 MVC 컨트롤러에 사용한다.

```java
@Controller
public class PageController {
}
```

보통 HTML view를 반환하는 컨트롤러에서 사용한다.

### `@RestController`

REST API 컨트롤러에 사용한다.

```java
@RestController
public class TodoController {
}
```

`@Controller`와 `@ResponseBody`를 합친 형태다. 메서드 반환값이 JSON 응답으로 변환된다.

### `@Service`

비즈니스 로직을 담는 서비스 계층에 사용한다.

```java
@Service
public class TodoService {
}
```

### `@Repository`

데이터 접근 계층에 사용한다.

```java
@Repository
public class TodoJdbcRepository {
}
```

Spring Framework 문서 기준으로 `@Repository`, `@Service`, `@Controller`는 `@Component`의 특수화다. `@Repository`는 데이터 접근 예외 변환과도 관련이 있다.

## 의존성 주입

### `@Autowired`

Bean을 주입할 때 사용한다.

```java
@Autowired
public TodoService(TodoRepository todoRepository) {
    this.todoRepository = todoRepository;
}
```

하지만 생성자가 하나뿐이면 생략할 수 있다.

권장:

```java
@Service
public class TodoService {

    private final TodoRepository todoRepository;

    public TodoService(TodoRepository todoRepository) {
        this.todoRepository = todoRepository;
    }
}
```

### `@Qualifier`

같은 타입의 Bean이 여러 개일 때 특정 Bean을 고른다.

```java
public NotificationService(@Qualifier("emailSender") MessageSender sender) {
    this.sender = sender;
}
```

### `@Primary`

같은 타입의 Bean 중 기본 선택 대상을 지정한다.

```java
@Primary
@Bean
MessageSender emailSender() {
    return new EmailSender();
}
```

## 설정

### `@Configuration`

설정 클래스를 나타낸다.

```java
@Configuration
public class AppConfig {
}
```

### `@Bean`

메서드 반환 객체를 Spring Bean으로 등록한다.

```java
@Bean
Clock clock() {
    return Clock.systemDefaultZone();
}
```

직접 만든 클래스에는 `@Component`를 쓰고, 외부 라이브러리 객체를 등록할 때는 `@Bean`을 많이 쓴다.

### `@ConfigurationProperties`

설정 값을 타입 안전하게 바인딩한다.

```java
@ConfigurationProperties(prefix = "app.mail")
public record MailProperties(
        String sender,
        int retryCount
) {
}
```

### `@Value`

간단한 설정 값을 주입한다.

```java
@Value("${app.name}")
private String appName;
```

설정 값이 많아지면 `@ConfigurationProperties`가 더 좋다.

## 웹 요청 처리

### `@RequestMapping`

공통 경로 또는 HTTP 요청 매핑을 정의한다.

```java
@RequestMapping("/api/todos")
@RestController
public class TodoController {
}
```

### `@GetMapping`, `@PostMapping`, `@PutMapping`, `@PatchMapping`, `@DeleteMapping`

HTTP 메서드별 요청을 처리한다.

```java
@GetMapping("/{id}")
public TodoResponse findById(@PathVariable Long id) {
    ...
}
```

### `@PathVariable`

URL 경로 값을 받는다.

```java
@GetMapping("/todos/{id}")
public TodoResponse find(@PathVariable Long id) {
    ...
}
```

### `@RequestParam`

쿼리 파라미터를 받는다.

```java
@GetMapping("/todos")
public List<TodoResponse> search(@RequestParam String keyword) {
    ...
}
```

### `@RequestBody`

요청 JSON 본문을 객체로 받는다.

```java
@PostMapping("/todos")
public TodoResponse create(@RequestBody CreateTodoRequest request) {
    ...
}
```

### `@ResponseStatus`

응답 상태 코드를 지정한다.

```java
@ResponseStatus(HttpStatus.CREATED)
@PostMapping("/todos")
public TodoResponse create(@RequestBody CreateTodoRequest request) {
    ...
}
```

## 검증과 예외

### `@Valid`

요청 DTO 검증을 실행한다.

```java
public TodoResponse create(@Valid @RequestBody CreateTodoRequest request) {
    ...
}
```

### `@NotBlank`, `@NotNull`, `@Size`

Bean Validation 제약 조건이다.

```java
public record CreateTodoRequest(
        @NotBlank String title,
        @Size(max = 1000) String description
) {
}
```

### `@ControllerAdvice`

여러 컨트롤러에 공통으로 적용되는 예외 처리 클래스를 만든다.

```java
@ControllerAdvice
public class GlobalExceptionHandler {
}
```

### `@ExceptionHandler`

특정 예외를 처리한다.

```java
@ExceptionHandler(TodoNotFoundException.class)
public ResponseEntity<ErrorResponse> handle(TodoNotFoundException e) {
    ...
}
```

## 데이터와 트랜잭션

### `@Entity`

JPA Entity를 나타낸다.

```java
@Entity
public class Todo {
}
```

Spring Boot 3.x에서는 `jakarta.persistence.Entity`를 사용한다.

### `@Id`

Entity의 식별자를 나타낸다.

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

### `@Transactional`

트랜잭션 경계를 만든다.

```java
@Transactional
public void update(Long id, String title) {
    ...
}
```

조회 전용:

```java
@Transactional(readOnly = true)
public TodoResponse findById(Long id) {
    ...
}
```

## 테스트

### `@SpringBootTest`

전체 Spring Boot 컨텍스트를 띄우는 통합 테스트에 사용한다.

```java
@SpringBootTest
class TodoServiceTest {
}
```

### `@WebMvcTest`

MVC 컨트롤러 계층만 테스트한다.

```java
@WebMvcTest(TodoController.class)
class TodoControllerTest {
}
```

### `@DataJpaTest`

JPA Repository 테스트에 사용한다.

```java
@DataJpaTest
class TodoRepositoryTest {
}
```

### `@MockBean`

테스트 컨텍스트 안의 Bean을 mock으로 바꾼다.

```java
@MockBean
TodoService todoService;
```

## 운영과 보안

### `@PreAuthorize`

메서드 실행 전 권한을 검사한다.

```java
@PreAuthorize("hasRole('ADMIN')")
public void delete(Long id) {
    ...
}
```

### `@Scheduled`

정해진 시간마다 작업을 실행한다.

```java
@Scheduled(cron = "0 0 3 * * *")
public void cleanup() {
}
```

### `@Async`

별도 스레드에서 비동기 실행한다.

```java
@Async
public void sendMail(String email) {
}
```

## 자주 하는 실수

### `@Component`, `@Service`, `@Repository`를 아무렇게나 쓴다

동작은 비슷해도 의미가 다르다. 계층에 맞게 사용하자.

### 필드 주입을 습관처럼 사용한다

생성자 주입이 테스트와 불변성에 유리하다.

### `@Transactional`을 컨트롤러에 붙인다

트랜잭션은 보통 서비스 계층에 둔다.

### `@SpringBootTest`만 모든 테스트에 사용한다

느리고 무겁다. 상황에 따라 slice test를 사용하자.
