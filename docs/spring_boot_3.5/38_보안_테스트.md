# 보안 테스트

## 이번 장에서 배울 것

이 장에서는 Spring Security가 적용된 애플리케이션을 테스트하는 방법을 배운다.

보안은 테스트가 특히 중요하다. 기능이 잘 동작하는 것만으로는 충분하지 않다. 접근하면 안 되는 사용자가 정말 막히는지 확인해야 한다.

## 의존성

Spring Security 테스트를 위해 다음 의존성을 추가한다.

```groovy
dependencies {
    testImplementation 'org.springframework.security:spring-security-test'
}
```

`spring-boot-starter-test`와 함께 사용한다.

## 무엇을 테스트할까?

보안 테스트에서 확인할 것:

- 인증하지 않은 사용자가 보호 API에 접근하면 거부되는가
- 로그인 사용자는 허용되는가
- 권한이 없는 사용자는 `403 Forbidden`을 받는가
- 관리자 권한은 관리자 API에 접근할 수 있는가
- CSRF가 필요한 요청에서 토큰 없이는 실패하는가
- 메서드 보안이 동작하는가

## `@WebMvcTest`와 `@WithMockUser`

Controller 보안 테스트는 `@WebMvcTest`와 `@WithMockUser`를 함께 사용할 수 있다.

```java
package com.example.todo.todo;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.security.test.context.support.WithMockUser;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.MockMvc;

import java.util.List;

import static org.mockito.BDDMockito.given;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(TodoController.class)
class TodoControllerSecurityTest {

    @Autowired
    MockMvc mockMvc;

    @MockitoBean
    TodoService todoService;

    @Test
    void rejectAnonymousUser() throws Exception {
        mockMvc.perform(get("/todos"))
                .andExpect(status().isUnauthorized());
    }

    @Test
    @WithMockUser(username = "user", roles = "USER")
    void allowAuthenticatedUser() throws Exception {
        given(todoService.findAll()).willReturn(List.of());

        mockMvc.perform(get("/todos"))
                .andExpect(status().isOk());
    }
}
```

`@WithMockUser`는 테스트용 인증 사용자를 SecurityContext에 넣어준다.

## role 테스트

관리자 API 예:

```java
@RestController
@RequestMapping("/admin")
public class AdminController {

    @GetMapping("/dashboard")
    public String dashboard() {
        return "admin";
    }
}
```

테스트:

```java
@WebMvcTest(AdminController.class)
class AdminControllerSecurityTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    @WithMockUser(roles = "USER")
    void rejectUserRole() throws Exception {
        mockMvc.perform(get("/admin/dashboard"))
                .andExpect(status().isForbidden());
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void allowAdminRole() throws Exception {
        mockMvc.perform(get("/admin/dashboard"))
                .andExpect(status().isOk());
    }
}
```

인증되지 않으면 보통 `401 Unauthorized`, 인증은 되었지만 권한이 없으면 `403 Forbidden`이다.

## CSRF 테스트

CSRF가 활성화된 상태에서 POST 요청을 보내면 CSRF 토큰이 필요하다.

```java
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.csrf;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;

@Test
@WithMockUser
void rejectPostWithoutCsrf() throws Exception {
    mockMvc.perform(post("/todos")
                    .contentType("application/json")
                    .content("{\"title\":\"테스트\"}"))
            .andExpect(status().isForbidden());
}

@Test
@WithMockUser
void allowPostWithCsrf() throws Exception {
    mockMvc.perform(post("/todos")
                    .with(csrf())
                    .contentType("application/json")
                    .content("{\"title\":\"테스트\"}"))
            .andExpect(status().isCreated());
}
```

세션 기반 웹에서는 CSRF 테스트가 중요하다.

JWT 기반 stateless API에서 CSRF를 비활성화했다면 이 테스트는 다르게 작성한다.

## HTTP Basic 테스트

HTTP Basic 인증을 테스트할 수 있다.

```java
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.httpBasic;

@Test
void allowWithHttpBasic() throws Exception {
    mockMvc.perform(get("/todos")
                    .with(httpBasic("user", "password")))
            .andExpect(status().isOk());
}
```

실제 `UserDetailsService`와 `PasswordEncoder`가 테스트 Context에 있어야 한다.

## JWT 테스트

Resource Server 기반 JWT 테스트에서는 `jwt()` request post processor를 사용할 수 있다.

```java
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.jwt;

@Test
void allowWithJwtScope() throws Exception {
    mockMvc.perform(get("/api/todos")
                    .with(jwt().authorities(() -> "SCOPE_todo:read")))
            .andExpect(status().isOk());
}
```

권한이 없을 때:

```java
@Test
void rejectWithoutScope() throws Exception {
    mockMvc.perform(get("/api/todos")
                    .with(jwt()))
            .andExpect(status().isForbidden());
}
```

이 방식은 실제 JWT 문자열을 만들지 않고도 SecurityContext에 JWT 인증을 넣어 테스트할 수 있다.

## 메서드 보안 테스트

Service 메서드에 `@PreAuthorize`가 있다면 메서드 보안도 테스트해야 한다.

```java
package com.example.todo.admin;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.security.access.AccessDeniedException;
import org.springframework.security.test.context.support.WithMockUser;

import static org.assertj.core.api.Assertions.assertThatThrownBy;

@SpringBootTest
class AdminServiceSecurityTest {

    @Autowired
    AdminService adminService;

    @Test
    @WithMockUser(roles = "USER")
    void rejectUser() {
        assertThatThrownBy(() -> adminService.deleteUser(1L))
                .isInstanceOf(AccessDeniedException.class);
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void allowAdmin() {
        adminService.deleteUser(1L);
    }
}
```

메서드 보안 테스트가 동작하려면 애플리케이션에 `@EnableMethodSecurity`가 설정되어 있어야 한다.

## 테스트에서 보안 설정 포함하기

`@WebMvcTest`는 제한된 Bean만 로드한다. 보안 설정이 자동으로 충분히 들어오지 않거나 커스텀 `SecurityConfig`가 필요하면 `@Import`를 사용할 수 있다.

```java
@WebMvcTest(TodoController.class)
@Import(SecurityConfig.class)
class TodoControllerSecurityTest {
}
```

테스트가 무엇을 검증하는지에 따라 실제 보안 설정을 넣을지, 단순 테스트용 설정을 넣을지 결정한다.

## 자주 하는 실수

### 인증 성공만 테스트한다

보안 테스트에서는 거부되어야 하는 요청을 반드시 테스트한다.

### 401과 403을 혼동한다

인증되지 않으면 401, 인증은 되었지만 권한이 없으면 403이다.

### CSRF 토큰을 빠뜨린다

CSRF가 활성화된 POST, PUT, PATCH, DELETE 요청은 테스트에서도 CSRF 토큰이 필요하다.

### `@WithMockUser(roles = "ROLE_ADMIN")`처럼 쓴다

`roles = "ADMIN"`으로 쓴다. `ROLE_` 접두사는 내부적으로 붙는다.
