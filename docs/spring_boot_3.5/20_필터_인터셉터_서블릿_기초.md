# 필터, 인터셉터, 서블릿 기초

## 이번 장에서 배울 것

이 장에서는 Spring MVC 요청 흐름의 큰 그림을 배운다.

지금까지는 요청이 곧바로 Controller에 도착한다고 생각했다. 실제로는 요청이 Controller에 도착하기 전에도 여러 단계를 지난다. 그 흐름을 이해하면 인증, 로깅, CORS, 인코딩, 공통 검사 같은 기능이 어디에 들어가야 하는지 판단할 수 있다.

## 전체 흐름

Spring MVC의 요청 흐름을 단순화하면 다음과 같다.

```text
Client
  -> Servlet Filter
  -> DispatcherServlet
  -> HandlerInterceptor
  -> Controller
  -> Service
  -> Repository
```

응답은 반대 방향으로 돌아간다.

```text
Repository
  -> Service
  -> Controller
  -> HandlerInterceptor
  -> DispatcherServlet
  -> Servlet Filter
  -> Client
```

## Servlet이란 무엇인가

Servlet은 Java 웹 애플리케이션에서 HTTP 요청과 응답을 처리하는 표준 기술이다.

Spring MVC도 Servlet 기반 위에서 동작한다. Spring MVC의 핵심 입구는 `DispatcherServlet`이다.

Spring Boot에서 `spring-boot-starter-web`을 사용하면 내장 Tomcat이 실행되고, Spring Boot가 `DispatcherServlet`을 자동으로 등록한다. 그래서 개발자가 직접 `web.xml`을 작성하지 않아도 된다.

## DispatcherServlet

`DispatcherServlet`은 Spring MVC의 중앙 입구다.

역할은 다음과 같다.

- 요청을 받는다.
- 어떤 Controller가 처리할지 찾는다.
- Controller 메서드를 호출한다.
- 반환값을 HTTP 응답으로 변환한다.
- 예외 처리 흐름을 연결한다.

초보자는 `DispatcherServlet`을 "Spring MVC의 프런트 컨트롤러"라고 이해하면 된다. 모든 요청을 중앙에서 받아 적절한 Controller로 보내는 역할이다.

## Filter

Filter는 Servlet 표준 기능이다. Spring MVC 바깥, 더 정확히는 `DispatcherServlet` 앞뒤에서 동작한다.

주로 다음에 사용한다.

- 요청/응답 로깅
- 인코딩 처리
- CORS 처리
- 인증 토큰 추출
- 보안 필터 체인

Filter는 Spring MVC Controller를 몰라도 동작할 수 있다. 그래서 더 낮은 레벨의 공통 처리에 적합하다.

## 간단한 Filter 예제

Spring Boot 3.x에서는 Servlet 관련 패키지가 `jakarta.servlet`이다.

```java
package com.example.todo.common;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;

@Component
public class RequestLoggingFilter extends OncePerRequestFilter {

    private static final Logger log =
            LoggerFactory.getLogger(RequestLoggingFilter.class);

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain
    ) throws ServletException, IOException {
        log.info("request {} {}", request.getMethod(), request.getRequestURI());

        filterChain.doFilter(request, response);

        log.info("response status={}", response.getStatus());
    }
}
```

`filterChain.doFilter(request, response)`를 호출해야 다음 단계로 요청이 넘어간다. 이 줄을 빼먹으면 Controller까지 도달하지 않는다.

## Interceptor

Interceptor는 Spring MVC가 제공하는 기능이다. `DispatcherServlet`이 요청을 받은 뒤, Controller 호출 전후에 동작한다.

주로 다음에 사용한다.

- 로그인 여부 확인
- 권한 검사
- Controller 실행 시간 측정
- 공통 모델 또는 요청 속성 추가

Filter보다 Spring MVC와 더 가깝다. 어떤 Controller가 선택됐는지와 관련된 처리를 하기에 좋다.

## 간단한 Interceptor 예제

```java
package com.example.todo.common;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.servlet.HandlerInterceptor;

public class ApiTimingInterceptor implements HandlerInterceptor {

    private static final Logger log =
            LoggerFactory.getLogger(ApiTimingInterceptor.class);

    @Override
    public boolean preHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler
    ) {
        request.setAttribute("startTime", System.currentTimeMillis());
        return true;
    }

    @Override
    public void afterCompletion(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            Exception ex
    ) {
        Long startTime = (Long) request.getAttribute("startTime");
        if (startTime == null) {
            return;
        }

        long elapsed = System.currentTimeMillis() - startTime;
        log.info("{} {} elapsed={}ms",
                request.getMethod(),
                request.getRequestURI(),
                elapsed);
    }
}
```

Interceptor를 등록하려면 설정 클래스가 필요하다.

```java
package com.example.todo.common;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new ApiTimingInterceptor())
                .addPathPatterns("/**");
    }
}
```

## Filter와 Interceptor 차이

| 구분 | Filter | Interceptor |
| --- | --- | --- |
| 소속 | Servlet 표준 | Spring MVC |
| 위치 | DispatcherServlet 앞뒤 | Controller 호출 전후 |
| 사용 예 | 인코딩, CORS, 보안 필터 | 로그인 체크, 권한, 실행 시간 |
| 객체 | `HttpServletRequest`, `HttpServletResponse` | handler 정보 접근 가능 |

둘 중 무엇을 쓸지는 "Spring MVC 안쪽의 처리인가, 바깥쪽의 처리인가"로 판단하면 쉽다.

## 언제 무엇을 쓸까?

### Filter가 어울리는 경우

- 모든 요청에 대한 아주 앞단 로깅
- 보안 토큰 추출
- Spring Security 필터 체인
- CORS 같은 웹 공통 처리

### Interceptor가 어울리는 경우

- Controller 실행 전 로그인 확인
- 특정 URL 패턴에 대한 권한 검사
- Controller 처리 시간 측정
- handler 정보를 활용한 처리

### ControllerAdvice가 어울리는 경우

- Controller에서 발생한 예외를 공통 응답으로 변환
- 특정 Controller 전체에 공통 데이터 바인딩

## Spring Security와 Filter

나중에 Spring Security를 배우면 Filter가 다시 등장한다.

Spring Security는 여러 Filter로 이루어진 필터 체인을 사용한다. 인증 토큰을 읽고, 로그인 상태를 확인하고, 권한을 검사하는 많은 일이 Controller에 도착하기 전에 일어난다.

그래서 Filter 흐름을 이해해 두면 보안 파트를 배울 때 훨씬 편하다.

## 자주 하는 실수

### Filter에서 `doFilter`를 호출하지 않는다

`filterChain.doFilter(request, response)`를 호출하지 않으면 요청이 다음 단계로 넘어가지 않는다.

### Interceptor를 만들고 등록하지 않는다

`HandlerInterceptor` 구현체를 만들기만 하면 동작하지 않는다. `WebMvcConfigurer`에서 등록해야 한다.

### Spring Boot 3.x에서 `javax.servlet`을 import한다

Spring Boot 3.x에서는 `jakarta.servlet`을 사용한다.
