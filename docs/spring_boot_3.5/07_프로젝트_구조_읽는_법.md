# 프로젝트 구조 읽는 법

## 이번 장에서 배울 것

이 장에서는 Spring Boot 프로젝트의 기본 구조를 읽는다. 초보자는 코드를 작성하기 전에 "파일을 어디에 둬야 하는지"부터 막히는 경우가 많다.

Spring Boot 프로젝트의 구조는 단순해 보이지만, 각 위치에는 분명한 역할이 있다.

## 기본 구조

Gradle 프로젝트를 만들면 보통 다음과 같은 구조가 생긴다.

```text
todo/
  build.gradle
  settings.gradle
  gradlew
  gradlew.bat
  gradle/
    wrapper/
  src/
    main/
      java/
        com/
          example/
            todo/
              TodoApplication.java
      resources/
        application.properties
    test/
      java/
        com/
          example/
            todo/
              TodoApplicationTests.java
```

## 루트 파일

### `build.gradle`

프로젝트의 빌드 설정 파일이다.

여기에는 다음 내용이 들어간다.

- 사용할 플러그인
- Java 버전
- 의존성 목록
- 테스트 설정
- Spring Boot 플러그인 설정

초보자는 처음부터 모든 줄을 이해하려 하지 않아도 된다. 우선 `dependencies` 블록을 읽을 수 있으면 된다.

### `settings.gradle`

프로젝트 이름과 멀티 모듈 설정을 담는다.

처음에는 대개 다음처럼 간단하다.

```groovy
rootProject.name = 'todo'
```

### `gradlew`, `gradlew.bat`

Gradle Wrapper 실행 파일이다.

Windows에서는 `gradlew.bat`, macOS와 Linux에서는 `gradlew`를 사용한다.

## `src/main/java`

애플리케이션의 Java 코드가 들어간다.

예:

```text
src/main/java/com/example/todo/TodoApplication.java
src/main/java/com/example/todo/HelloController.java
```

패키지 구조와 폴더 구조는 일치해야 한다.

```java
package com.example.todo;
```

위 패키지 선언을 가진 파일은 보통 다음 위치에 둔다.

```text
src/main/java/com/example/todo/
```

## 메인 클래스 위치가 중요한 이유

Spring Boot의 메인 클래스에는 `@SpringBootApplication`이 붙어 있다.

```java
@SpringBootApplication
public class TodoApplication {
}
```

이 애너테이션은 현재 패키지와 그 하위 패키지를 스캔한다.

따라서 다음 구조가 좋다.

```text
com.example.todo
  TodoApplication
  controller
    HelloController
  service
    TodoService
  repository
    TodoRepository
```

반대로 다음처럼 Controller가 메인 클래스의 바깥 패키지에 있으면 스캔되지 않을 수 있다.

```text
com.example.todo
  TodoApplication

com.example.web
  HelloController
```

## `src/main/resources`

Java 코드가 아닌 리소스 파일이 들어간다.

대표적인 파일은 다음과 같다.

- `application.properties`
- `application.yml`
- 정적 파일
- 템플릿 파일
- SQL 초기화 파일

처음에는 설정 파일 하나만 기억하면 된다.

## `application.properties`와 `application.yml`

Spring Boot 설정을 적는 파일이다.

`application.properties` 예:

```properties
server.port=8081
spring.application.name=todo
```

`application.yml` 예:

```yaml
server:
  port: 8081

spring:
  application:
    name: todo
```

둘 중 하나를 선택해서 쓰면 된다. 이 문서 모음에서는 구조가 보기 쉬운 `application.yml`을 주로 사용한다.

## `src/test/java`

테스트 코드가 들어간다.

예:

```text
src/test/java/com/example/todo/TodoApplicationTests.java
```

테스트 코드는 운영 코드와 같은 패키지 구조를 맞추는 것이 일반적이다.

## 추천 패키지 구조

처음에는 다음 구조를 추천한다.

```text
com.example.todo
  TodoApplication.java
  todo
    TodoController.java
    TodoService.java
    TodoRepository.java
    Todo.java
```

기능이 커지면 다음처럼 계층별로 나눌 수도 있다.

```text
com.example.todo
  controller
  service
  repository
  domain
  dto
  config
  exception
```

초보자에게는 기능별 구조가 이해하기 쉬운 경우가 많다. 예를 들어 `todo` 기능과 관련된 파일을 한 폴더에 모아두면 작은 프로젝트에서 이동이 편하다.

## 자주 하는 실수

### 파일 위치와 package 선언이 다르다

파일 위치와 `package` 선언이 다르면 IDE나 빌드 도구에서 오류가 난다.

### 설정 파일 이름을 틀린다

`applications.yml`이 아니라 `application.yml`이다. 끝에 `s`가 붙지 않는다.

### 테스트 코드를 `src/main/java`에 둔다

테스트 코드는 `src/test/java`에 둔다. 그래야 빌드와 배포 결과물에 섞이지 않는다.
