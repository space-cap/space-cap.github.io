# 최종 프로젝트

## 이번 장에서 배울 것

이번 장에서는 지금까지 배운 Spring Boot 3.5.x 내용을 하나의 최종 프로젝트로 연결한다.

목표는 거창한 서비스를 만드는 것이 아니다. 초보자가 실무에 가까운 구조를 경험할 수 있도록 인증, CRUD, 검증, 예외 처리, DB, 테스트, 운영 설정, 배포 준비까지 담은 작은 서비스를 완성하는 것이다.

## 프로젝트 주제

추천 주제는 인증이 있는 할 일 관리 API다.

이유:

- 도메인이 단순하다.
- CRUD를 모두 다룰 수 있다.
- 사용자별 데이터 분리가 필요하다.
- 인증과 권한을 붙이기 좋다.
- 테스트하기 쉽다.
- 배포 예제로도 적당하다.

프로젝트 이름:

```text
todo-api
```

### 사용자

## Entity 설계

사용자:

```java
@Entity
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String email;

    @Column(nullable = false)
    private String password;

    @Column(nullable = false)
    private String name;
}
```

할 일:

```java
@Entity
public class Todo {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    private User user;

    @Column(nullable = false)
    private String title;

    private String description;

    @Column(nullable = false)
    private boolean completed;
}
```

실제 구현에서는 생성자, 정적 팩터리 메서드, 변경 메서드를 추가한다.

## DTO 설계

요청 DTO:

```java
public record CreateTodoRequest(
        @NotBlank String title,
        @Size(max = 1000) String description
) {
}
```

응답 DTO:

```java
public record TodoResponse(
        Long id,
        String title,
        String description,
        boolean completed
) {
    public static TodoResponse from(Todo todo) {
        return new TodoResponse(
                todo.getId(),
                todo.getTitle(),
                todo.getDescription(),
                todo.isCompleted()
        );
    }
}
```

Entity를 API 응답으로 직접 내보내지 않는다.

## 예외 응답

공통 오류 응답:

```java
public record ErrorResponse(
        String code,
        String message
) {
}
```

예외 처리:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(TodoNotFoundException.class)
    public ResponseEntity<ErrorResponse> handle(TodoNotFoundException e) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(new ErrorResponse("TODO_NOT_FOUND", e.getMessage()));
    }
}
```

## 보안 설계

처음 단계:

```text
세션 기반 로그인 또는 HTTP Basic으로 구조 이해
```

확장 단계:

```text
JWT 기반 인증
```

보안 설정 예:

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                    .requestMatchers("/api/users/signup", "/api/auth/login").permitAll()
                    .anyRequest().authenticated())
            .build();
}
```

실제 운영에서는 CSRF, CORS, 토큰 저장 위치, refresh token 전략을 더 깊게 설계해야 한다.

## DB 마이그레이션

Flyway 파일:

```text
src/main/resources/db/migration/V1__create_users.sql
src/main/resources/db/migration/V2__create_todos.sql
```

예:

```sql
create table users (
    id bigserial primary key,
    email varchar(255) not null unique,
    password varchar(255) not null,
    name varchar(100) not null
);
```

운영에 가까운 프로젝트에서는 JPA `ddl-auto`보다 migration 도구를 사용한다.

## 운영 설정

`application-local.yml`:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/todo
    username: todo
    password: todo
  jpa:
    hibernate:
      ddl-auto: validate
```

`application-prod.yml`:

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
```

운영 설정에서 민감 정보는 환경 변수로 분리한다.

## Docker Compose

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: todo
      POSTGRES_USER: todo
      POSTGRES_PASSWORD: todo
    ports:
      - "5432:5432"

  app:
    build: .
    environment:
      SPRING_PROFILES_ACTIVE: local
      DB_URL: jdbc:postgresql://db:5432/todo
      DB_USERNAME: todo
      DB_PASSWORD: todo
    ports:
      - "8080:8080"
    depends_on:
      - db
```

## 완성 기준

최종 프로젝트가 완성되었다고 볼 수 있는 기준:

```text
[ ] 회원 가입이 된다.
[ ] 로그인 또는 인증이 된다.
[ ] 인증된 사용자가 자기 할 일만 볼 수 있다.
[ ] 할 일 CRUD가 동작한다.
[ ] 잘못된 요청은 검증 오류를 반환한다.
[ ] 없는 리소스는 404를 반환한다.
[ ] Repository/Service/Controller 테스트가 있다.
[ ] PostgreSQL에서 동작한다.
[ ] Flyway로 스키마가 생성된다.
[ ] Actuator health가 동작한다.
[ ] Docker로 실행할 수 있다.
[ ] README에 실행 방법이 적혀 있다.
```

## 자주 하는 실수

### 처음부터 완벽한 구조를 만들려고 한다

작게 시작해서 리팩터링하자. 처음부터 복잡한 구조는 학습을 방해한다.

### Entity를 그대로 응답한다

DTO를 사용해 API 계약과 내부 모델을 분리하자.

### 인증을 마지막에 붙인다

사용자별 데이터 분리가 필요하면 중간 단계에서 보안을 붙이는 것이 좋다.

### 테스트를 마지막에 몰아서 작성한다

기능이 작을 때 테스트를 함께 작성해야 쉽다.
