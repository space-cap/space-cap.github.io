# 운영용 설정 관리

## 이번 장에서 배울 것

이 장에서는 운영 환경에서 설정을 관리하는 방법을 배운다.

개발 환경에서는 `application.yml`에 값을 적어도 큰 문제가 없어 보인다. 하지만 운영에서는 DB 비밀번호, API Key, JWT Secret, 외부 API 주소 같은 값이 민감하다. 설정 관리는 보안과 안정성의 출발점이다.

## 운영 설정의 원칙

운영 설정은 다음 원칙을 지킨다.

- 민감 정보는 Git에 올리지 않는다.
- 환경별 설정은 분리한다.
- 운영 값은 배포 환경에서 주입한다.
- 기본값과 필수값을 구분한다.
- 설정 변경 이력을 관리한다.
- 설정을 로그에 노출하지 않는다.

코드와 설정을 분리해야 같은 애플리케이션을 local, dev, prod에서 다르게 실행할 수 있다.

## Profile 분리

기본 설정:

```text
application.yml
```

환경별 설정:

```text
application-local.yml
application-dev.yml
application-prod.yml
```

`application.yml`에는 공통 설정을 둔다.

```yaml
spring:
  application:
    name: todo-api
```

`application-prod.yml`에는 운영 전용 설정을 둔다.

```yaml
server:
  port: 8080

logging:
  level:
    root: info
```

단, 운영 비밀번호 같은 민감 정보는 파일에 직접 쓰지 않는다.

## 환경 변수 사용

운영에서는 환경 변수를 자주 사용한다.

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}

jwt:
  secret: ${JWT_SECRET}
```

환경 변수 예:

```bash
export DB_URL=jdbc:postgresql://db:5432/todo
export DB_USERNAME=todo
export DB_PASSWORD=secret
export JWT_SECRET=very-secret-value
```

Windows PowerShell:

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/todo"
$env:DB_USERNAME="todo"
$env:DB_PASSWORD="secret"
```

## 기본값 지정

개발 편의를 위해 기본값을 줄 수 있다.

```yaml
external:
  payment-url: ${PAYMENT_URL:http://localhost:9000}
```

하지만 비밀번호와 secret에는 기본값을 주지 않는 편이 안전하다. 누락되면 애플리케이션이 시작 실패하는 것이 낫다.

## ConfigurationProperties 사용

설정 값이 많아지면 `@Value`보다 `@ConfigurationProperties`가 좋다.

설정:

```yaml
todo:
  policy:
    max-title-length: 100
    allow-empty-description: false
```

클래스:

```java
package com.example.todo.config;

import org.springframework.boot.context.properties.ConfigurationProperties;

@ConfigurationProperties(prefix = "todo.policy")
public record TodoPolicyProperties(
        int maxTitleLength,
        boolean allowEmptyDescription
) {
}
```

활성화:

```java
package com.example.todo.config;

import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableConfigurationProperties(TodoPolicyProperties.class)
public class TodoPolicyConfig {
}
```

설정을 타입으로 묶으면 테스트와 유지보수가 쉬워진다.

## 설정 검증

필수 설정을 검증할 수도 있다.

```java
package com.example.todo.config;

import jakarta.validation.constraints.Min;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

@Validated
@ConfigurationProperties(prefix = "todo.policy")
public record TodoPolicyProperties(
        @Min(1)
        int maxTitleLength
) {
}
```

잘못된 설정이면 애플리케이션 시작 단계에서 실패한다. 운영에서는 빨리 실패하는 것이 조용히 잘못 동작하는 것보다 낫다.

## Actuator env와 configprops 주의

Actuator의 `env`, `configprops` endpoint는 설정 확인에 유용하다.

하지만 민감 정보가 포함될 수 있다.

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info
```

운영에서 `env`, `configprops`를 노출해야 한다면 반드시 인증, 권한, 네트워크 제한을 적용한다.

Spring Boot는 민감한 값에 대한 sanitization을 제공하지만, 그것만 믿고 넓게 노출하지 않는다.

## 설정 변경 전략

설정 변경은 코드 변경만큼 조심스럽게 다룬다.

추천 절차:

1. 변경 이유를 기록한다.
2. dev 환경에서 먼저 적용한다.
3. 모니터링 지표를 확인한다.
4. prod에 반영한다.
5. 문제 발생 시 되돌릴 방법을 준비한다.

특히 커넥션 풀 크기, timeout, thread pool 크기 같은 설정은 서비스 안정성에 직접 영향을 준다.

## 자주 하는 실수

### 운영 비밀번호를 Git에 올린다

한 번 올라간 secret은 삭제 커밋만으로 안전해지지 않는다. 즉시 폐기하고 재발급해야 한다.

### local 기본값을 운영에서 그대로 사용한다

`localhost`, `password`, `changeme` 같은 값이 운영에 들어가지 않도록 배포 전 점검한다.

### 설정을 로그에 찍는다

디버깅용으로 전체 설정을 로그에 출력하면 민감 정보가 새어 나갈 수 있다.

## 확인 문제
