# 로깅 기초

## 이번 장에서 배울 것

이 장에서는 Spring Boot의 로깅 기본기를 배운다.

초보자는 문제가 생기면 코드만 계속 쳐다보는 경우가 많다. 하지만 서버 애플리케이션에서 문제의 출발점은 대부분 로그에 남아 있다. 로그를 읽을 줄 알면 오류 해결 속도가 크게 빨라진다.

## 로그란 무엇인가

로그는 애플리케이션이 실행되는 동안 남기는 기록이다.

예를 들어 다음과 같은 정보가 로그에 나온다.

- 애플리케이션 시작 여부
- 어떤 Profile이 활성화됐는지
- 내장 서버가 몇 번 포트로 떴는지
- 요청 처리 중 발생한 예외
- DB 연결 실패
- 개발자가 직접 남긴 메시지

Spring Boot를 실행하면 처음부터 많은 로그가 출력된다. 처음에는 복잡해 보여도 자주 보는 줄은 정해져 있다.

## 기본 로그 레벨

로그에는 심각도 수준이 있다.

| 레벨 | 의미 |
| --- | --- |
| `TRACE` | 가장 자세한 추적 정보 |
| `DEBUG` | 디버깅용 상세 정보 |
| `INFO` | 일반적인 실행 정보 |
| `WARN` | 당장 실패는 아니지만 주의가 필요한 상황 |
| `ERROR` | 오류 발생 |

Spring Boot는 기본적으로 콘솔에 로그를 출력한다. 기본 설정에서는 `ERROR`, `WARN`, `INFO` 수준의 로그가 출력된다.

## 실행 로그에서 볼 것

애플리케이션을 실행하면 다음 정보를 먼저 찾는다.

### 1. 활성 Profile

```text
The following 1 profile is active: "local"
```

또는:

```text
No active profile set, falling back to 1 default profile: "default"
```

내가 의도한 Profile로 실행됐는지 확인한다.

### 2. 포트

```text
Tomcat started on port 8080
```

요청을 보낼 포트를 확인한다.

### 3. 시작 완료

```text
Started TodoApplication
```

이 로그가 나오면 애플리케이션이 정상적으로 시작된 것이다.

## 코드에서 로그 남기기

Spring Boot에서는 SLF4J API를 사용해 로그를 남기는 것이 일반적이다.

```java
package com.example.todo;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class LogExampleController {

    private static final Logger log =
            LoggerFactory.getLogger(LogExampleController.class);

    @GetMapping("/log-example")
    public String logExample() {
        log.info("log example endpoint called");
        return "ok";
    }
}
```

요청:

```bash
curl http://localhost:8080/log-example
```

콘솔에 다음과 비슷한 로그가 나온다.

```text
INFO ... LogExampleController : log example endpoint called
```

## 문자열 결합 대신 placeholder 사용

로그를 남길 때는 문자열 더하기보다 placeholder를 사용한다.

좋지 않은 예:

```java
log.debug("todo id = " + todoId);
```

좋은 예:

```java
log.debug("todo id = {}", todoId);
```

placeholder를 사용하면 로그 레벨에 따라 실제 문자열 생성 비용을 줄일 수 있고, 코드도 읽기 좋다.

## 패키지별 로그 레벨 설정

`application.yml`:

```yaml
logging:
  level:
    root: info
    com.example.todo: debug
```

이 설정은 전체 기본 로그 레벨은 `info`로 두고, 우리 애플리케이션 패키지인 `com.example.todo`만 `debug`까지 출력한다.

개발 중에는 우리 코드의 `debug` 로그를 보고 싶지만, 모든 라이브러리의 `debug` 로그까지 보면 너무 시끄럽다. 그래서 패키지별 설정이 중요하다.

## debug 모드와 로그 레벨은 다르다

Spring Boot는 `--debug` 플래그를 지원한다.

```bash
java -jar todo.jar --debug
```

또는:

```yaml
debug: true
```

하지만 이것은 애플리케이션의 모든 로그를 `DEBUG`로 바꾸는 뜻이 아니다. Spring Boot의 핵심 로거 일부가 더 자세한 정보를 출력하도록 하는 기능이다.

내 코드의 로그 레벨을 바꾸려면 다음처럼 `logging.level`을 사용한다.

```yaml
logging:
  level:
    com.example.todo: debug
```

## 파일로 로그 남기기

기본적으로 Spring Boot는 콘솔에만 로그를 출력한다. 파일로도 남기고 싶다면 다음 설정을 사용할 수 있다.

```yaml
logging:
  file:
    name: logs/todo.log
```

이제 애플리케이션을 실행하면 `logs/todo.log` 파일에 로그가 기록된다.

학습 초반에는 콘솔 로그만으로 충분하다. 파일 로그는 운영 준비 파트에서 더 자세히 다룬다.

## 로그에 남기면 안 되는 것

다음 값은 로그에 직접 남기지 않는다.

- 비밀번호
- 인증 토큰
- API Key
- 주민등록번호 같은 개인정보
- 카드 번호

로그는 운영 중 문제를 추적하는 데 중요하지만, 잘못 남기면 보안 사고의 원인이 된다.

## 자주 하는 실수

### `System.out.println`을 계속 사용한다

간단한 확인에는 쓸 수 있지만, 애플리케이션 코드에서는 Logger를 사용하는 습관을 들인다. 로그 레벨과 출력 형식을 관리할 수 있기 때문이다.

### 오류 로그를 읽지 않고 맨 아래만 본다

예외는 위에서부터 원인을 찾아야 한다. `Caused by` 근처에 실제 원인이 숨어 있는 경우가 많다.

### 운영에서 DEBUG 로그를 과하게 켠다

DEBUG 로그는 성능과 저장 공간에 영향을 줄 수 있다. 운영에서는 필요한 패키지에만 제한적으로 켠다.
