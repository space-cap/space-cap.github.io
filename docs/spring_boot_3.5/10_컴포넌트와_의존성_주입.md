# 컴포넌트와 의존성 주입

## 이번 장에서 배울 것

이 장에서는 Spring의 핵심인 Bean, Component, 의존성 주입을 배운다.

Spring Boot를 잘 쓰려면 결국 "객체를 누가 만들고, 누가 연결하는가"를 이해해야 한다.

## 직접 객체를 만드는 방식

순수 Java에서는 보통 필요한 객체를 직접 만든다.

```java
public class TodoController {

    private final TodoService todoService = new TodoService();
}
```

작은 프로그램에서는 괜찮다. 하지만 애플리케이션이 커지면 문제가 생긴다.

- 구현체를 바꾸기 어렵다.
- 테스트에서 가짜 객체로 바꾸기 어렵다.
- 객체 생성 책임이 여러 곳에 흩어진다.
- 설정과 생명주기 관리가 어려워진다.

Spring은 이 문제를 Container와 Bean으로 해결한다.

## Bean이란 무엇인가

Bean은 Spring Container가 관리하는 객체다.

개발자가 직접 `new`로 만들고 버리는 객체가 아니라, Spring이 만들고 필요한 곳에 넣어 주는 객체다.

Spring이 관리하면 다음 장점이 생긴다.

- 객체 생성 위치가 명확해진다.
- 의존성 연결이 자동화된다.
- 테스트에서 대체하기 쉬워진다.
- 트랜잭션, 보안, 로깅 같은 부가 기능을 적용하기 쉬워진다.

## Component란 무엇인가

`@Component`는 "이 클래스를 Spring Bean으로 등록해 달라"는 표시다.

```java
import org.springframework.stereotype.Component;

@Component
public class TodoService {
}
```

Spring Boot는 `@SpringBootApplication`이 있는 패키지와 그 하위 패키지를 스캔하면서 `@Component`가 붙은 클래스를 Bean으로 등록한다.

## 역할별 애너테이션

Spring에는 `@Component`를 더 구체적인 의미로 표현하는 애너테이션이 있다.

| 애너테이션 | 주 용도 |
| --- | --- |
| `@Controller` | 화면 또는 웹 요청 처리 |
| `@RestController` | REST API 요청 처리 |
| `@Service` | 비즈니스 로직 |
| `@Repository` | 데이터 접근 |
| `@Configuration` | 설정 클래스 |

이 애너테이션들은 모두 Bean 등록 대상이다. 단지 역할을 더 잘 드러내기 위해 구분해서 사용한다.

## 의존성 주입이란 무엇인가

의존성 주입은 필요한 객체를 외부에서 넣어 주는 방식이다.

Spring에서는 보통 생성자 주입을 사용한다.

```java
import org.springframework.stereotype.Service;

@Service
public class TodoService {

    public String getMessage() {
        return "할 일 서비스를 준비했습니다.";
    }
}
```

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class TodoController {

    private final TodoService todoService;

    public TodoController(TodoService todoService) {
        this.todoService = todoService;
    }

    @GetMapping("/todos/message")
    public String message() {
        return todoService.getMessage();
    }
}
```

`TodoController`는 `TodoService`를 직접 만들지 않는다. 생성자를 통해 받는다. Spring은 `TodoService` Bean을 찾아서 `TodoController`를 만들 때 넣어 준다.

## 왜 생성자 주입을 권장할까?

생성자 주입은 의존성을 명확하게 보여준다.

장점은 다음과 같다.

- 필요한 의존성이 `final`로 고정된다.
- 객체 생성 시점에 필요한 값이 빠지면 바로 알 수 있다.
- 테스트 코드에서 직접 가짜 객체를 넣기 쉽다.
- 순환 의존성을 발견하기 쉽다.

필드 주입도 가능하지만, 처음부터 생성자 주입을 습관으로 만드는 것이 좋다.

## 간단한 계층 구조

처음 프로젝트에서는 다음 흐름을 자주 사용한다.

```text
Controller -> Service -> Repository
```

각 역할은 다음과 같다.

- Controller: HTTP 요청과 응답 담당
- Service: 비즈니스 규칙 담당
- Repository: 데이터 저장소 접근 담당

처음에는 Repository 없이 Service까지만 만들어도 된다. DB를 배우는 장에서 Repository가 본격적으로 등장한다.

## 자주 하는 실수

### `new`와 DI를 섞어 쓴다

Spring이 관리해야 하는 객체를 직접 `new`로 만들면 Spring의 도움을 받을 수 없다. 가능한 한 Bean끼리는 생성자 주입으로 연결한다.

### `@Service`를 빼먹는다

생성자 주입 대상이 Bean으로 등록되어 있지 않으면 Spring이 주입할 수 없다. Service 클래스에 `@Service`가 붙어 있는지 확인한다.

### 패키지 위치가 스캔 범위 밖이다

Bean 애너테이션을 붙였는데도 등록되지 않는다면 패키지 위치를 확인한다. 메인 클래스의 하위 패키지에 두는 것이 기본이다.
