# 예외 처리

## 이번 장에서 배울 것

이 장에서는 REST API의 예외 처리 방식을 배운다.

좋은 API는 성공 응답만 예쁘게 만들지 않는다. 실패했을 때도 클라이언트가 이해할 수 있는 상태 코드와 에러 메시지를 돌려준다.

## 기본 에러 응답의 한계

Spring Boot는 기본 에러 응답을 제공한다. 그래서 예외 처리를 전혀 하지 않아도 서버는 에러 응답을 반환한다.

하지만 실무 API에서는 보통 다음 요구가 생긴다.

- 모든 에러 응답 형식을 통일하고 싶다.
- 검증 실패 필드 목록을 내려주고 싶다.
- 비즈니스 오류마다 다른 상태 코드를 주고 싶다.
- 내부 예외 메시지를 그대로 노출하지 않고 싶다.

이를 위해 `@RestControllerAdvice`와 `@ExceptionHandler`를 사용한다.

## 에러 응답 DTO 만들기

```java
package com.example.todo.common;

import java.time.LocalDateTime;
import java.util.List;

public record ErrorResponse(
        LocalDateTime timestamp,
        int status,
        String code,
        String message,
        List<FieldErrorResponse> errors
) {

    public static ErrorResponse of(
            int status,
            String code,
            String message
    ) {
        return new ErrorResponse(
                LocalDateTime.now(),
                status,
                code,
                message,
                List.of()
        );
    }

    public static ErrorResponse of(
            int status,
            String code,
            String message,
            List<FieldErrorResponse> errors
    ) {
        return new ErrorResponse(
                LocalDateTime.now(),
                status,
                code,
                message,
                errors
        );
    }
}
```

```java
package com.example.todo.common;

public record FieldErrorResponse(
        String field,
        String message
) {
}
```

에러 응답 예:

```json
{
  "timestamp": "2026-05-19T10:30:00",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "message": "요청 값이 올바르지 않습니다.",
  "errors": [
    {
      "field": "title",
      "message": "제목은 비어 있을 수 없습니다."
    }
  ]
}
```

## 전역 예외 처리 클래스

```java
package com.example.todo.common;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.List;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(
            MethodArgumentNotValidException exception
    ) {
        List<FieldErrorResponse> errors = exception.getBindingResult()
                .getFieldErrors()
                .stream()
                .map(error -> new FieldErrorResponse(
                        error.getField(),
                        error.getDefaultMessage()
                ))
                .toList();

        ErrorResponse response = ErrorResponse.of(
                HttpStatus.BAD_REQUEST.value(),
                "VALIDATION_FAILED",
                "요청 값이 올바르지 않습니다.",
                errors
        );

        return ResponseEntity.badRequest().body(response);
    }
}
```

`@RestControllerAdvice`는 여러 Controller에서 발생한 예외를 한 곳에서 처리할 수 있게 해준다.

`@ExceptionHandler`는 어떤 예외를 처리할지 지정한다.

## 비즈니스 예외 만들기

할 일을 찾지 못했을 때 사용할 예외를 만든다.

```java
package com.example.todo.todo;

public class TodoNotFoundException extends RuntimeException {

    public TodoNotFoundException(Long id) {
        super("할 일을 찾을 수 없습니다. id=" + id);
    }
}
```

Service 또는 예제 Controller에서 예외를 던질 수 있다.

```java
@GetMapping("/{id}")
public TodoResponse findById(@PathVariable Long id) {
    if (id == 999L) {
        throw new TodoNotFoundException(id);
    }

    return new TodoResponse(id, "Spring Boot 공부", false);
}
```

전역 예외 처리에 추가한다.

```java
@ExceptionHandler(TodoNotFoundException.class)
public ResponseEntity<ErrorResponse> handleTodoNotFound(
        TodoNotFoundException exception
) {
    ErrorResponse response = ErrorResponse.of(
            HttpStatus.NOT_FOUND.value(),
            "TODO_NOT_FOUND",
            exception.getMessage()
    );

    return ResponseEntity.status(HttpStatus.NOT_FOUND).body(response);
}
```

## 예상하지 못한 예외 처리

마지막 안전망으로 `Exception`도 처리할 수 있다.

```java
@ExceptionHandler(Exception.class)
public ResponseEntity<ErrorResponse> handleException(Exception exception) {
    ErrorResponse response = ErrorResponse.of(
            HttpStatus.INTERNAL_SERVER_ERROR.value(),
            "INTERNAL_SERVER_ERROR",
            "서버 내부 오류가 발생했습니다."
    );

    return ResponseEntity
            .status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(response);
}
```

주의할 점은 내부 예외 메시지를 그대로 클라이언트에 노출하지 않는 것이다. DB 오류, 파일 경로, 토큰 정보 같은 민감한 단서가 새어 나갈 수 있다.

## 상태 코드 선택

자주 쓰는 매핑은 다음과 같다.

| 상황 | 상태 코드 |
| --- | --- |
| 요청 값 검증 실패 | `400 Bad Request` |
| 인증 필요 | `401 Unauthorized` |
| 권한 없음 | `403 Forbidden` |
| 리소스 없음 | `404 Not Found` |
| 중복 또는 상태 충돌 | `409 Conflict` |
| 예상하지 못한 서버 오류 | `500 Internal Server Error` |

상태 코드는 클라이언트와의 약속이다. 실패했는데 무조건 `200 OK`를 반환하면 클라이언트가 오류를 제대로 처리하기 어렵다.

## 로그는 남기되 응답은 숨긴다

서버 내부에서는 원인을 추적할 수 있도록 로그를 남겨야 한다.

```java
private static final Logger log =
        LoggerFactory.getLogger(GlobalExceptionHandler.class);

@ExceptionHandler(Exception.class)
public ResponseEntity<ErrorResponse> handleException(Exception exception) {
    log.error("Unexpected exception", exception);

    ErrorResponse response = ErrorResponse.of(
            500,
            "INTERNAL_SERVER_ERROR",
            "서버 내부 오류가 발생했습니다."
    );

    return ResponseEntity.status(500).body(response);
}
```

클라이언트에게는 안전한 메시지를 주고, 서버 로그에는 자세한 원인을 남긴다.

## 자주 하는 실수

### 모든 예외를 `200 OK`로 응답한다

HTTP 상태 코드를 활용해야 클라이언트가 성공과 실패를 명확하게 구분할 수 있다.

### 내부 예외 메시지를 그대로 노출한다

예상하지 못한 예외는 안전한 공통 메시지를 사용한다.

### Controller마다 try-catch를 반복한다

공통 예외 처리는 `@RestControllerAdvice`로 모은다.
