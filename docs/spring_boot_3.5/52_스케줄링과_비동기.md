# 스케줄링과 비동기

## 이번 장에서 배울 것

이번 장에서는 Spring Boot에서 일정한 시간마다 작업을 실행하는 방법과, 요청 처리와 분리해서 백그라운드 작업을 실행하는 방법을 배운다.

핵심 애너테이션은 두 가지다.

- `@Scheduled`: 정해진 시간마다 실행
- `@Async`: 별도 스레드에서 비동기 실행

둘 다 편리하지만 운영에서는 스레드, 중복 실행, 실패 처리까지 함께 생각해야 한다.

## 스케줄링이 필요한 상황

스케줄링은 사람이 직접 호출하지 않아도 주기적으로 실행되는 작업이다.

예:

- 매일 새벽 오래된 임시 파일 삭제
- 5분마다 외부 API에서 환율 정보 갱신
- 매시간 만료된 토큰 정리
- 매일 오전 리포트 생성
- 일정 시간마다 알림 발송 대상 찾기

웹 요청은 사용자가 부르는 작업이고, 스케줄링은 시스템이 스스로 실행하는 작업이라고 보면 쉽다.

## 스케줄링 켜기

```java
package com.example.todo.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableScheduling;

@Configuration
@EnableScheduling
public class SchedulingConfig {
}
```

그 다음 `@Scheduled`를 사용한다.

```java
package com.example.todo.job;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

@Component
public class TodoCleanupJob {

    private static final Logger log = LoggerFactory.getLogger(TodoCleanupJob.class);

    @Scheduled(fixedDelay = 60000)
    public void cleanup() {
        log.info("오래된 할 일 정리 작업 실행");
    }
}
```

`fixedDelay = 60000`은 이전 실행이 끝난 뒤 60초 후에 다시 실행한다는 뜻이다.

## fixedDelay와 fixedRate

`fixedDelay`:

```java
@Scheduled(fixedDelay = 60000)
public void job() {
}
```

이전 작업이 끝난 뒤 일정 시간이 지나면 다시 실행한다.

`fixedRate`:

```java
@Scheduled(fixedRate = 60000)
public void job() {
}
```

작업 시작 시점을 기준으로 일정 간격마다 실행한다.

초보자는 `fixedDelay`부터 쓰는 것이 안전하다. 작업 시간이 길어졌을 때 겹쳐 실행될 가능성을 줄이기 쉽기 때문이다.

## cron 표현식

매일 특정 시간에 실행하려면 cron을 사용한다.

```java
@Scheduled(cron = "0 0 3 * * *")
public void runAtThree() {
}
```

위 예시는 매일 새벽 3시에 실행한다.

Spring의 cron은 보통 다음 6개 필드를 사용한다.

```text
초 분 시 일 월 요일
```

예:

```text
0 0 9 * * MON-FRI
```

평일 오전 9시에 실행한다.

## 설정으로 주기 관리하기

코드에 시간을 고정하면 운영에서 바꾸기 어렵다.

```java
@Scheduled(fixedDelayString = "${jobs.cleanup-delay}")
public void cleanup() {
}
```

`application.yml`:

```yaml
jobs:
  cleanup-delay: 60000
```

운영에서는 환경마다 스케줄 주기를 다르게 둘 수 있다.

## 비동기가 필요한 상황

비동기는 호출한 쪽이 결과를 기다리지 않아도 되는 작업에 사용한다.

예:

- 회원 가입 후 이메일 발송
- 요청 처리 후 감사 로그 저장
- 이미지 리사이징 요청
- 알림 메시지 발송
- 외부 시스템으로 이벤트 전송

비동기는 "빠르게 응답하기 위해 뒤로 미루는 작업"에 적합하다.

## 비동기 켜기

```java
package com.example.todo.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableAsync;

@Configuration
@EnableAsync
public class AsyncConfig {
}
```

비동기 메서드:

```java
package com.example.todo.service;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;

@Service
public class MailLogService {

    private static final Logger log = LoggerFactory.getLogger(MailLogService.class);

    @Async
    public void sendWelcomeLog(String email) {
        log.info("환영 메일 발송 로그 저장: {}", email);
    }
}
```

호출하는 쪽:

```java
@Service
public class UserService {

    private final MailLogService mailLogService;

    public UserService(MailLogService mailLogService) {
        this.mailLogService = mailLogService;
    }

    public void register(String email) {
        // 사용자 저장
        mailLogService.sendWelcomeLog(email);
    }
}
```

`sendWelcomeLog`는 별도 스레드에서 실행된다.

## 비동기 반환 타입

결과가 필요 없다면 `void`를 사용할 수 있다.

결과가 필요하면 `CompletableFuture`를 사용할 수 있다.

```java
@Async
public CompletableFuture<Integer> countTodosAsync(Long userId) {
    int count = todoRepository.countByUserId(userId);
    return CompletableFuture.completedFuture(count);
}
```

## TaskExecutor 설정

Spring Boot는 별도 `Executor` Bean이 없으면 `AsyncTaskExecutor`를 자동 설정한다. Java 21 이상에서 `spring.threads.virtual.enabled=true`를 사용하면 가상 스레드 기반 실행기를 사용할 수 있다.

운영에서는 스레드 이름과 풀 크기를 명시하는 편이 좋다.

```java
package com.example.todo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

@Configuration
public class TaskExecutorConfig {

    @Bean(name = "taskExecutor")
    public ThreadPoolTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(20);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("todo-async-");
        executor.initialize();
        return executor;
    }
}
```

## `@Async`의 중요한 제약

`@Async`는 Spring 프록시를 통해 동작한다. 그래서 같은 클래스 내부에서 자기 자신의 `@Async` 메서드를 호출하면 비동기로 동작하지 않는다.

잘못된 예:

```java
@Service
public class UserService {

    public void register(String email) {
        sendMail(email);
    }

    @Async
    public void sendMail(String email) {
    }
}
```

이 경우 `sendMail`은 그냥 일반 메서드 호출이 된다.

해결 방법은 비동기 메서드를 별도 Bean으로 분리하는 것이다.

## 스케줄 작업의 실패 처리

스케줄 작업에서 예외가 나면 로그에 남기고 다음 실행이 계속될 수 있다. 하지만 실패를 방치하면 운영자는 모른다.

```java
@Scheduled(cron = "0 0 3 * * *")
public void cleanup() {
    try {
        cleanupService.deleteOldData();
    } catch (Exception e) {
        log.error("오래된 데이터 정리 실패", e);
    }
}
```

중요한 작업은 실패 횟수, 마지막 성공 시간, 알림까지 고려해야 한다.

## 여러 서버에서 스케줄 중복 실행

서버를 3대 띄우면 `@Scheduled` 작업도 3대에서 모두 실행된다. 어떤 작업은 괜찮지만, 어떤 작업은 큰 문제가 된다.

예:

- 매일 리포트를 한 번만 보내야 하는데 3번 발송된다.
- 정산 작업이 중복 실행된다.
- 외부 API를 불필요하게 여러 번 호출한다.

이런 경우에는 다음 전략이 필요하다.

- DB 락
- 분산 락
- 스케줄 전용 서버 분리
- Kubernetes CronJob 사용
- Spring Batch와 조합

초보 단계에서는 "서버가 여러 대면 스케줄도 여러 번 돈다"는 사실만 꼭 기억하자.

## 자주 하는 실수

### 오래 걸리는 작업에 fixedRate를 무심코 쓴다

작업 시간이 주기보다 길어지면 겹침 문제가 생길 수 있다. 처음에는 `fixedDelay`가 이해하기 쉽다.

### 비동기 작업의 실패를 확인하지 않는다

요청은 성공했지만 백그라운드 메일 발송이 실패할 수 있다. 실패 로그와 재시도 전략을 생각해야 한다.

### `@Async`를 같은 클래스 내부에서 호출한다

Spring 프록시를 거치지 않으므로 비동기로 실행되지 않는다.

### 스케줄 작업을 모든 서버에서 동시에 실행한다

운영 서버가 여러 대일 때 중복 실행 문제가 생길 수 있다.
