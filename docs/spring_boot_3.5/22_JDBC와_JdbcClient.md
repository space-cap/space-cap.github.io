# JDBC와 JdbcClient

## 이번 장에서 배울 것

이 장에서는 SQL을 직접 작성해서 DB를 다루는 JDBC 방식을 배운다.

JPA는 편리하지만, SQL이 어떻게 실행되는지 모르면 문제가 생겼을 때 원인을 찾기 어렵다. 그래서 먼저 JDBC로 CRUD를 경험하는 것이 좋다.

## JDBC란 무엇인가

JDBC는 Java Database Connectivity의 줄임말이다. Java에서 관계형 데이터베이스에 접속하고 SQL을 실행하기 위한 표준 API다.

순수 JDBC는 반복 코드가 많다.

- Connection 열기
- PreparedStatement 만들기
- 파라미터 바인딩
- ResultSet 읽기
- 예외 처리
- 리소스 닫기

Spring은 이 반복을 줄이기 위해 `JdbcTemplate`을 제공했고, 최근 Spring Framework는 더 현대적인 사용감을 제공하는 `JdbcClient`도 제공한다.

## JdbcTemplate과 JdbcClient

`JdbcTemplate`은 오래전부터 널리 쓰인 Spring JDBC 도구다.

`JdbcClient`는 `JdbcTemplate`과 `NamedParameterJdbcTemplate` 위에 만들어진 더 읽기 좋은 API다. SQL을 직접 쓰면서도 코드가 간결하다.

이 문서에서는 `JdbcClient`를 중심으로 본다.

## Repository 만들기

```java
package com.example.todo.todo;

import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Repository;

import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.List;
import java.util.Optional;

@Repository
public class TodoJdbcRepository {

    private final JdbcClient jdbcClient;

    public TodoJdbcRepository(JdbcClient jdbcClient) {
        this.jdbcClient = jdbcClient;
    }

    public List<Todo> findAll() {
        return jdbcClient.sql("""
                        select id, title, completed, created_at
                        from todos
                        order by id
                        """)
                .query(this::mapRow)
                .list();
    }

    public Optional<Todo> findById(Long id) {
        return jdbcClient.sql("""
                        select id, title, completed, created_at
                        from todos
                        where id = :id
                        """)
                .param("id", id)
                .query(this::mapRow)
                .optional();
    }

    public Todo save(String title) {
        Long id = jdbcClient.sql("""
                        insert into todos (title, completed, created_at)
                        values (:title, false, current_timestamp)
                        returning id
                        """)
                .param("title", title)
                .query(Long.class)
                .single();

        return findById(id).orElseThrow();
    }

    public void deleteById(Long id) {
        jdbcClient.sql("delete from todos where id = :id")
                .param("id", id)
                .update();
    }

    private Todo mapRow(ResultSet rs, int rowNum) throws SQLException {
        return new Todo(
                rs.getLong("id"),
                rs.getString("title"),
                rs.getBoolean("completed"),
                rs.getTimestamp("created_at").toLocalDateTime()
        );
    }
}
```

주의: `returning id` 문법은 DB 종류에 따라 다르게 동작할 수 있다. H2와 PostgreSQL에서는 사용할 수 있지만, 모든 DB에서 같은 방식으로 지원되는 것은 아니다. DB 독립성을 더 높이려면 `KeyHolder` 같은 방식을 검토한다.

## Service 만들기

```java
package com.example.todo.todo;

import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class TodoService {

    private final TodoJdbcRepository todoRepository;

    public TodoService(TodoJdbcRepository todoRepository) {
        this.todoRepository = todoRepository;
    }

    public List<TodoResponse> findAll() {
        return todoRepository.findAll()
                .stream()
                .map(TodoResponse::from)
                .toList();
    }

    public TodoResponse findById(Long id) {
        Todo todo = todoRepository.findById(id)
                .orElseThrow(() -> new TodoNotFoundException(id));
        return TodoResponse.from(todo);
    }

    public TodoResponse create(TodoCreateRequest request) {
        Todo todo = todoRepository.save(request.title());
        return TodoResponse.from(todo);
    }
}
```

DTO:

public record TodoResponse(

## Controller 연결

```java
package com.example.todo.todo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/todos")
public class TodoController {

    private final TodoService todoService;

    public TodoController(TodoService todoService) {
        this.todoService = todoService;
    }

    @GetMapping
    public List<TodoResponse> findAll() {
        return todoService.findAll();
    }

    @GetMapping("/{id}")
    public TodoResponse findById(@PathVariable Long id) {
        return todoService.findById(id);
    }

    @PostMapping
    public TodoResponse create(@RequestBody TodoCreateRequest request) {
        return todoService.create(request);
    }
}
```

## SQL 파라미터 바인딩

다음처럼 문자열을 직접 이어 붙이면 위험하다.

```java
jdbcClient.sql("select * from todos where title = '" + title + "'");
```

SQL Injection 위험이 있고, 특수문자 처리도 어렵다.

좋은 방식:

```java
jdbcClient.sql("select * from todos where title = :title")
        .param("title", title)
        .query(this::mapRow)
        .list();
```

항상 파라미터 바인딩을 사용한다.

## JDBC의 장점과 단점

장점:

- SQL이 명확하게 보인다.
- 복잡한 쿼리를 직접 제어하기 쉽다.
- 동작 원리가 비교적 직관적이다.

단점:

- CRUD 반복 코드가 많다.
- 테이블과 객체 매핑을 직접 해야 한다.
- DB 종류별 SQL 차이를 개발자가 관리해야 한다.

이 단점을 줄이기 위해 JPA와 Spring Data JPA를 사용한다.

## 자주 하는 실수

### SQL 문자열에 값을 직접 붙인다

항상 `param`으로 바인딩한다.

### Repository에서 HTTP 응답 DTO를 반환한다

Repository는 DB 접근에 집중한다. API 응답 DTO 변환은 Service나 Controller 근처에서 처리한다.

### 컬럼 이름과 Java 필드 이름을 혼동한다

DB는 `created_at`, Java는 `createdAt`처럼 이름 규칙이 다를 수 있다. 매핑 코드를 꼼꼼히 본다.
