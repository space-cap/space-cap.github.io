# 공식 문서 읽는 법

## 이번 장에서 배울 것

이번 장에서는 Spring Boot 공식 문서를 어떻게 읽어야 하는지 배운다.

초보자는 공식 문서를 어렵게 느낀다. 하지만 공식 문서는 가장 정확하고, 버전별 차이를 확인할 수 있는 기준점이다. 블로그와 영상은 이해를 돕는 자료이고, 최종 확인은 공식 문서에서 하는 습관을 들이자.

## 공식 문서를 읽어야 하는 이유

Spring Boot는 버전에 따라 설정 이름, 기본값, 권장 방식이 바뀐다.

예:

- Spring Boot 2와 3의 `javax`/`jakarta` 차이
- Spring Security 설정 방식 변화
- Actuator endpoint 기본 노출 정책
- profile 이름 검증
- deprecated properties 제거

블로그 글이 작성된 버전과 내 프로젝트 버전이 다르면 따라 해도 안 될 수 있다.

## 가장 먼저 볼 곳

Spring Boot 3.5 문서 입구:

```text
https://docs.spring.io/spring-boot/3.5/documentation.html
```

이 페이지는 지도다. 설치, 첫 애플리케이션, 기능별 reference, how-to, appendix로 가는 입구를 제공한다.

## 문서 종류 구분하기

### Reference Documentation

기능의 원리와 설정을 설명한다.

읽을 때 좋은 상황:

- 자동 설정이 어떻게 동작하는지 알고 싶다.
- 특정 기능의 공식 설정 방법을 알고 싶다.
- starter가 무엇을 제공하는지 알고 싶다.

### How-to Guides

구체적인 문제 해결 방법을 제공한다.

읽을 때 좋은 상황:

- Docker Compose를 어떻게 붙일까?
- Batch Job을 어떻게 실행할까?
- 특정 배포 환경에서 어떻게 설정할까?

### API Documentation

클래스, 메서드, 애너테이션의 정확한 시그니처를 확인한다.

읽을 때 좋은 상황:

- 메서드 파라미터가 궁금하다.
- 애너테이션 속성의 기본값이 궁금하다.
- 상속 구조나 구현체를 확인하고 싶다.

### Appendix

설정 프로퍼티, 자동 설정 클래스, dependency version 같은 목록성 자료를 제공한다.

읽을 때 좋은 상황:

- `spring.datasource.*` 설정이 궁금하다.
- 어떤 버전의 라이브러리가 관리되는지 알고 싶다.
- test slice에 어떤 자동 설정이 포함되는지 알고 싶다.

## 버전 선택이 중요하다

공식 문서도 버전이 있다.

주소를 확인하자.

```text
https://docs.spring.io/spring-boot/3.5/...
```

`current`, `4.0`, `3.4` 문서를 보고 있으면 내 프로젝트와 다를 수 있다.

Spring Boot 3.5.x를 학습한다면 3.5 문서를 기준으로 읽는다.

## Common Application Properties 읽기

설정 값이 궁금할 때는 Common Application Properties를 검색한다.

예:

```text
server.port
spring.datasource.url
spring.jpa.hibernate.ddl-auto
management.endpoints.web.exposure.include
```

이 문서는 모든 설정을 처음부터 끝까지 읽는 용도가 아니다. 검색해서 필요한 항목을 찾는 사전처럼 사용한다.

## Release Notes 읽기

업그레이드할 때는 release notes를 반드시 읽는다.

읽는 순서:

1. `Upgrading from ...` 섹션
2. breaking change 또는 behavior change
3. deprecated/removed 항목
4. dependency upgrades
5. new and noteworthy

새 기능보다 먼저 봐야 하는 것은 "내 프로젝트가 깨질 수 있는 지점"이다.

## Migration Guide 읽기

큰 버전을 올릴 때는 migration guide를 먼저 본다.

예:

```text
Spring Boot 2.x -> 3.x
```

이런 업그레이드는 단순 dependency 변경이 아니라 코드 구조, import, 보안 설정, 라이브러리 호환성까지 바뀐다.

## 공식 문서 검색 팁

검색어 예:

```text
site:docs.spring.io/spring-boot/3.5 cache
site:docs.spring.io/spring-boot/3.5 Testcontainers
site:docs.spring.io/spring-boot/3.5 spring.data.redis.url
```

브라우저에서 문서 페이지를 열고 `Ctrl+F`로 설정 이름을 검색하는 것도 좋다.

## 코드 예제 읽는 법

공식 문서 코드는 보통 최소 예제다.

읽을 때 질문:

- 어떤 의존성이 필요한가?
- 어떤 Bean이 자동 설정되는가?
- 사용자가 직접 Bean을 만들면 자동 설정이 물러나는가?
- 설정 파일 예시는 properties와 yaml 중 무엇인가?
- 테스트에서는 어떻게 검증할 수 있는가?

코드를 그대로 복사하기 전에 "이 예제가 보여주려는 핵심이 무엇인지"를 먼저 잡자.

## 문서에서 자주 보이는 표현

`auto-configures`:

```text
조건이 맞으면 Spring Boot가 자동으로 Bean이나 설정을 만든다.
```

`backs off`:

```text
사용자가 직접 Bean을 만들면 자동 설정이 물러난다.
```

`classpath`:

```text
현재 애플리케이션이 사용할 수 있는 클래스와 라이브러리 경로
```

`starter`:

```text
관련 의존성을 묶어 둔 편의 dependency
```

`deprecated`:

```text
지금은 동작하지만 앞으로 제거될 수 있으니 다른 방식으로 바꾸라는 표시
```

## 공식 문서와 블로그를 함께 쓰는 법

좋은 순서:

1. 블로그나 영상으로 감을 잡는다.
2. 공식 문서에서 현재 버전 기준을 확인한다.
3. 작은 예제로 직접 실행한다.
4. 내 프로젝트에 적용한다.
5. 테스트로 검증한다.

블로그를 무시할 필요는 없다. 다만 최종 기준은 공식 문서다.

## 자주 하는 실수

### 최신 문서를 보고 예전 프로젝트에 적용한다

Spring Boot 4.0 문서를 보고 3.5 프로젝트에 적용하면 안 맞을 수 있다.

### Stack Overflow 답변을 버전 확인 없이 따라 한다

답변이 Spring Boot 1.x나 2.x 기준일 수 있다.

### release notes에서 새 기능만 본다

업그레이드 때는 breaking change와 deprecated 제거가 더 중요하다.

### Common Application Properties를 암기하려 한다

외우는 문서가 아니다. 검색하는 문서다.

## 확인 문제

1. Spring Boot 3.5 문서인지 확인하려면 URL에서 무엇을 봐야 하는가?
2. 설정 프로퍼티를 찾을 때 어느 appendix를 보면 좋은가?
3. 업그레이드 전에 release notes에서 가장 먼저 볼 섹션은 무엇인가?
4. `backs off`는 자동 설정 문맥에서 어떤 뜻인가?
