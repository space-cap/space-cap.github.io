# PostgreSQL로 전환하기

## 이번 장에서 배울 것

이 장에서는 H2로 개발하던 애플리케이션을 PostgreSQL에 연결하는 방법을 배운다.

H2는 학습에 좋지만 운영 DB와 완전히 같지 않다. 실무에 가까운 개발을 하려면 가능한 한 빨리 실제 운영 후보 DB와 비슷한 환경에서 실행해 보는 것이 좋다.

## 왜 PostgreSQL인가

PostgreSQL은 널리 쓰이는 오픈소스 관계형 데이터베이스다.

장점은 다음과 같다.

- 표준 SQL 지원이 좋다.
- 트랜잭션과 제약 조건이 강력하다.
- JSON, 인덱스, 확장 기능이 풍부하다.
- 실무 백엔드 프로젝트에서 자주 사용된다.

MySQL을 선택해도 괜찮다. 이 문서에서는 PostgreSQL을 기준으로 설명한다.

## 의존성 변경

H2 의존성:

```groovy
runtimeOnly 'com.h2database:h2'
```

PostgreSQL 의존성:

```groovy
runtimeOnly 'org.postgresql:postgresql'
```

JPA와 함께 사용한다면:

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    runtimeOnly 'org.postgresql:postgresql'
}
```

Flyway를 함께 쓴다면:

```groovy
dependencies {
    implementation 'org.flywaydb:flyway-core'
    implementation 'org.flywaydb:flyway-database-postgresql'
    runtimeOnly 'org.postgresql:postgresql'
}
```

## Docker Compose로 PostgreSQL 실행

로컬에 PostgreSQL을 직접 설치해도 되지만, Docker Compose를 쓰면 재현하기 쉽다.

프로젝트 루트에 `compose.yml`을 만든다.

```yaml
services:
  postgres:
    image: postgres:16
    container_name: todo-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: todo
      POSTGRES_USER: todo
      POSTGRES_PASSWORD: todo
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

실행:

```bash
docker compose up -d
```

종료:

```bash
docker compose down
```

데이터까지 삭제:

```bash
docker compose down -v
```

`-v`는 볼륨을 삭제하므로 주의한다.

## Spring Boot 설정

`application-local.yml`:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/todo
    username: todo
    password: todo

  jpa:
    hibernate:
      ddl-auto: validate
    properties:
      hibernate:
        format_sql: true

  flyway:
    enabled: true
```

PostgreSQL JDBC URL 형식:

```text
jdbc:postgresql://host:port/database
```

예:

```text
jdbc:postgresql://localhost:5432/todo
```

## 민감 정보는 환경 변수로 빼기

학습용 로컬 비밀번호는 단순하게 둘 수 있지만, 실무에서는 설정 파일에 비밀번호를 직접 넣지 않는다.

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
```

PowerShell:

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/todo"
$env:DB_USERNAME="todo"
$env:DB_PASSWORD="todo"
```

macOS 또는 Linux:

```bash
export DB_URL=jdbc:postgresql://localhost:5432/todo
export DB_USERNAME=todo
export DB_PASSWORD=todo
```

## PostgreSQL용 Flyway 마이그레이션

`src/main/resources/db/migration/V1__create_todos_table.sql`:

```sql
create table todos (
    id bigserial primary key,
    title varchar(100) not null,
    completed boolean not null default false,
    created_at timestamp not null
);
```

H2에서는 `generated by default as identity`를 썼지만 PostgreSQL에서는 `bigserial`을 사용할 수 있다. PostgreSQL 최신 버전에서는 identity 문법도 가능하다.

DB별 차이를 줄이고 싶다면 SQL 표준에 가까운 문법을 선택하거나, Flyway의 `{vendor}` 위치 전략을 검토한다.

## H2와 PostgreSQL 차이

H2는 편리하지만 PostgreSQL과 다른 점이 있다.

- SQL 문법 차이
- 타입 차이
- 대소문자 처리 차이
- 날짜와 시간 함수 차이
- 자동 증가 ID 문법 차이
- 제약 조건 처리 차이

그래서 "H2에서 됐으니 운영 DB에서도 된다"라고 단정하면 안 된다.

테스트 단계에서는 Testcontainers로 실제 PostgreSQL을 띄워 테스트하는 방식도 많이 사용한다. 이 내용은 테스트 파트에서 다룬다.

```powershell

```

로그에서 다음을 확인한다.


## 자주 하는 실수

### PostgreSQL 컨테이너가 안 떠 있는데 애플리케이션을 실행한다

먼저 `docker compose ps`로 DB 상태를 확인한다.

### 포트 5432 충돌

로컬에 이미 PostgreSQL이 설치되어 있으면 5432 포트가 충돌할 수 있다. Compose의 왼쪽 포트를 바꾼다.

```yaml
ports:
  - "5433:5432"
```

이 경우 JDBC URL은 다음처럼 바꾼다.

```text
jdbc:postgresql://localhost:5433/todo
```

### 운영 DB에서 `ddl-auto: update`를 사용한다

운영 DB 스키마는 Flyway나 Liquibase로 관리하는 것이 안전하다.

### H2 전용 SQL을 PostgreSQL에 그대로 쓴다

자동 증가 ID, 날짜 함수, 타입 문법을 확인한다.
