# 설정 파일과 외부 설정

## 이번 장에서 배울 것

이 장에서는 Spring Boot 설정을 어디에, 어떻게 적는지 배운다.

Spring Boot는 좋은 기본값을 제공하지만, 실제 프로젝트에서는 포트, 애플리케이션 이름, DB 주소, 로그 레벨, 외부 API 주소 같은 값을 바꿔야 한다. 이런 값을 코드에 직접 박아 넣으면 환경이 바뀔 때마다 코드를 다시 빌드해야 한다.

설정 파일과 외부 설정은 이 문제를 해결한다.

## 설정은 왜 코드 밖에 두어야 할까?

다음 코드를 보자.

```java
public class PaymentClient {

    private final String apiUrl = "https://dev-api.example.com";
}
```

개발 환경에서는 괜찮아 보인다. 하지만 운영 환경에서는 주소가 달라질 수 있다.

```text
local: http://localhost:9000
dev: https://dev-api.example.com
prod: https://api.example.com
```

이 값을 코드에 직접 넣으면 환경마다 코드를 고쳐야 한다. 좋은 애플리케이션은 코드는 그대로 두고 설정만 바꿔서 실행할 수 있어야 한다.

## 기본 설정 파일

Spring Boot의 기본 설정 파일 이름은 다음 둘 중 하나다.

```text
application.properties
application.yml
```

둘 다 `src/main/resources` 아래에 둔다.

```text
src/main/resources/application.yml
```

이 문서 모음에서는 `application.yml`을 기본으로 사용한다. 계층 구조가 눈에 잘 들어오기 때문이다.

## properties와 yml 비교

`application.properties`:

```properties
server.port=8081
spring.application.name=todo
logging.level.com.example.todo=debug
```

`application.yml`:

```yaml
server:
  port: 8081

spring:
  application:
    name: todo

logging:
  level:
    com.example.todo: debug
```

둘은 표현 방식만 다르고 같은 설정을 할 수 있다.

## 자주 쓰는 기본 설정

처음 프로젝트에서는 다음 정도를 자주 사용한다.

```yaml
spring:
  application:
    name: todo

server:
  port: 8080

logging:
  level:
    com.example.todo: debug
```

각 의미는 다음과 같다.

- `spring.application.name`: 애플리케이션 이름
- `server.port`: 내장 웹 서버 포트
- `logging.level`: 패키지별 로그 레벨

## 설정 값 읽기: `@Value`

간단한 설정 값은 `@Value`로 읽을 수 있다.

`application.yml`:

```yaml
todo:
  welcome-message: "오늘도 한 걸음씩"
```

Java 코드:

```java
package com.example.todo;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class WelcomeController {

    private final String welcomeMessage;

    public WelcomeController(
            @Value("${todo.welcome-message}") String welcomeMessage
    ) {
        this.welcomeMessage = welcomeMessage;
    }

    @GetMapping("/welcome")
    public String welcome() {
        return welcomeMessage;
    }
}
```

요청:

```bash
curl http://localhost:8080/welcome
```

응답:

```text
오늘도 한 걸음씩
```

## 기본값 지정하기

설정이 없을 때 기본값을 지정할 수도 있다.

```java
@Value("${todo.welcome-message:환영합니다}")
private String welcomeMessage;
```

콜론 뒤의 값이 기본값이다.

하지만 필드 주입보다 생성자 주입이 더 좋다. 위 코드는 기본값 문법을 보여주기 위한 짧은 예다.

## 환경 변수로 설정 바꾸기

Spring Boot 설정은 환경 변수로도 바꿀 수 있다.

예를 들어 다음 설정은:

```yaml
server:
  port: 8080
```

환경 변수로 바꿀 수 있다.

```bash
SERVER_PORT=8081
```

Windows PowerShell에서는 다음처럼 설정한다.

```powershell
$env:SERVER_PORT="8081"
```

이후 애플리케이션을 실행하면 8081 포트를 사용할 수 있다.

## 명령행 인자로 설정 바꾸기

실행할 때 인자로도 설정할 수 있다.

```bash
java -jar todo.jar --server.port=8081
```

Gradle bootRun에서도 인자를 넘길 수 있지만, 초보 단계에서는 JAR 실행 예제부터 이해하면 충분하다.

명령행 인자는 설정 파일보다 우선순위가 높다. 그래서 운영에서는 배포 스크립트나 실행 환경에서 값을 덮어쓰는 방식이 자주 쓰인다.

## 설정 파일 위치

Spring Boot는 기본적으로 여러 위치에서 `application.properties` 또는 `application.yml`을 찾는다.

대표적으로 다음 위치를 사용한다.

- 클래스패스 루트
- 클래스패스의 `/config` 패키지
- 현재 디렉터리
- 현재 디렉터리의 `config/` 하위 디렉터리
- `config/`의 바로 아래 하위 디렉터리

나중에 외부 설정 파일을 운영 서버의 `config/` 폴더에 두고 실행할 수도 있다.

## 비밀값은 코드에 넣지 않는다

DB 비밀번호, API Key, JWT Secret 같은 값은 Git에 올라가면 안 된다.

나쁜 예:

```yaml
payment:
  api-key: "real-secret-key"
```

좋은 방향:

```yaml
payment:
  api-key: ${PAYMENT_API_KEY}
```

실제 값은 환경 변수로 주입한다.

## 자주 하는 실수

### YAML 들여쓰기를 틀린다

YAML은 들여쓰기가 중요하다. 탭보다 공백 두 칸을 사용한다.

잘못된 예:

```yaml
spring:
application:
name: todo
```

올바른 예:

```yaml
spring:
  application:
    name: todo
```

### 설정 파일 이름을 틀린다

`applications.yml`이 아니라 `application.yml`이다.

### 민감 정보를 Git에 올린다

비밀번호와 토큰은 설정 파일에 직접 쓰지 않는다. 로컬 학습용 값이라도 습관을 잘 들이는 것이 좋다.
