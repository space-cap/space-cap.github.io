# 개발 환경 설치

## 이번 장에서 배울 것

이 장에서는 Spring Boot 3.5.x 실습에 필요한 개발 환경을 준비한다.

설치는 한 번만 하면 되지만, 잘못 설치하면 이후 장마다 이상한 오류가 생긴다. 특히 Java 버전과 Gradle Wrapper 사용법은 꼭 확인해야 한다.

## 설치할 도구

필요한 도구는 다음과 같다.

- JDK 21
- IDE
- Git
- HTTP 요청 도구
- 선택 사항: Docker Desktop

Gradle과 Maven은 직접 설치해도 되지만, Spring Initializr로 만든 프로젝트에는 보통 Wrapper가 포함된다. 처음에는 Wrapper를 사용하는 것이 좋다.

## JDK 설치

Spring Boot 3.5.x는 Java 17 이상이 필요하다. 이 문서에서는 Java 21 LTS를 권장한다.

JDK 배포판은 여러 가지가 있다.

- Eclipse Temurin
- Amazon Corretto
- Microsoft Build of OpenJDK
- Oracle JDK

처음이라면 Eclipse Temurin 또는 Amazon Corretto를 설치해도 충분하다.

설치 후 터미널에서 확인한다.

```bash
java -version
```

Java 21이 보이면 좋다.

```text
openjdk version "21..."
```

`javac`도 확인한다.

```bash
javac -version
```

`java`는 있는데 `javac`가 없다면 JRE만 설치했거나 PATH 설정이 잘못되었을 수 있다. Spring Boot 개발에는 JDK가 필요하다.

## IDE 설치

추천 IDE는 다음과 같다.

- IntelliJ IDEA Community 또는 Ultimate
- VS Code
- Eclipse 또는 Spring Tools

초보자에게는 IntelliJ IDEA를 추천한다. Gradle 프로젝트 인식, 코드 자동 완성, 실행 설정이 편하다.

IntelliJ IDEA에서 확인할 설정은 다음과 같다.

- Project SDK가 Java 21인지
- Gradle JVM이 Java 21인지
- 파일 인코딩이 UTF-8인지

## Git 설치

Git은 코드 버전 관리 도구다. Spring Initializr로 프로젝트를 만들 때도 Git이 꼭 필요하지는 않지만, 실무 학습에는 반드시 필요하다.

설치 확인:

```bash
git --version
```

처음 설치했다면 사용자 이름과 이메일을 설정한다.

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

## HTTP 요청 도구 준비

REST API를 만들면 브라우저만으로는 테스트하기 어렵다. 다음 중 하나를 준비한다.

- curl
- HTTPie
- Postman
- IntelliJ HTTP Client

이 문서에서는 터미널에서 바로 사용할 수 있는 curl 예제를 자주 사용한다.

GET 요청 예:

```bash
curl http://localhost:8080/hello
```

POST 요청 예:

```bash
curl -X POST http://localhost:8080/todos \
  -H "Content-Type: application/json" \
  -d '{"title":"Spring Boot 공부"}'
```

Windows PowerShell에서는 줄바꿈 문법이 다르므로, 처음에는 한 줄로 실행해도 된다.

```powershell
curl.exe -X POST http://localhost:8080/todos -H "Content-Type: application/json" -d "{\"title\":\"Spring Boot 공부\"}"
```

## Docker Desktop 설치

Docker는 처음부터 필수는 아니다. 하지만 PostgreSQL, Redis, Testcontainers, 배포 실습에서 유용하다.

처음 1부와 2부는 Docker 없이 진행할 수 있다. 데이터베이스 파트부터 설치해도 된다.

설치 확인:

```bash
docker version
```

## Gradle Wrapper 사용법

Spring Initializr로 Gradle 프로젝트를 만들면 보통 다음 파일이 생긴다.

- `gradlew`
- `gradlew.bat`
- `gradle/wrapper/gradle-wrapper.properties`

Windows에서는 다음 명령을 쓴다.

```powershell
.\gradlew.bat bootRun
```

macOS나 Linux에서는 다음 명령을 쓴다.

```bash
./gradlew bootRun
```

Wrapper의 장점은 팀원 모두가 같은 Gradle 버전을 사용할 수 있다는 점이다. 시스템에 설치된 Gradle 버전이 달라도 프로젝트가 지정한 버전으로 실행된다.

## 자주 하는 실수

### Java 8 또는 11을 사용한다

Spring Boot 3.5.x는 Java 17 이상이 필요하다. 오류가 이상하게 보여도 먼저 `java -version`부터 확인한다.

### IDE의 Java 버전과 터미널 Java 버전이 다르다

터미널에서는 Java 21인데 IDE에서는 Java 17이나 11을 쓰는 경우가 있다. IntelliJ IDEA의 Project SDK와 Gradle JVM 설정을 확인한다.

### PowerShell에서 curl이 다르게 동작한다

Windows PowerShell에서는 `curl`이 별칭으로 동작할 수 있다. 문제가 생기면 `curl.exe`를 사용한다.
