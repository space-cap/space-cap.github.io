# Spring Boot 3.5.x 학습 로드맵

## 이번 장에서 배울 것

이 장에서는 Spring Boot 3.5.x를 어떤 순서로 공부하면 좋은지 정리한다.

Spring Boot는 처음 보면 애너테이션 몇 개와 설정 파일 몇 줄로 모든 일이 갑자기 되는 것처럼 보인다. 초보자에게는 이 편리함이 오히려 장벽이 된다. 그래서 이 문서 모음은 "일단 실행"에서 끝나지 않고, 실행 뒤에서 Spring Boot가 무엇을 대신해 주는지 하나씩 벗겨 보는 방식으로 진행한다.

## 먼저 알아야 할 배경

Spring Boot를 배우기 전에 모든 Java 고급 문법을 완벽히 알 필요는 없다. 다만 다음 정도는 알고 있으면 좋다.

- 클래스, 인터페이스, 메서드, 생성자
- `public`, `private` 같은 접근 제어자
- 컬렉션 `List`, `Map`
- 예외 처리 `try`, `catch`, `throw`
- 애너테이션이 코드에 의미를 붙이는 표식이라는 점
- Gradle 또는 Maven이 외부 라이브러리를 받아오는 도구라는 점

모르면 중간에 다시 찾아보면 된다. Spring Boot 학습에서 중요한 것은 처음부터 완벽한 지식이 아니라, "요청이 들어와서 응답이 나가기까지 어떤 객체들이 협력하는가"를 꾸준히 보는 눈이다.

## 학습 단계

### 1단계: 실행 감각 만들기

먼저 개발 환경을 설치하고, Spring Initializr로 프로젝트를 만든 뒤, 브라우저나 curl로 `Hello Spring Boot` 응답을 확인한다.

이 단계의 목표는 다음과 같다.

- 프로젝트를 만들 수 있다.
- 애플리케이션을 실행할 수 있다.
- HTTP 요청을 보내고 응답을 볼 수 있다.
- 에러가 나도 로그를 보고 최소한 어디서 실패했는지 찾을 수 있다.

### 2단계: Spring Boot가 대신해 주는 일 이해하기

Spring Boot의 핵심은 자동 설정이다. 우리는 `spring-boot-starter-web` 하나를 추가했을 뿐인데 Tomcat, Spring MVC, JSON 변환기, 기본 에러 처리까지 함께 준비된다.

이 단계에서는 다음 질문에 답할 수 있어야 한다.

- Starter는 무엇인가?
- Auto Configuration은 무엇인가?
- Bean은 무엇인가?
- 왜 `@SpringBootApplication` 하나로 애플리케이션이 시작되는가?

### 3단계: REST API 만들기

Controller, DTO, Validation, Exception Handler를 배운다.

초보자는 여기서 코드를 많이 작성해야 한다. 읽기만 하면 아는 것 같지만, 직접 요청 본문을 잘못 보내 보고, 상태 코드가 다르게 나오는 것을 봐야 감각이 생긴다.

### 4단계: 데이터베이스 연결하기

처음에는 H2로 가볍게 시작하고, 이후 PostgreSQL로 전환한다.

데이터 파트에서는 다음을 구분해야 한다.

- SQL을 직접 쓰는 방식
- JPA로 객체와 테이블을 연결하는 방식
- 트랜잭션이 필요한 이유
- 테스트 DB와 운영 DB를 분리하는 이유

### 5단계: 테스트 작성하기

Spring Boot 프로젝트는 실행만 되는 것으로 충분하지 않다. 테스트가 있어야 코드를 고칠 수 있다.

테스트는 다음 순서로 배운다.

- 순수 Java 단위 테스트
- Controller 슬라이스 테스트
- Repository 테스트
- 전체 Spring Context 테스트
- Testcontainers를 이용한 실제 DB 테스트

### 6단계: 보안, 운영, 배포

실무 애플리케이션은 로그인, 권한, 로그, 메트릭, 배포, 설정 분리가 필요하다.

처음부터 보안과 배포를 깊게 파고들면 지치기 쉽다. 그래서 REST API와 DB 흐름이 익숙해진 뒤에 다룬다.

## 이 문서 모음의 추천 실습 프로젝트

처음에는 "할 일 관리 API"로 시작한다.

기능은 작지만 Spring Boot의 거의 모든 기본기를 담을 수 있다.

- 할 일 등록
- 할 일 목록 조회
- 할 일 수정
- 할 일 완료 처리
- 할 일 삭제
- 사용자별 할 일 관리
- 로그인과 권한
- 테스트와 배포

이 프로젝트를 끝까지 가져가면, 이후 게시판, 쇼핑몰, 사내 관리 도구 같은 프로젝트로 확장할 수 있다.

## 초보자가 자주 착각하는 것

### 착각 1: 애너테이션을 많이 외워야 한다

처음부터 애너테이션을 외우려 하지 않아도 된다. 중요한 것은 애너테이션이 Spring에게 어떤 역할을 알려주는지 이해하는 것이다.

예를 들어 `@RestController`는 "이 클래스는 HTTP 요청을 받아 JSON 같은 응답을 돌려주는 Controller다"라고 Spring에게 알려준다.

### 착각 2: 설정이 적으니 내부도 단순하다

Spring Boot는 단순한 도구가 아니라 복잡한 설정을 합리적인 기본값으로 감춘 도구다. 학습의 핵심은 감춰진 설정을 한 번에 다 외우는 것이 아니라, 필요할 때 찾아 들어가는 법을 익히는 것이다.

### 착각 3: JPA부터 깊게 배워야 한다

JPA는 중요하지만 처음부터 깊게 들어가면 Spring Boot의 큰 흐름을 놓치기 쉽다. 먼저 Controller, Service, Repository의 역할을 잡고, 그 다음 JPA를 배워도 늦지 않다.

4. 테스트를 학습 흐름 중반에 넣은 이유는 무엇일까?
