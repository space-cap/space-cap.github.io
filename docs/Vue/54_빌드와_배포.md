# 빌드와 배포

## 이번 장에서 배울 것

개발 중에는 `npm run dev`로 앱을 확인한다. 하지만 실제 사용자에게 제공하려면 배포용 파일로 빌드해야 한다.

이번 장에서는 Vite 기반 Vue 앱의 빌드와 배포 흐름을 배운다.

---

## 개발 서버와 운영 빌드

개발 서버:

```bash
npm run dev
```

개발 서버는 빠른 개발과 새로고침을 위한 모드다. 실제 배포에는 사용하지 않는다.

운영 빌드:

```bash
npm run build
```

빌드가 끝나면 보통 `dist` 폴더가 생성된다. 이 폴더 안의 정적 파일을 서버나 호스팅 서비스에 올린다.

---

## 빌드 결과 미리보기

빌드된 결과를 로컬에서 확인한다.

```bash
npm run preview
```

`preview`는 빌드 결과를 미리 보는 용도다. 운영 서버로 쓰는 목적은 아니다.

---

## package.json 스크립트

Vite 프로젝트에는 보통 다음 스크립트가 있다.

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

배포 전에 최소한 다음을 실행해본다.

```bash
npm run build
npm run preview
```

테스트와 lint를 사용한다면 함께 실행한다.

```bash
npm run lint
npm run test:unit
```

---

## dist 폴더

`dist` 폴더에는 브라우저가 실행할 HTML, CSS, JavaScript, 이미지 파일이 들어간다.

```text
dist/
├─ index.html
└─ assets/
   ├─ index-xxxxx.js
   └─ index-xxxxx.css
```

배포 대상은 소스 파일이 아니라 `dist` 폴더의 결과물이다.

---

## base 경로

GitHub Pages처럼 하위 경로에 배포할 때는 Vite의 `base` 설정이 필요할 수 있다.

`vite.config.js`

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  base: '/repository-name/'
})
```

루트 도메인에 배포한다면 보통 기본값 `/`로 충분하다.

---

## Router와 새로고침 문제

`createWebHistory`를 사용하는 SPA는 `/about` 같은 경로에서 새로고침했을 때 서버가 `index.html`을 반환해야 한다.

서버 설정이 없으면 404가 날 수 있다.

해결 방향:

- 호스팅 서비스의 SPA fallback 설정 사용
- 서버에서 모든 경로를 `index.html`로 연결
- 설정이 어려운 정적 호스팅에서는 `createWebHashHistory` 검토

## Netlify 배포

Netlify에서는 보통 다음 설정을 사용한다.

```text
Build command: npm run build
Publish directory: dist
```

SPA fallback이 필요하면 `public/_redirects` 파일을 사용할 수 있다.

```text
/* /index.html 200
```

---

## Vercel 배포

Vercel은 Vite 프로젝트를 자동 인식하는 경우가 많다.

기본 설정:

```text
Build Command: npm run build
Output Directory: dist
```

환경 변수는 Vercel 프로젝트 설정에서 등록한다.

---

## GitHub Pages 배포

GitHub Pages는 프로젝트 페이지인지 사용자/조직 페이지인지에 따라 `base` 설정이 달라질 수 있다.

예:

```js
base: '/my-vue-app/'
```

정적 파일 배포 방식은 GitHub Actions를 사용할 수 있다. 이 내용은 별도 CI/CD 문서로 확장할 수 있다.

## 배포 전 체크리스트

- `npm run build` 성공
- `npm run preview`로 화면 확인
- 라우터 새로고침 확인
- 환경 변수 값 확인
- API 서버 주소 확인
- 콘솔 에러 확인
- 주요 화면 모바일 확인
- 테스트와 lint 통과

---

## 자주 하는 실수

### dist가 아니라 src를 올림

배포 대상은 빌드 결과인 `dist`다.

### 환경 변수를 운영에 등록하지 않음

로컬 `.env`와 호스팅 서비스 환경 변수는 별개다.

### 라우터 history 모드 새로고침을 확인하지 않음

직접 URL로 접속하거나 새로고침했을 때 404가 나지 않는지 확인한다.

---

## 작은 실습

학습용 Vue 앱을 빌드해보자.

```bash
npm run build
npm run preview
```

확인할 것:

- `dist` 폴더가 생겼는가
- preview 주소에서 화면이 보이는가
- 주요 라우트를 직접 입력해도 동작하는가
- 개발 서버와 다른 콘솔 에러가 없는가

## 이번 장 요약

- 개발 서버는 개발용, 운영 배포는 빌드 결과를 사용한다.
- `npm run build`는 `dist` 폴더를 만든다.
- `npm run preview`로 빌드 결과를 로컬에서 확인한다.
- SPA 라우터는 새로고침 fallback 설정이 중요하다.
- 배포 환경 변수와 base 경로를 확인해야 한다.
