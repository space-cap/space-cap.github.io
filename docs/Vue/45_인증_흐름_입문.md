# 인증 흐름 입문

## 이번 장에서 배울 것

인증은 사용자가 누구인지 확인하는 과정이다. Vue 앱에서는 로그인 요청, 로그인 상태 저장, 보호된 페이지 접근 제어를 함께 다루게 된다.

이번 장에서는 초보자가 이해할 수 있는 기본 인증 흐름을 정리한다.

---

## 기본 흐름

일반적인 로그인 흐름은 다음과 같다.

```text
사용자 로그인 폼 입력
  ↓
서버에 로그인 요청
  ↓
서버가 토큰 또는 세션 발급
  ↓
프론트엔드가 로그인 상태 저장
  ↓
보호된 API 요청 또는 페이지 접근
```

프로젝트마다 세부 구현은 다르지만 큰 흐름은 비슷하다.

---

## 인증과 인가

두 용어를 구분하자.

| 용어 | 의미 |
| --- | --- |
| 인증 | 사용자가 누구인지 확인 |
| 인가 | 사용자가 어떤 일을 할 수 있는지 확인 |

로그인은 인증이고, 관리자 페이지 접근 가능 여부는 인가에 가깝다.

---

## 로그인 API 호출 예제

```js
export async function login(email, password) {
  const response = await fetch('/api/login', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({ email, password })
  })

  if (!response.ok) {
    throw new Error('로그인에 실패했습니다.')
  }

  return await response.json()
}
```

응답 예:

```json
{
  "accessToken": "token-value",
  "user": {
    "id": 1,
    "name": "Kim",
    "role": "admin"
  }
}
```

## Auth Store 만들기

Pinia를 사용하면 로그인 상태를 관리하기 쉽다.

```js
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'
import { login } from '../api/auth'

export const useAuthStore = defineStore('auth', () => {
  const accessToken = ref(localStorage.getItem('accessToken'))
  const user = ref(null)

  const isLoggedIn = computed(() => Boolean(accessToken.value))

  async function signIn(email, password) {
    const result = await login(email, password)

    accessToken.value = result.accessToken
    user.value = result.user
    localStorage.setItem('accessToken', result.accessToken)
  }

  function signOut() {
    accessToken.value = null
    user.value = null
    localStorage.removeItem('accessToken')
  }

  return {
    accessToken,
    user,
    isLoggedIn,
    signIn,
    signOut
  }
})
```

## 토큰 저장 주의점

예제에서는 이해를 위해 `localStorage`를 사용했다. 하지만 토큰 저장은 보안과 밀접하다.

| 저장 위치 | 특징 |
| --- | --- |
| 메모리 | 새로고침 시 사라짐, XSS 노출 위험 감소 |
| localStorage | 사용 편함, XSS에 취약 |
| httpOnly cookie | JavaScript에서 접근 불가, 서버 설정 필요 |

실무에서는 보안 요구사항에 따라 백엔드와 함께 저장 전략을 정해야 한다. 초보 단계에서는 `localStorage`가 편하지만, 민감한 서비스에서는 신중해야 한다.

---

## Authorization 헤더

토큰이 필요한 API 요청에는 보통 Authorization 헤더를 붙인다.

```js
export async function fetchMe(token) {
  const response = await fetch('/api/me', {
    headers: {
      Authorization: `Bearer ${token}`
    }
  })

  if (!response.ok) {
    throw new Error('사용자 정보를 불러오지 못했습니다.')
  }

  return await response.json()
}
```

## 보호된 라우트

라우트 meta에 인증 필요 여부를 표시한다.

```js
{
  path: '/mypage',
  name: 'mypage',
  component: () => import('../views/MyPageView.vue'),
  meta: {
    requiresAuth: true
  }
}
```

라우터 가드:

```js
router.beforeEach((to) => {
  const auth = useAuthStore()

  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return {
      name: 'login',
      query: { redirect: to.fullPath }
    }
  }
})
```

Pinia를 라우터 가드에서 사용할 때는 앱에 Pinia가 먼저 설치되어 있어야 한다.

## 로그인 후 원래 페이지로 이동

로그인 페이지:

```js
const router = useRouter()
const route = useRoute()
const auth = useAuthStore()

async function submit() {
  await auth.signIn(email.value, password.value)

  router.push(route.query.redirect || '/')
}
```

보호된 페이지로 가려던 사용자를 로그인 후 원래 페이지로 돌려보낼 수 있다.

## 권한 처리

관리자만 접근 가능한 페이지는 role을 확인할 수 있다.

```js
{
  path: '/admin',
  name: 'admin',
  component: () => import('../views/AdminView.vue'),
  meta: {
    requiresAuth: true,
    roles: ['admin']
  }
}
```

```js
router.beforeEach((to) => {
  const auth = useAuthStore()

  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return { name: 'login' }
  }

  if (to.meta.roles && !to.meta.roles.includes(auth.user?.role)) {
    return { name: 'forbidden' }
  }
})
```

프론트엔드 권한 검사는 UX와 화면 제어용이다. 실제 보안은 서버 API에서도 반드시 검증해야 한다.

## 자주 하는 실수

### 프론트엔드 라우터 가드만 믿음

사용자는 브라우저 코드를 조작할 수 있다. 서버에서도 권한을 검사해야 한다.

### localStorage 보안 위험을 모름

XSS가 발생하면 localStorage의 토큰이 탈취될 수 있다. 실무에서는 저장 전략을 신중히 정한다.

### 로그아웃 시 상태만 지우고 저장소를 안 지움

`localStorage.removeItem('accessToken')` 같은 정리도 함께 해야 한다.

---

## 작은 실습

인증 흐름을 간단히 만들어보자.

- `auth` Pinia store 생성
- `isLoggedIn` computed 작성
- 로그인 시 임시 토큰 저장
- 로그아웃 시 토큰 제거
- `/mypage` 라우트에 `requiresAuth` meta 추가
- 로그인하지 않으면 `/login`으로 이동
