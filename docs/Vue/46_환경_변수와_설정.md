# 환경 변수와 설정

## 이번 장에서 배울 것

환경 변수는 개발, 테스트, 운영 환경마다 달라지는 값을 코드 밖에서 관리하는 방법이다.

예:

- API 서버 주소
- 앱 이름
- 기능 플래그
- 배포 경로

Vite 기반 Vue 프로젝트에서는 `import.meta.env`로 환경 변수를 읽는다.

---

## .env 파일

프로젝트 루트에 `.env` 파일을 만들 수 있다.

```text
VITE_APP_NAME=Vue Study
VITE_API_BASE_URL=https://api.example.com
```

Vite에서 클라이언트 코드에 노출할 환경 변수는 반드시 `VITE_` 접두사로 시작해야 한다.

---

## 환경 변수 읽기

```js
const appName = import.meta.env.VITE_APP_NAME
const apiBaseUrl = import.meta.env.VITE_API_BASE_URL
```

템플릿에서 사용하려면 script에서 변수로 꺼낸다.

```vue
<script setup>
const appName = import.meta.env.VITE_APP_NAME
</script>

<template>
  <h1>{{ appName }}</h1>
</template>
```

---

## VITE_ 접두사가 필요한 이유

브라우저에서 실행되는 Vue 코드는 사용자에게 전달된다. 따라서 모든 환경 변수를 클라이언트에 노출하면 위험하다.

Vite는 실수로 민감한 값을 노출하지 않도록 `VITE_`로 시작하는 값만 클라이언트 코드에서 접근할 수 있게 한다.

```text
VITE_API_BASE_URL=https://api.example.com
SECRET_KEY=server-secret
```

클라이언트에서 접근 가능:

```js
import.meta.env.VITE_API_BASE_URL
```

접근하면 안 되는 값:

```js
import.meta.env.SECRET_KEY
```

---

## 환경별 파일

환경별로 파일을 나눌 수 있다.

```text
.env
.env.development
.env.production
.env.local
```

| 파일 | 용도 |
| --- | --- |
| `.env` | 모든 모드에 공통 |
| `.env.development` | 개발 모드 |
| `.env.production` | 운영 빌드 |
| `.env.local` | 로컬 개인 설정, Git 제외 권장 |

예:

`.env.development`

```text
VITE_API_BASE_URL=http://localhost:3000
```

`.env.production`

```text
VITE_API_BASE_URL=https://api.example.com
```

---

## 내장 환경 변수

Vite는 몇 가지 내장 값을 제공한다.

```js
console.log(import.meta.env.MODE)
console.log(import.meta.env.DEV)
console.log(import.meta.env.PROD)
console.log(import.meta.env.BASE_URL)
```

| 값 | 의미 |
| --- | --- |
| `MODE` | 현재 모드 |
| `DEV` | 개발 서버 여부 |
| `PROD` | 운영 빌드 여부 |
| `BASE_URL` | 앱 base 경로 |

---

## API 설정 파일 만들기

환경 변수를 여러 곳에서 직접 읽기보다 설정 파일로 모아두면 좋다.

`src/config/index.js`

```js
export const config = {
  appName: import.meta.env.VITE_APP_NAME || 'Vue App',
  apiBaseUrl: import.meta.env.VITE_API_BASE_URL || ''
}
```

사용:

```js
import { config } from '../config'

const response = await fetch(`${config.apiBaseUrl}/posts`)
```

## .env 파일 수정 후 재시작

환경 변수 파일을 수정했다면 개발 서버를 재시작해야 반영되는 경우가 많다.

```bash
Ctrl + C
npm run dev
```

값이 이상하면 서버 재시작을 먼저 확인하자.

---

## 민감 정보 주의

Vue 앱에 들어간 환경 변수는 최종적으로 브라우저에 전달될 수 있다. 따라서 다음 값을 넣으면 안 된다.

- DB 비밀번호
- 서버 시크릿 키
- 비공개 API 키
- 관리자 토큰

클라이언트에서 쓰는 환경 변수는 "사용자에게 보여도 되는 값"만 넣는다.

---

## 자주 하는 실수

### VITE_ 접두사를 빼먹음

```text
API_BASE_URL=https://api.example.com
```

클라이언트에서 읽으려면 다음처럼 작성한다.

```text
VITE_API_BASE_URL=https://api.example.com
```

### .env를 수정하고 서버를 재시작하지 않음

개발 서버를 다시 실행한다.

### 클라이언트 환경 변수에 비밀값을 넣음

브라우저 앱에 들어가는 값은 숨길 수 없다고 생각하자.

---

## 작은 실습

환경 변수를 설정해보자.

- `.env.development`에 `VITE_APP_NAME`, `VITE_API_BASE_URL` 추가
- `src/config/index.js`에서 읽기
- `App.vue`에서 앱 이름 출력
- API 함수에서 base URL 사용

---

## 이번 장 요약

- Vite 환경 변수는 `import.meta.env`로 읽는다.
- 클라이언트에서 사용할 값은 `VITE_` 접두사가 필요하다.
- 환경별로 `.env.development`, `.env.production` 파일을 둘 수 있다.
- 민감 정보는 클라이언트 환경 변수에 넣으면 안 된다.
- `.env` 수정 후 개발 서버 재시작이 필요할 수 있다.
