# 폼 검증과 사용자 입력 처리

## 이번 장에서 배울 것

폼은 사용자 입력을 받는 중요한 UI다. 좋은 폼은 잘못된 입력을 막고, 무엇을 고쳐야 하는지 명확히 알려준다.

이번 장에서는 Vue에서 기본적인 폼 검증을 직접 구현하는 방법을 배운다.

---

## 기본 상태 설계

회원가입 폼을 예로 들어보자.

```vue
<script setup>
import { reactive } from 'vue'

const form = reactive({
  email: '',
  password: '',
  name: ''
})

const errors = reactive({
  email: '',
  password: '',
  name: ''
})
</script>
```

`form`은 입력 값, `errors`는 에러 메시지를 담는다.

---

## 검증 함수 만들기

```js
function validate() {
  errors.email = ''
  errors.password = ''
  errors.name = ''

  if (!form.email.trim()) {
    errors.email = '이메일을 입력하세요.'
  } else if (!form.email.includes('@')) {
    errors.email = '올바른 이메일 형식이 아닙니다.'
  }

  if (!form.password) {
    errors.password = '비밀번호를 입력하세요.'
  } else if (form.password.length < 8) {
    errors.password = '비밀번호는 8자 이상이어야 합니다.'
  }

  if (!form.name.trim()) {
    errors.name = '이름을 입력하세요.'
  }

  return !errors.email && !errors.password && !errors.name
}
```

검증 함수는 에러 메시지를 채우고, 전체 통과 여부를 반환한다.

---

## 제출 처리

```js
async function submitForm() {
  if (!validate()) {
    return
  }

  console.log('제출 가능:', form)
}
```

템플릿에서는 `@submit.prevent`를 사용한다.

```html
<form @submit.prevent="submitForm">
  ...
</form>
```

## 전체 예제

```vue
<script setup>
import { reactive } from 'vue'

const form = reactive({
  email: '',
  password: '',
  name: ''
})

const errors = reactive({
  email: '',
  password: '',
  name: ''
})

function validate() {
  errors.email = ''
  errors.password = ''
  errors.name = ''

  if (!form.email.trim()) {
    errors.email = '이메일을 입력하세요.'
  } else if (!form.email.includes('@')) {
    errors.email = '올바른 이메일 형식이 아닙니다.'
  }

  if (!form.password) {
    errors.password = '비밀번호를 입력하세요.'
  } else if (form.password.length < 8) {
    errors.password = '비밀번호는 8자 이상이어야 합니다.'
  }

  if (!form.name.trim()) {
    errors.name = '이름을 입력하세요.'
  }

  return !errors.email && !errors.password && !errors.name
}

function submitForm() {
  if (!validate()) {
    return
  }

  alert('가입 요청을 보낼 수 있습니다.')
}
</script>

<template>
  <form @submit.prevent="submitForm" novalidate>
    <label>
      이메일
      <input v-model.trim="form.email" type="email">
    </label>
    <p v-if="errors.email">{{ errors.email }}</p>

    <label>
      비밀번호
      <input v-model="form.password" type="password">
    </label>
    <p v-if="errors.password">{{ errors.password }}</p>

    <label>
      이름
      <input v-model.trim="form.name">
    </label>
    <p v-if="errors.name">{{ errors.name }}</p>

    <button type="submit">가입</button>
  </form>
</template>
```

`novalidate`는 브라우저 기본 검증 UI를 끄고 직접 만든 검증 흐름을 확인하기 위해 사용한다.

## 실시간 검증

입력할 때마다 검증하고 싶다면 `watch`를 사용할 수 있다.

```js
watch(
  () => form.email,
  () => {
    if (!form.email.includes('@')) {
      errors.email = '올바른 이메일 형식이 아닙니다.'
    } else {
      errors.email = ''
    }
  }
)
```

다만 처음부터 모든 입력에 실시간 에러를 띄우면 사용자가 부담을 느낄 수 있다. 보통은 입력 후 blur 시점이나 제출 시점에 검증한다.

---

## touched 상태

사용자가 한 번이라도 건드린 필드에만 에러를 보여주고 싶을 수 있다.

```js
const touched = reactive({
  email: false,
  password: false
})
```

```html
<input
  v-model.trim="form.email"
  @blur="touched.email = true"
>
<p v-if="touched.email && errors.email">{{ errors.email }}</p>
```

## 서버 검증

프론트엔드 검증은 사용자 경험을 좋게 만들지만, 보안을 책임지지는 않는다. 서버에서도 반드시 검증해야 한다.

예를 들어 이메일 중복 여부, 비밀번호 정책, 권한 검사는 서버 기준이 최종이다.

---

## 라이브러리를 써야 할까?

큰 프로젝트에서는 VeeValidate, Zod, Yup 같은 도구를 사용하기도 한다. 하지만 초보자는 먼저 직접 검증 함수를 만들어보는 것이 좋다.

직접 만들어보면 폼 검증 라이브러리가 어떤 문제를 해결하는지 더 잘 이해할 수 있다.

---

## 자주 하는 실수

### 에러를 초기화하지 않음

검증 시작 전에 기존 에러를 지워야 이전 에러가 남지 않는다.

### 프론트엔드 검증만 믿음

사용자는 브라우저 코드를 우회할 수 있다. 서버 검증은 필수다.

### 제출 중 버튼을 계속 누를 수 있음

API 요청 중에는 `submitting` 상태로 버튼을 비활성화하는 것이 좋다.
