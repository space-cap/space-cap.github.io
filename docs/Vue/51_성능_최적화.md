# 성능 최적화

## 이번 장에서 배울 것

성능 최적화는 앱이 더 빠르게 뜨고, 더 부드럽게 동작하도록 만드는 작업이다.

초보 단계에서 복잡한 최적화 기법을 모두 알 필요는 없다. 먼저 측정하고, 큰 문제부터 해결하는 습관이 중요하다.

---

## 성능을 나누어 보기

웹 앱 성능은 크게 두 방향으로 볼 수 있다.

| 구분 | 의미 |
| --- | --- |
| 로딩 성능 | 처음 화면이 얼마나 빨리 뜨는가 |
| 업데이트 성능 | 사용 중 화면이 얼마나 부드럽게 반응하는가 |

Vue 앱에서는 번들 크기, 코드 분할, 렌더링 비용, 불필요한 반응성 등을 함께 고려한다.

---

## 먼저 측정하기

감으로 최적화하지 말고 도구로 확인한다.

사용할 수 있는 도구:

- Chrome DevTools Performance
- Chrome DevTools Network
- Lighthouse
- Vue DevTools
- Vite build 결과

어떤 페이지가 느린지, 어떤 요청이 큰지, 어떤 컴포넌트가 자주 업데이트되는지 확인한 뒤 개선한다.

---

## 프로덕션 빌드 사용

개발 서버는 개발 편의를 위해 만들어진 모드다. 실제 배포 성능을 확인하려면 프로덕션 빌드를 사용한다.

```bash
npm run build
npm run preview
```

개발 모드와 운영 빌드는 성능 특성이 다르다.

---

## 코드 분할

라우트 페이지는 동적 import로 지연 로딩할 수 있다.

```js
{
  path: '/admin',
  component: () => import('../views/AdminView.vue')
}
```

처음 화면에 필요 없는 코드를 나중에 불러오면 초기 로딩을 줄일 수 있다.

---

## 무거운 컴포넌트 지연 로딩

차트, 지도, 에디터 같은 무거운 컴포넌트는 비동기 컴포넌트로 분리할 수 있다.

```js
import { defineAsyncComponent } from 'vue'

const ChartPanel = defineAsyncComponent(() =>
  import('./components/ChartPanel.vue')
)
```

사용자가 실제로 필요로 할 때 로드하는 것이 좋다.

---

## computed로 불필요한 계산 줄이기

템플릿에 복잡한 계산을 직접 넣으면 렌더링 때마다 읽기 어렵고 비용도 커질 수 있다.

```html
{{ items.filter((item) => item.active).length }}
```

`computed`로 분리한다.

```js
const activeCount = computed(() => {
  return items.value.filter((item) => item.active).length
})
```

---

## v-for key 안정화

목록 렌더링에서는 고유한 `key`를 사용한다.

```html
<li v-for="item in items" :key="item.id">
  {{ item.name }}
</li>
```

index를 key로 쓰면 항목 재정렬이나 삭제 시 DOM 재사용이 어색해질 수 있다.

---

## v-once와 v-memo

정적인 내용은 `v-once`로 한 번만 렌더링하게 할 수 있다.

```html
<h1 v-once>{{ title }}</h1>
```

`v-memo`는 특정 의존성이 바뀌지 않으면 하위 트리 업데이트를 건너뛸 수 있다.

```html
<div v-for="item in list" :key="item.id" v-memo="[item.id === selected]">
  {{ item.name }}
</div>
```

이 기능들은 성능 문제가 확인된 뒤 신중히 사용한다. 처음부터 남발할 필요는 없다.

---

## 불필요한 반응성 줄이기

화면에 반응할 필요가 없는 큰 데이터는 굳이 깊은 반응형으로 만들지 않아도 된다.

예:

- 수정하지 않는 대형 설정 객체
- 외부 라이브러리 인스턴스
- 화면 갱신과 무관한 캐시 데이터

필요에 따라 일반 변수, `shallowRef`, `markRaw` 같은 API를 검토할 수 있다. 초보 단계에서는 "모든 것을 ref/reactive로 감싸지 않아도 된다"는 감각만 잡아도 좋다.

---

## 이미지 최적화

Vue만의 문제는 아니지만 이미지가 로딩 성능에 큰 영향을 준다.

체크할 것:

- 실제 표시 크기에 맞는 이미지 사용
- WebP/AVIF 같은 현대 포맷 검토
- lazy loading 적용
- 불필요하게 큰 배경 이미지 피하기

```html
<img src="/thumbnail.webp" alt="상품 이미지" loading="lazy">
```

---

## 자주 하는 실수

### 측정 없이 최적화함

느린 원인을 확인하지 않고 복잡한 최적화를 하면 코드만 어려워질 수 있다.

### 모든 컴포넌트를 비동기로 만듦

초기 화면에 꼭 필요한 컴포넌트는 일반 import가 더 단순하다.

### computed를 상태 변경용으로 사용함

`computed`는 계산된 값을 위한 것이다. 상태 변경은 함수에서 처리한다.
