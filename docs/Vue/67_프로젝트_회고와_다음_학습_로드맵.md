## Vue 기본기 체크리스트

다음 질문에 스스로 답할 수 있는지 확인해보자.

- `ref`와 `reactive`의 차이를 설명할 수 있는가?
- JavaScript 코드에서 `ref` 값을 바꿀 때 `.value`를 쓰는 이유를 아는가?
- `computed`와 `watch`의 차이를 설명할 수 있는가?
- `v-if`와 `v-show`의 차이를 아는가?
- `v-for`에서 `key`가 왜 중요한지 설명할 수 있는가?
- Props와 Emit으로 부모-자식 통신을 만들 수 있는가?
- Slot이 Props와 어떻게 다른지 아는가?
- Composable이 컴포넌트와 어떻게 다른지 설명할 수 있는가?

막히는 항목이 있다면 해당 장으로 돌아가 예제를 다시 작성해보자.

## 코드 회고 질문

프로젝트를 만든 뒤에는 다음 질문을 던져보자.

- 컴포넌트가 너무 많은 일을 하고 있지는 않은가?
- 반복되는 로직을 Composable로 분리할 수 있는가?
- Props와 Emit 이름이 명확한가?
- 전역 상태와 지역 상태를 적절히 나누었는가?
- 에러 상태가 사용자에게 보이는가?
- API 실패를 고려했는가?
- 접근성 있는 HTML을 사용했는가?
- 테스트하기 어려운 구조는 아닌가?

회고는 잘못을 찾는 시간이 아니라 다음 코드를 더 쉽게 만들기 위한 시간이다.

## 다음 학습 4: Nuxt

Vue 기본기를 익혔다면 Nuxt를 배울 수 있다.

Nuxt가 필요한 경우:

- SEO가 중요한 사이트
- 블로그나 문서 사이트
- SSR/SSG가 필요한 서비스
- 파일 기반 라우팅을 사용하고 싶을 때
- Vue 기반 풀스택 앱을 만들고 싶을 때

Nuxt를 배우기 전에 Vue Router, 컴포넌트, Composition API를 이해하고 있으면 훨씬 수월하다.

## 학습 루틴 제안

Vue를 꾸준히 익히는 루틴:

1. 공식 문서 한 장 읽기
2. 예제를 직접 타이핑하기
3. 예제에 작은 기능 하나 추가하기
4. 컴포넌트로 분리하기
5. 에러와 빈 상태 추가하기
6. README에 배운 점 정리하기

눈으로 읽는 것보다 직접 바꾸고 망가뜨려보는 시간이 훨씬 오래 남는다.

## 마지막 체크리스트

- 새 Vue 프로젝트를 혼자 만들 수 있다.
- 컴포넌트를 적절히 나눌 수 있다.
- Props와 Emit을 설명할 수 있다.
- Router로 페이지를 만들 수 있다.
- Pinia로 전역 상태를 관리할 수 있다.
- API 통신의 로딩/에러 상태를 처리할 수 있다.
- 빌드와 배포 기본 흐름을 안다.
- TypeScript를 어디에 적용하면 좋은지 안다.
- 다음에 무엇을 공부해야 할지 알고 있다.

---

## 마무리

Vue 학습의 목표는 문법을 외우는 것이 아니라, 사용자에게 필요한 화면을 안정적으로 만드는 것이다. 작은 앱을 여러 번 만들고, 매번 구조를 조금씩 개선해보자.

이제 이 문서 묶음을 기준으로 다시 처음부터 따라가며 실습하거나, 원하는 장으로 돌아가 필요한 부분을 반복하면 된다.
