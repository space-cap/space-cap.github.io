# E2E 테스트 입문

## 이번 장에서 배울 것

E2E 테스트는 End-to-End 테스트의 줄임말이다. 사용자가 실제 브라우저에서 앱을 사용하는 흐름을 자동으로 검증한다.

예를 들어 다음 흐름을 테스트할 수 있다.

- 로그인한다.
- 게시글 목록으로 이동한다.
- 새 게시글을 작성한다.
- 작성한 게시글이 목록에 보인다.

---

## E2E 테스트가 필요한 이유

단위 테스트와 컴포넌트 테스트는 작은 범위를 빠르게 확인한다. 하지만 실제 사용자는 여러 페이지와 기능을 이어서 사용한다.

E2E 테스트는 다음 문제를 찾는 데 도움이 된다.

- 라우터 이동 문제
- 폼 제출 문제
- 실제 브라우저 이벤트 문제
- API와 화면 연결 문제
- 빌드된 앱에서만 나타나는 문제

---

## 도구 선택

Vue 공식 문서는 E2E 도구로 Playwright, Cypress 등을 소개한다. 이 문서에서는 Playwright를 기준으로 설명한다.

Playwright는 Chromium, Firefox, WebKit 같은 여러 브라우저에서 테스트할 수 있고, 현대적인 E2E 테스트에 많이 사용된다.

---

## 설치

```bash
npm init playwright@latest
```

질문에 답하면 기본 설정과 예제 테스트가 생성된다.

일반적으로 다음과 같은 폴더가 생긴다.

```text
tests/
└─ example.spec.js
playwright.config.js
```

---

## package.json 스크립트

보통 다음 스크립트를 추가한다.

```json
{
  "scripts": {
    "test:e2e": "playwright test"
  }
}
```

실행:

```bash
npm run test:e2e
```

---

## 첫 테스트

`tests/home.spec.js`

```js
import { expect, test } from '@playwright/test'

test('홈 화면 제목이 보인다', async ({ page }) => {
  await page.goto('/')

  await expect(page.getByRole('heading', { name: 'Vue App' })).toBeVisible()
})
```

`page.goto('/')`는 브라우저를 해당 경로로 이동시킨다.

`getByRole`은 접근성 역할을 기준으로 요소를 찾는다. 가능하면 CSS 선택자보다 사용자가 인식하는 이름과 역할을 기준으로 찾는 것이 좋다.

## 개발 서버와 함께 실행하기

`playwright.config.js`에서 테스트 전에 개발 서버 또는 preview 서버를 실행할 수 있다.

```js
export default {
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:5173',
    reuseExistingServer: true
  },
  use: {
    baseURL: 'http://localhost:5173'
  }
}
```

운영 빌드와 더 비슷하게 확인하고 싶다면 `npm run build` 후 preview 서버를 사용할 수도 있다.

## 로그인 흐름 테스트 예제

```js
import { expect, test } from '@playwright/test'

test('로그인 후 마이페이지로 이동한다', async ({ page }) => {
  await page.goto('/login')

  await page.getByLabel('이메일').fill('user@example.com')
  await page.getByLabel('비밀번호').fill('password123')
  await page.getByRole('button', { name: '로그인' }).click()

  await expect(page).toHaveURL(/\/mypage/)
  await expect(page.getByRole('heading', { name: '마이페이지' })).toBeVisible()
})
```

이 테스트는 사용자가 실제로 하는 행동과 비슷하게 작성한다.

## 테스트용 데이터

E2E 테스트는 데이터 준비가 중요하다.

방법:

- 테스트 전용 API 서버 사용
- 테스트 DB 사용
- 네트워크 요청 mock
- 로그인 상태를 미리 저장
- 테스트 후 데이터 정리

처음에는 mock API나 테스트 전용 계정을 사용하는 방식이 단순하다.

---

## 좋은 E2E 테스트 기준

좋은 E2E 테스트는 사용자의 핵심 흐름을 검증한다.

우선순위:

- 로그인
- 회원가입
- 결제 또는 주문
- 게시글 작성
- 검색
- 권한이 필요한 페이지 접근

모든 작은 버튼을 E2E로 테스트하면 느리고 관리가 어려워진다. 작은 로직은 단위/컴포넌트 테스트로 확인하고, E2E는 중요한 사용자 여정을 맡긴다.

---

## 자주 하는 실수

### CSS class에 너무 의존함

스타일 변경만으로 테스트가 깨질 수 있다. 가능하면 role, label, text를 기준으로 찾는다.

### 테스트 간 데이터가 서로 영향을 줌

각 테스트는 독립적으로 실행될 수 있어야 한다.

### E2E로 모든 것을 테스트하려 함

E2E는 강력하지만 느리고 복잡하다. 핵심 흐름 위주로 작성한다.

## 작은 실습

Todo 앱 E2E 테스트를 작성해보자.

- 홈으로 이동한다.
- 입력 칸에 할 일을 입력한다.
- 추가 버튼을 클릭한다.
- 새 Todo가 목록에 보인다.
- 삭제 버튼을 클릭한다.
- Todo가 목록에서 사라진다.
