# 접근성 A11y

## 이번 장에서 배울 것

접근성은 더 많은 사람이 웹 앱을 사용할 수 있게 만드는 기본 품질이다. 키보드 사용자, 스크린 리더 사용자, 저시력 사용자, 일시적으로 마우스를 쓰기 어려운 사용자 모두를 고려한다.

A11y는 Accessibility의 줄임말이다. A와 y 사이에 11글자가 있어서 A11y라고 부른다.

---

## 접근성은 선택 사항이 아니다

접근성은 특별한 사람만을 위한 기능이 아니다. 좋은 접근성은 모두에게 도움이 된다.

예:

- 명확한 label은 모든 사용자가 폼을 이해하는 데 도움된다.
- 키보드 조작은 마우스가 없는 환경에서도 필요하다.
- 충분한 색상 대비는 밝은 야외에서도 읽기 좋다.
- 시맨틱 HTML은 검색 엔진과 보조 기술 모두에 도움된다.

---

## 시맨틱 HTML 사용하기

가능하면 의미에 맞는 HTML 요소를 사용한다.

```html
<button type="button">저장</button>
```

클릭 가능한 div보다 실제 button이 낫다.

```html
<!-- 피하기 -->
<div @click="save">저장</div>
```

button은 기본적으로 키보드 접근성과 역할 정보를 가진다.

---

## label 연결

입력 요소에는 label을 연결한다.

```vue
<template>
  <label for="email">이메일</label>
  <input id="email" v-model="email" type="email">
</template>
```

또는 label 안에 input을 넣을 수 있다.

```html
<label>
  이메일
  <input v-model="email" type="email">
</label>
```

---

## 이미지 alt

이미지에는 목적에 맞는 `alt`를 작성한다.

```html
<img src="/profile.jpg" alt="김민수 프로필 사진">
```

장식용 이미지는 빈 alt를 사용할 수 있다.

```html
<img src="/divider.svg" alt="">
```

이미지가 정보를 전달한다면 alt는 반드시 의미 있게 작성한다.

---

## 키보드 접근성

사용자는 Tab, Enter, Space, Escape 같은 키로 앱을 사용할 수 있어야 한다.

체크할 것:

- 버튼과 링크가 Tab으로 이동 가능한가
- 현재 포커스 위치가 눈에 보이는가
- 모달이 열렸을 때 포커스가 모달 안에 있는가
- Escape로 닫을 수 있는가
- 키보드만으로 주요 기능을 사용할 수 있는가

---

## 포커스 스타일

포커스 스타일을 없애면 키보드 사용자가 현재 위치를 알 수 없다.

```css
button:focus-visible,
a:focus-visible,
input:focus-visible {
  outline: 2px solid #2563eb;
  outline-offset: 2px;
}
```

디자인에 맞게 바꿀 수는 있지만, 완전히 없애면 안 된다.

---

## aria는 보조 수단

ARIA 속성은 HTML 의미를 보완한다. 하지만 올바른 HTML 요소를 쓰는 것이 먼저다.

예를 들어 버튼은 이렇게 쓰는 것이 좋다.

```html
<button type="button">메뉴 열기</button>
```

아래처럼 div에 role을 붙이는 것은 최후의 수단에 가깝다.

```html
<div role="button" tabindex="0">메뉴 열기</div>
```

가능하면 native HTML 요소를 사용하자.

---

## 모달 접근성

모달은 접근성 고려가 많다.

기본 체크리스트:

- `role="dialog"` 또는 적절한 dialog 구조
- `aria-modal="true"`
- 모달 제목 연결
- 열릴 때 포커스 이동
- 닫힐 때 원래 버튼으로 포커스 복귀
- Escape로 닫기
- 배경 콘텐츠에 접근하지 않도록 처리

Teleport는 DOM 위치 문제를 해결해주지만, 접근성을 자동으로 완성해주지는 않는다.

---

## 색상 대비

텍스트와 배경의 대비가 충분해야 한다.

나쁜 예:

```css
color: #aaa;
background: #fff;
```

회색 텍스트를 사용할 때는 실제 대비를 확인한다. 특히 에러 메시지, 비활성 상태, 작은 글자는 더 주의한다.

---

## Vue에서 자주 하는 접근성 실수

### v-if로 에러 메시지를 보여주지만 입력과 연결하지 않음

에러 메시지는 시각적으로만 보이는 것이 아니라 입력과 연결될 수 있어야 한다.

```html
<input
  id="email"
  aria-describedby="email-error"
  :aria-invalid="Boolean(error)"
>
<p v-if="error" id="email-error">{{ error }}</p>
```

### Router 이동 후 포커스 관리 안 함

SPA는 페이지 전체 새로고침이 없으므로 라우트 이동 후 포커스와 제목 관리가 필요할 수 있다.

### 아이콘 버튼에 이름이 없음

아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.

```html
<button type="button" aria-label="검색">
  <SearchIcon />
</button>
```

---

## 작은 실습

로그인 폼 접근성을 점검해보자.

- 이메일 input에 label 연결
- 비밀번호 input에 label 연결
- 에러 메시지를 `aria-describedby`로 연결
- 제출 버튼을 button 요소로 작성
- Tab 키만으로 폼을 사용할 수 있는지 확인

## 이번 장 요약

- 접근성은 모든 사용자를 위한 기본 품질이다.
- 시맨틱 HTML을 먼저 사용한다.
- input에는 label을 연결한다.
- 키보드만으로 주요 기능을 사용할 수 있어야 한다.
- ARIA는 HTML 의미를 보완하는 도구다.
- 모달, 라우터 이동, 아이콘 버튼은 특히 주의한다.
