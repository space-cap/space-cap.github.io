# 보안 기초

## 이번 장에서 배울 것

프론트엔드 보안은 사용자의 입력과 외부 데이터를 어떻게 다루는지에서 시작한다. Vue는 기본적으로 텍스트와 속성 바인딩을 안전하게 처리해주지만, 개발자가 위험한 코드를 작성하면 보안 문제가 생길 수 있다.

이번 장에서는 Vue 앱에서 초보자가 꼭 알아야 할 보안 원칙을 정리한다.

---

## 첫 번째 원칙: 신뢰할 수 없는 템플릿을 사용하지 않기

사용자가 입력한 문자열을 Vue 템플릿으로 컴파일하면 안 된다.

```js
// 절대 피해야 하는 예
createApp({
  template: userProvidedTemplate
})
```

Vue 템플릿은 JavaScript로 컴파일되어 실행된다. 신뢰할 수 없는 내용을 템플릿으로 쓰는 것은 임의 코드 실행 위험으로 이어질 수 있다.

---

## Vue가 기본적으로 보호해주는 것

보간법은 HTML을 그대로 실행하지 않고 텍스트로 표시한다.

```vue
<template>
  <p>{{ userInput }}</p>
</template>
```

`userInput`에 다음 값이 들어와도 스크립트가 실행되지 않고 텍스트로 표시된다.

```html
<script>alert('xss')</script>
```

속성 바인딩도 브라우저 API를 통해 안전하게 처리된다.

```html
<div :title="userInput"></div>
```

하지만 이것이 모든 보안 문제를 자동으로 해결한다는 뜻은 아니다.

---

## v-html 주의

`v-html`은 문자열을 실제 HTML로 렌더링한다.

```html
<div v-html="content"></div>
```

사용자 입력이나 외부에서 받은 신뢰할 수 없는 값을 `v-html`에 넣으면 XSS 위험이 생긴다.

원칙:

- 사용자 입력에는 `v-html`을 사용하지 않는다.
- 꼭 필요하면 서버에서 검증하고 안전하게 정제한다.
- 가능한 경우 텍스트 보간법 `{{ }}`을 사용한다.

---

## URL 바인딩 주의

사용자 입력 URL을 그대로 링크에 넣으면 위험할 수 있다.

```html
<a :href="userProvidedUrl">링크</a>
```

예를 들어 `javascript:`로 시작하는 URL은 보안 문제가 될 수 있다. URL은 가능하면 서버에서 검증하고 저장하기 전에 정제해야 한다.

프론트엔드에서만 정제하는 것은 최종 방어선이 될 수 없다.

---

## style 바인딩 주의

사용자가 제공한 스타일을 그대로 적용하면 화면을 속이는 공격이 가능할 수 있다.

```html
<div :style="userProvidedStyle"></div>
```

사용자가 색상을 고르게 해야 한다면 허용할 속성만 제한한다.

```html
<div :style="{ color: safeColor }"></div>
```

CSS 전체를 사용자에게 맡기는 방식은 피한다.

---

## 인증 토큰 주의

토큰을 `localStorage`에 저장하는 예제는 이해하기 쉽지만 XSS에 취약하다.

보안 요구사항이 있는 서비스에서는 백엔드와 함께 다음을 검토한다.

- httpOnly cookie
- SameSite cookie
- CSRF 방어
- 토큰 만료와 갱신
- 로그아웃 시 서버 세션 무효화

프론트엔드 예제만 보고 모든 서비스에 같은 저장 방식을 적용하면 안 된다.

---

## 환경 변수에 비밀값 넣지 않기

Vite의 `VITE_` 환경 변수는 브라우저 코드에 포함될 수 있다.

넣으면 안 되는 값:

- DB 비밀번호
- 서버 비밀 키
- 관리자 토큰
- 비공개 API 키

클라이언트에 들어가는 값은 사용자가 볼 수 있다고 생각해야 한다.

---

## 서버 검증은 필수

프론트엔드 검증은 사용자 경험을 좋게 만들지만 보안을 보장하지 않는다.

반드시 서버에서 검증해야 하는 것:

- 로그인 정보
- 권한
- 결제 금액
- 게시글 작성 권한
- 파일 업로드 타입과 크기
- 입력 길이와 형식

사용자는 브라우저 코드를 바꿀 수 있다. 서버가 최종 판단을 해야 한다.

---

## 의존성 관리

라이브러리는 최신 보안 패치를 적용해야 한다.

```bash
npm audit
```

```bash
npm outdated
```

무작정 최신으로 올리기보다 변경 사항을 확인하고 테스트 후 업데이트한다.

---

## 자주 하는 실수

### v-html을 편한 출력 도구처럼 사용함

HTML이 정말 필요한지 먼저 생각한다. 대부분은 `{{ }}`로 충분하다.

### 프론트엔드 권한 체크만 믿음

라우터 가드와 버튼 숨김은 UX용이다. 서버 API에서 권한을 검증해야 한다.

### API 키를 환경 변수에 넣으면 숨겨진다고 생각함

클라이언트 번들에 포함된 값은 숨겨지지 않는다.

---

## 작은 실습

기존 코드에서 다음을 찾아보자.

- `v-html` 사용 위치
- 사용자 입력이 URL에 들어가는 위치
- 토큰 저장 위치
- `VITE_` 환경 변수에 민감한 값이 있는지
- 서버 검증이 필요한 프론트엔드 검증 코드

---

## 이번 장 요약

- 신뢰할 수 없는 문자열을 Vue 템플릿으로 사용하면 안 된다.
- Vue 보간법은 기본적으로 HTML을 텍스트로 이스케이프한다.
- `v-html`, URL 바인딩, style 바인딩은 특히 주의한다.
- 프론트엔드 검증과 라우터 가드는 보안을 완성하지 않는다.
- 민감 정보는 클라이언트 환경 변수에 넣지 않는다.
