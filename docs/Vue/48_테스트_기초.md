# 테스트 기초

## 이번 장에서 배울 것

테스트는 코드를 자동으로 확인하는 방법이다. 버튼을 눌렀을 때 값이 바뀌는지, props에 따라 화면이 바뀌는지, Composable 함수가 기대한 값을 반환하는지 확인할 수 있다.

Vue 공식 문서에서는 Vite 기반 프로젝트에 Vitest를 권장한다. 컴포넌트 테스트에는 Vue Test Utils를 함께 사용할 수 있다.

---

## 왜 테스트를 작성할까?

테스트는 다음 상황에서 특히 도움이 된다.

- 기존 기능이 망가지지 않았는지 확인
- 리팩터링할 때 자신감 확보
- 복잡한 조건을 코드로 문서화
- 반복 확인을 자동화
- 팀원이 변경한 코드의 영향 확인

테스트가 모든 버그를 막지는 못하지만, 중요한 기능이 조용히 깨지는 일을 줄여준다.

---

## 테스트 종류

| 종류 | 확인 대상 | 예 |
| --- | --- | --- |
| 단위 테스트 | 작은 함수, Composable | 가격 계산 함수 |
| 컴포넌트 테스트 | Vue 컴포넌트 동작 | 버튼 클릭 시 emit 발생 |
| E2E 테스트 | 실제 사용자 흐름 | 로그인 후 마이페이지 이동 |

처음에는 단위 테스트와 컴포넌트 테스트부터 시작하는 것이 좋다.

---

## Vitest 설치

프로젝트 생성 시 테스트 옵션을 선택하지 않았다면 직접 설치할 수 있다.

```bash
npm install -D vitest jsdom @vue/test-utils
```

`package.json`에 스크립트를 추가한다.

```json
{
  "scripts": {
    "test:unit": "vitest"
  }
}
```

테스트 실행:

```bash
npm run test:unit
```

## vite.config.js 설정

Vue 컴포넌트 테스트에서 DOM 환경이 필요하면 `jsdom`을 사용한다.

```js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  test: {
    environment: 'jsdom'
  },
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})
```

프로젝트 설정은 생성 옵션에 따라 다를 수 있다. 이미 테스트 설정이 있다면 기존 설정을 우선 따른다.

## 단위 테스트 예제

`src/utils/price.js`

```js
export function formatPrice(value) {
  return value.toLocaleString() + '원'
}
```

`src/utils/price.test.js`

```js
import { describe, expect, it } from 'vitest'
import { formatPrice } from './price'

describe('formatPrice', () => {
  it('숫자를 원화 문자열로 변환한다', () => {
    expect(formatPrice(1000)).toBe('1,000원')
  })
})
```

`describe`는 테스트 묶음, `it`은 하나의 테스트, `expect`는 기대값을 확인하는 함수다.

## 컴포넌트 테스트 예제

`CounterButton.vue`

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <button @click="count++">
    {{ count }}
  </button>
</template>
```

`CounterButton.test.js`

```js
import { mount } from '@vue/test-utils'
import { describe, expect, it } from 'vitest'
import CounterButton from './CounterButton.vue'

describe('CounterButton', () => {
  it('버튼을 클릭하면 숫자가 증가한다', async () => {
    const wrapper = mount(CounterButton)

    expect(wrapper.text()).toContain('0')

    await wrapper.find('button').trigger('click')

    expect(wrapper.text()).toContain('1')
  })
})
```

`mount`는 컴포넌트를 테스트 환경에 렌더링한다.

## Props 테스트

`UserCard.vue`

```vue
<script setup>
defineProps({
  name: {
    type: String,
    required: true
  }
})
</script>

<template>
  <article>
    <h2>{{ name }}</h2>
  </article>
</template>
```

테스트:

```js
import { mount } from '@vue/test-utils'
import { expect, it } from 'vitest'
import UserCard from './UserCard.vue'

it('name prop을 화면에 표시한다', () => {
  const wrapper = mount(UserCard, {
    props: {
      name: 'Kim'
    }
  })

  expect(wrapper.text()).toContain('Kim')
})
```

## Emit 테스트

```vue
<script setup>
const emit = defineEmits(['remove'])
</script>

<template>
  <button @click="emit('remove', 1)">삭제</button>
</template>
```

테스트:

```js
const wrapper = mount(RemoveButton)

await wrapper.find('button').trigger('click')

expect(wrapper.emitted('remove')).toEqual([[1]])
```

컴포넌트 테스트는 내부 구현보다 외부에서 보이는 결과에 집중한다. 화면에 무엇이 보이는지, 어떤 이벤트가 발생하는지, 어떤 사용자 동작에 어떻게 반응하는지를 확인한다.

## 무엇을 테스트할까?

처음에는 다음을 우선 테스트하자.

- 계산 로직이 있는 유틸 함수
- 여러 컴포넌트에서 재사용하는 Composable
- props에 따라 화면이 달라지는 컴포넌트
- 클릭, 입력, 제출 같은 사용자 행동
- emit 이벤트
- 중요한 폼 검증

스타일 색상 하나하나보다 사용자에게 의미 있는 동작을 테스트하는 것이 좋다.

## 자주 하는 실수

### 구현 세부사항을 테스트함

변수명이 무엇인지보다 사용자가 보는 결과와 컴포넌트의 공개 인터페이스를 확인한다.

### 비동기 업데이트에 await를 빼먹음

클릭이나 입력 후 DOM 업데이트가 필요하면 `await`를 사용한다.

```js
await wrapper.find('button').trigger('click')
```

### 테스트 이름이 모호함

`잘 동작한다`보다 `버튼을 클릭하면 숫자가 증가한다`처럼 구체적으로 쓴다.
