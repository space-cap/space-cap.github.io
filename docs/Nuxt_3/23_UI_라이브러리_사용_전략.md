# UI 라이브러리 사용 전략

## 이번 장에서 배울 것

- UI 라이브러리가 무엇인지
- 직접 만드는 UI와 라이브러리를 쓰는 UI의 차이
- Nuxt 프로젝트에서 UI 도구를 선택하는 기준
- 초보자가 조심해야 할 점

## UI 라이브러리란

UI 라이브러리는 버튼, 입력 폼, 모달, 탭, 드롭다운, 테이블 같은 화면 요소를 미리 만들어 제공하는 도구다.

직접 모든 UI를 만들 수도 있지만, 실무에서는 자주 쓰는 UI를 라이브러리로 가져와 개발 속도를 높이는 경우가 많다.

## UI 라이브러리를 쓰면 좋은 점

UI 라이브러리를 사용하면 다음 장점이 있다.

- 기본 컴포넌트를 빠르게 사용할 수 있다.
- 버튼, 폼, 모달 같은 반복 UI를 직접 만들지 않아도 된다.
- 접근성이나 키보드 조작을 어느 정도 챙긴 컴포넌트를 사용할 수 있다.
- 디자인 일관성을 맞추기 쉽다.

특히 관리자 페이지나 내부 도구처럼 빠르게 기능을 만들어야 하는 프로젝트에서 유용하다.

## UI 라이브러리의 단점

장점만 있는 것은 아니다.

- 라이브러리의 디자인 스타일에 묶일 수 있다.
- 원하는 디자인으로 바꾸기 어려울 수 있다.
- 사용하지 않는 기능까지 프로젝트에 들어올 수 있다.
- Nuxt 버전이나 SSR 환경과의 호환성을 확인해야 한다.
- 라이브러리 사용법을 따로 배워야 한다.

그래서 무조건 설치하기보다 프로젝트 성격을 먼저 생각해야 한다.

## 대표적인 선택지

Nuxt 프로젝트에서 자주 고려하는 선택지는 다음과 같다.

| 선택지 | 특징 | 잘 어울리는 경우 |
| --- | --- | --- |
| 직접 CSS 작성 | 자유도가 높고 의존성이 적다 | 작은 프로젝트, 학습용 프로젝트 |
| Tailwind CSS | 유틸리티 클래스로 빠르게 스타일링한다 | 커스텀 디자인, 빠른 화면 제작 |
| Nuxt UI | Nuxt 생태계에 맞춘 UI 컴포넌트 | Nuxt 중심 프로젝트 |
| Vuetify | Material Design 기반 컴포넌트 | 관리자, 업무 시스템 |
| Headless UI 계열 | 동작만 제공하고 디자인은 직접 작성 | 디자인 시스템을 직접 만들 때 |

이 표는 절대적인 정답이 아니다. 프로젝트 목표, 팀 경험, 디자인 요구사항에 따라 달라진다.

## 초보자에게 추천하는 선택

Nuxt를 처음 배우는 단계라면 처음부터 큰 UI 라이브러리를 붙이지 않는 것을 추천한다.

먼저 다음 흐름을 경험해 보자.

1. 기본 HTML과 scoped CSS로 간단한 화면 만들기
2. 공통 버튼과 카드 컴포넌트 직접 만들기
3. 폼, 모달, 드롭다운처럼 복잡한 UI가 필요해지는 지점 확인하기
4. 그때 UI 라이브러리를 비교하기

이렇게 하면 UI 라이브러리가 무엇을 대신해 주는지 더 잘 이해할 수 있다.

## Tailwind CSS를 선택할 때

Tailwind CSS는 빠르게 스타일을 붙이기 좋다.

```vue
<template>
  <button class="rounded bg-black px-4 py-2 text-white">
    저장
  </button>
</template>
```

클래스를 조합해 디자인을 만들기 때문에 CSS 파일을 많이 오가지 않아도 된다.

하지만 클래스가 길어지면 템플릿이 복잡해질 수 있다. 반복되는 스타일은 컴포넌트로 분리하는 습관이 필요하다.

## Nuxt UI를 선택할 때

Nuxt UI는 Nuxt 프로젝트에서 사용하기 좋게 설계된 UI 컴포넌트 모음이다.

Nuxt와의 통합을 중요하게 생각하고, 빠르게 그럴듯한 UI를 만들고 싶다면 좋은 선택지가 될 수 있다.

다만 학습 초반에는 Nuxt 자체 기능과 UI 라이브러리 기능이 섞여 헷갈릴 수 있다. 먼저 Nuxt의 라우팅, 레이아웃, 데이터 가져오기를 익힌 뒤 도입하는 것이 좋다.

## Vuetify를 선택할 때

Vuetify는 Material Design 기반의 풍부한 컴포넌트를 제공한다.

관리자 페이지, 대시보드, 업무 시스템처럼 폼과 테이블이 많은 화면에 잘 어울린다.

반면 디자인이 Material Design 스타일에 가까워지기 쉽다. 브랜드 개성이 강한 사이트라면 커스터마이징 비용을 고려해야 한다.

## 선택 체크리스트

UI 라이브러리를 고르기 전에 다음 질문을 해 보자.

- Nuxt 3와 잘 호환되는가?
- SSR 환경에서 문제가 없는가?
- 필요한 컴포넌트가 충분히 있는가?
- 디자인을 원하는 만큼 바꿀 수 있는가?
- 문서와 예제가 충분한가?
- 팀원이 배우기 쉬운가?
- 프로젝트 크기에 비해 너무 무겁지 않은가?

## 자주 하는 실수

가장 흔한 실수는 프로젝트를 시작하자마자 여러 UI 도구를 동시에 설치하는 것이다.

예를 들어 Tailwind CSS, Vuetify, 다른 컴포넌트 라이브러리를 한 번에 섞으면 스타일 규칙이 복잡해지고 유지보수가 어려워질 수 있다.

처음에는 하나의 전략을 선택하고, 필요한 이유가 생길 때만 추가하는 것이 좋다.

## 정리

UI 라이브러리는 개발 속도를 높여 주지만 프로젝트의 디자인과 구조에 영향을 준다. Nuxt를 처음 배울 때는 기본 CSS와 컴포넌트 작성에 익숙해진 뒤, 필요에 따라 Tailwind CSS, Nuxt UI, Vuetify 같은 도구를 선택하는 것이 좋다.
