## 서버 API에서 다루는 것

서버 API는 클라이언트의 요청을 받고 응답을 돌려준다.

요청에는 여러 정보가 들어 있다.

- 주소
- HTTP 메서드
- query string
- route params
- request body
- headers
- cookies

이번 장에서는 가장 자주 쓰는 query, params, body, status code를 먼저 배운다.

## query 읽기

query string은 주소 뒤에 붙는 검색 조건이다.

```txt
/api/posts?page=2&q=nuxt
```

서버 API에서는 `getQuery`로 읽을 수 있다.

`server/api/posts.get.ts`

```ts
export default defineEventHandler((event) => {
  const query = getQuery(event)

  return {
    page: query.page,
    q: query.q
  }
})
```

query 값은 문자열, 배열, undefined 등으로 들어올 수 있다. 숫자로 사용하려면 직접 변환한다.

```ts
const page = Number(query.page || 1)
```

## params 읽기

동적 경로의 값은 `getRouterParam`으로 읽을 수 있다.

```txt
server/api/posts/[id].get.ts
```

```ts
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')

  return {
    id,
    title: `${id}번 게시글`
  }
})
```

`/api/posts/10`으로 요청하면 `id`는 `10`이 된다.

## body 읽기

POST 요청의 body는 `readBody`로 읽는다.

`server/api/posts.post.ts`

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  return {
    title: body.title,
    content: body.content
  }
})
```

클라이언트에서는 다음처럼 보낸다.

```ts
await $fetch('/api/posts', {
  method: 'POST',
  body: {
    title: '새 글',
    content: '내용입니다.'
  }
})
```

## 간단한 유효성 검사

서버에서는 사용자가 보낸 값을 믿으면 안 된다.

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  if (!body.title) {
    throw createError({
      statusCode: 400,
      statusMessage: '제목은 필수입니다.'
    })
  }

  return {
    ok: true,
    title: body.title
  }
})
```

필수 값이 없으면 400 오류를 반환한다.

## status code 설정하기

기본적으로 정상 응답은 200으로 처리된다.

다른 상태 코드를 반환하고 싶다면 `setResponseStatus`를 사용할 수 있다.

```ts
export default defineEventHandler((event) => {
  setResponseStatus(event, 201)

  return {
    ok: true
  }
})
```

201은 보통 리소스 생성 성공을 의미한다.

## createError 사용하기

오류 응답은 `createError`로 만들 수 있다.

```ts
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')

  if (!id) {
    throw createError({
      statusCode: 400,
      statusMessage: 'ID가 필요합니다.'
    })
  }

  return {
    id
  }
})
```

잘못된 요청, 권한 없음, 찾을 수 없음 같은 상황에 사용한다.

## 자주 쓰는 상태 코드

| 상태 코드 | 의미 | 사용하는 상황 |
| --- | --- | --- |
| 200 | OK | 조회 성공 |
| 201 | Created | 생성 성공 |
| 400 | Bad Request | 요청 값이 잘못됨 |
| 401 | Unauthorized | 로그인 필요 |
| 403 | Forbidden | 권한 없음 |
| 404 | Not Found | 데이터를 찾을 수 없음 |
| 500 | Internal Server Error | 서버 오류 |

처음에는 200, 201, 400, 401, 403, 404 정도만 익혀도 충분하다.

## 자주 하는 실수

클라이언트에서 검증했으니 서버 검증은 필요 없다고 생각하는 실수를 조심해야 한다.

브라우저의 코드는 사용자가 조작할 수 있다. 중요한 검증은 반드시 서버에서도 해야 한다.

## 정리

서버 API에서는 `getQuery`, `getRouterParam`, `readBody`, `setResponseStatus`, `createError`를 자주 사용한다. 요청 값을 읽고 검증한 뒤, 상황에 맞는 응답과 상태 코드를 반환하는 습관이 중요하다.
