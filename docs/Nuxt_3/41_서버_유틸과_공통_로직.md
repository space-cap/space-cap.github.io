# 서버 유틸과 공통 로직

## 이번 장에서 배울 것

- `server/utils` 폴더의 역할
- 서버 API에서 공통 로직을 분리하는 방법
- 응답 형식과 검증 로직을 재사용하는 방법
- 앱의 `utils`와 서버 `utils`의 차이

## 왜 서버 유틸이 필요할까

API가 늘어나면 같은 코드가 반복된다.

예를 들어 다음 로직은 여러 API에서 반복될 수 있다.

- 성공 응답 형식 만들기
- 오류 응답 만들기
- 사용자 인증 확인
- 날짜 포맷 변환
- 외부 API 호출 공통 옵션
- body 검증

이런 코드를 매번 API 파일에 작성하면 수정하기 어렵다. `server/utils`로 분리하면 서버 API에서 재사용할 수 있다.

## server/utils 폴더

프로젝트 루트에 `server/utils` 폴더를 만든다.

```txt
server/
  utils/
    response.ts
```

Nuxt 서버 영역에서는 `server/utils` 안의 유틸을 자동으로 사용할 수 있다.

## 성공 응답 유틸 만들기

`server/utils/response.ts`

```ts
export const okResponse = <T>(data: T) => {
  return {
    ok: true,
    data
  }
}
```

API에서 사용한다.

```ts
export default defineEventHandler(() => {
  return okResponse([
    { id: 1, title: '첫 번째 글' }
  ])
})
```

반복되는 응답 구조를 통일할 수 있다.

## 인증 확인 유틸 만들기

`server/utils/auth.ts`

```ts
export const requireUser = (event) => {
  const user = event.context.auth?.user

  if (!user) {
    throw createError({
      statusCode: 401,
      statusMessage: '로그인이 필요합니다.'
    })
  }

  return user
}
```

API에서 사용한다.

```ts
export default defineEventHandler((event) => {
  const user = requireUser(event)

  return {
    user
  }
})
```

실제 프로젝트에서는 `event` 타입을 더 정확히 지정할 수 있다. 초보 단계에서는 흐름을 이해하는 것이 먼저다.

## body 검증 유틸 예시

간단한 필수값 검증 함수를 만들 수 있다.

```ts
export const requireFields = (body, fields: string[]) => {
  for (const field of fields) {
    if (!body[field]) {
      throw createError({
        statusCode: 400,
        statusMessage: `${field} 값이 필요합니다.`
      })
    }
  }
}
```

사용 예시는 다음과 같다.

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  requireFields(body, ['title', 'content'])

  return {
    ok: true
  }
})
```

실무에서는 Zod 같은 검증 라이브러리를 사용하는 경우도 많다. 하지만 처음에는 직접 간단한 검증부터 이해해도 좋다.

## 앱 utils와 server/utils 차이

Nuxt에는 `utils` 폴더도 있고 `server/utils` 폴더도 있다.

```txt
utils/
  formatDate.ts

server/
  utils/
    response.ts
```

차이는 다음과 같다.

| 폴더 | 사용 위치 | 예시 |
| --- | --- | --- |
| `utils` | Vue 앱 영역 | 화면 포맷 함수 |
| `server/utils` | 서버 영역 | API 응답, 인증, 서버 검증 |

서버에서만 필요한 비밀 처리나 인증 로직은 `server/utils`에 둔다.

## 자주 하는 실수

클라이언트에서도 쓰는 `utils`에 서버 비밀 로직을 넣는 실수를 조심해야 한다.

서버 전용 로직은 `server/utils`에 둔다.

또 유틸을 너무 빨리 만들 필요는 없다. 같은 코드가 두세 번 반복되고 의미가 분명해졌을 때 분리해도 늦지 않다.

## 정리

`server/utils`는 서버 API에서 반복되는 공통 로직을 분리하는 곳이다. 응답 형식, 인증 확인, 검증 로직처럼 서버에서만 필요한 코드를 관리하기 좋다.
