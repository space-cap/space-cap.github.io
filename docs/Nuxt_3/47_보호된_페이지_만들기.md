# 보호된 페이지 만들기

## 이번 장에서 배울 것

- 보호된 페이지가 무엇인지
- 라우트 미들웨어로 접근을 제한하는 방법
- 서버 API에서도 권한을 확인해야 하는 이유
- 로그인 페이지로 리다이렉트하는 흐름

## 보호된 페이지란

보호된 페이지는 로그인한 사용자만 볼 수 있는 페이지다.

예를 들어 다음 페이지는 보통 보호가 필요하다.

- 마이페이지
- 대시보드
- 주문 내역
- 관리자 페이지
- 글 작성 페이지

Nuxt에서는 라우트 미들웨어를 사용해 페이지 이동 전에 로그인 여부를 확인할 수 있다.

## auth 미들웨어 만들기

`middleware/auth.ts`

```ts
export default defineNuxtRouteMiddleware(async (to) => {
  const user = useState('auth-user', () => null)

  if (user.value) {
    return
  }

  try {
    user.value = await $fetch('/api/auth/me')
  } catch {
    return navigateTo({
      path: '/login',
      query: {
        redirect: to.fullPath
      }
    })
  }
})
```

이 미들웨어는 먼저 사용자 상태를 확인한다. 없으면 `/api/auth/me`로 현재 사용자를 가져오려고 시도한다.

실패하면 로그인 페이지로 이동한다.

## 페이지에 미들웨어 적용하기

`pages/dashboard.vue`

```vue
<script setup>
definePageMeta({
  middleware: 'auth'
})
</script>

<template>
  <main>
    <h1>대시보드</h1>
    <p>로그인한 사용자만 볼 수 있습니다.</p>
  </main>
</template>
```

이제 `/dashboard`로 이동할 때 `auth` 미들웨어가 먼저 실행된다.

## 로그인 후 원래 페이지로 돌아가기

사용자가 `/dashboard`에 접근하다가 로그인 페이지로 이동되었다면, 로그인 후 원래 가려던 페이지로 돌려보내면 좋다.

`pages/login.vue`

```vue
<script setup>
const route = useRoute()

const email = ref('')
const password = ref('')

const login = async () => {
  await $fetch('/api/auth/login', {
    method: 'POST',
    body: {
      email: email.value,
      password: password.value
    }
  })

  const redirect = typeof route.query.redirect === 'string'
    ? route.query.redirect
    : '/dashboard'

  await navigateTo(redirect)
}
</script>
```

`redirect` query가 있으면 그 주소로 이동하고, 없으면 `/dashboard`로 이동한다.

## 서버 API도 보호하기

라우트 미들웨어는 사용자 경험을 위한 페이지 접근 제어다.

하지만 중요한 데이터 API는 서버에서도 반드시 보호해야 한다.

`server/api/admin/users.get.ts`

```ts
export default defineEventHandler((event) => {
  const session = getCookie(event, 'session')

  if (!session) {
    throw createError({
      statusCode: 401,
      statusMessage: '로그인이 필요합니다.'
    })
  }

  return [
    { id: 1, name: '홍길동' }
  ]
})
```

클라이언트에서 페이지 접근을 막아도, 사용자는 API 주소를 직접 호출할 수 있다. 그래서 서버 API 검증이 필수다.

## 사용자 상태 초기화

로그아웃하면 사용자 상태도 비워야 한다.

```ts
const logout = async () => {
  await $fetch('/api/auth/logout', {
    method: 'POST'
  })

  const user = useState('auth-user', () => null)
  user.value = null

  await navigateTo('/login')
}
```

쿠키만 지우고 클라이언트 상태를 그대로 두면 화면에는 아직 로그인된 것처럼 보일 수 있다.

## 자주 하는 실수

라우트 미들웨어만 믿고 서버 API를 보호하지 않는 실수를 조심해야 한다.

페이지 접근 제한은 화면 이동을 제어하는 장치다. 실제 데이터 보호는 서버에서 해야 한다.

또 미들웨어에서 매번 `/api/auth/me`를 호출하면 페이지 이동이 느려질 수 있다. 사용자 상태가 이미 있으면 재사용하고, 필요한 시점에만 새로 확인하는 전략이 좋다.

## 정리

보호된 페이지는 라우트 미들웨어로 접근을 제어할 수 있다. 하지만 실제 보안은 서버 API의 인증과 권한 검증에서 완성된다. 페이지 보호와 API 보호를 함께 설계해야 한다.
