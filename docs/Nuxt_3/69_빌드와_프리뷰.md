# 빌드와 프리뷰

## 이번 장에서 배울 것

- 개발 서버와 운영 빌드의 차이
- `npm run build`가 하는 일
- `.output` 폴더의 의미
- `npm run preview`로 배포 전 확인하는 방법

## 개발 서버와 운영 빌드

개발 중에는 보통 다음 명령을 사용한다.

```bash
npm run dev
```

개발 서버는 빠른 피드백을 위해 동작한다. 파일을 저장하면 화면이 갱신되고, 오류 메시지도 개발자가 보기 쉽게 표시된다.

하지만 실제 배포에는 개발 서버를 사용하지 않는다. 운영 환경에 맞게 빌드한 결과물을 사용해야 한다.

## 빌드 명령

Nuxt 앱을 운영용으로 빌드한다.

```bash
npm run build
```

`package.json`에는 보통 다음 script가 있다.

```json
{
  "scripts": {
    "build": "nuxt build"
  }
}
```

빌드 과정에서는 Nuxt가 앱을 분석하고, 서버와 클라이언트 결과물을 생성한다.

## .output 폴더

빌드가 성공하면 `.output` 폴더가 만들어진다.

```txt
.output/
  public/
  server/
```

이 폴더는 운영 환경에서 실행하거나 배포할 결과물이다.

중요한 점은 `.output`은 생성 결과물이므로 보통 Git에 커밋하지 않는다는 것이다.

`.gitignore`에 포함되어 있어야 한다.

```txt
.output
.nuxt
node_modules
```

## 프리뷰 명령

빌드 결과를 로컬에서 확인하려면 다음 명령을 실행한다.

```bash
npm run preview
```

`package.json`에는 보통 다음 script가 있다.

```json
{
  "scripts": {
    "preview": "nuxt preview"
  }
}
```

일반적인 확인 순서는 다음과 같다.

```bash
npm run build
npm run preview
```

브라우저에서 로컬 주소를 열어 빌드 결과가 제대로 동작하는지 확인한다.

## 왜 preview가 필요할까

개발 서버에서는 잘 되던 코드가 운영 빌드에서 문제가 생길 수 있다.

예를 들어 다음 문제가 배포 전에 발견될 수 있다.

- 타입 오류
- SSR에서만 발생하는 오류
- 환경 변수 누락
- 빌드 시점에만 실행되는 코드 문제
- 정적 생성 경로 누락
- 클라이언트 전용 코드를 서버에서 사용한 문제

배포 전에 `build`와 `preview`를 실행하는 습관이 좋다.

## Node 서버로 실행하기

Node 서버 배포에서는 빌드 후 다음처럼 실행할 수 있다.

```bash
node .output/server/index.mjs
```

Nitro의 Node preset은 실행 가능한 서버 결과물을 만든다.

대부분의 플랫폼에서는 직접 이 명령을 작성하지 않아도 플랫폼이 알맞은 실행 방식을 감지한다. 하지만 구조를 이해하면 배포 문제를 해결하기 쉽다.

## 포트 설정

Node 서버로 실행할 때 포트는 환경 변수로 조정할 수 있다.

```bash
PORT=3000 node .output/server/index.mjs
```

Windows PowerShell에서는 다음처럼 설정한다.

```powershell
$env:PORT=3000
node .output/server/index.mjs
```

대부분의 호스팅 플랫폼은 `PORT` 값을 자동으로 제공한다.

## 자주 하는 실수

개발 서버인 `npm run dev`를 운영 환경에서 실행하는 실수를 조심해야 한다.

운영 환경에서는 `npm run build`로 만든 결과물을 실행해야 한다.

또 빌드가 성공했는지 확인하지 않고 배포하면, 배포 플랫폼에서 처음 오류를 보게 된다. 로컬에서 `npm run build`를 먼저 실행해 보는 습관이 좋다.

## 정리

`npm run dev`는 개발용이고, `npm run build`는 운영용 결과물을 만든다. 빌드 결과는 `.output` 폴더에 생성되며, `npm run preview`로 배포 전 로컬에서 확인할 수 있다.
