# 서버 미들웨어

## 이번 장에서 배울 것

- 서버 미들웨어가 무엇인지
- 라우트 미들웨어와 서버 미들웨어의 차이
- `server/middleware` 폴더 사용법
- 요청 로깅과 공통 context 추가

## 서버 미들웨어란

서버 미들웨어는 서버 요청이 들어올 때 API나 서버 라우트보다 먼저 실행되는 코드다.

예를 들어 다음 일을 할 수 있다.

- 모든 요청 로그 남기기
- 요청 헤더 확인하기
- 인증 정보를 `event.context`에 추가하기
- 공통 보안 헤더 설정하기

Nuxt에서는 `server/middleware` 폴더에 파일을 만들면 서버 미들웨어로 등록된다.

## 라우트 미들웨어와의 차이

이름이 비슷해서 헷갈리기 쉽다.

| 구분 | 라우트 미들웨어 | 서버 미들웨어 |
| --- | --- | --- |
| 위치 | `middleware/` | `server/middleware/` |
| 실행 시점 | 페이지 이동 전 | 서버 요청 처리 전 |
| 주요 목적 | 페이지 접근 제어 | 서버 요청 공통 처리 |
| 예시 | 로그인하지 않으면 `/login` 이동 | 모든 API 요청 로그 기록 |

둘은 서로 다른 기능이다.

## 요청 로그 남기기

`server/middleware/log.ts` 파일을 만든다.

```ts
export default defineEventHandler((event) => {
  console.log('요청:', getRequestURL(event).pathname)
})
```

서버에 요청이 들어올 때마다 경로가 터미널에 출력된다.

개발 중에는 어떤 요청이 발생하는지 확인하는 데 유용하다.

## event.context에 값 추가하기

서버 미들웨어에서 `event.context`에 값을 넣으면 뒤에 실행되는 API에서 사용할 수 있다.

`server/middleware/auth.ts`

```ts
export default defineEventHandler((event) => {
  event.context.auth = {
    userId: 1,
    role: 'admin'
  }
})
```

API에서 읽는다.

```ts
export default defineEventHandler((event) => {
  return {
    auth: event.context.auth
  }
})
```

실무에서는 쿠키나 헤더를 읽어 사용자 정보를 확인한 뒤 context에 넣는 방식으로 활용할 수 있다.

## 미들웨어는 응답을 반환하지 않는다

서버 미들웨어는 보통 응답을 직접 반환하지 않는다.

공식 문서에서도 서버 미들웨어는 요청을 검사하거나 context를 확장하고, 응답을 닫거나 반환하지 않는 흐름을 권장한다.

```ts
export default defineEventHandler((event) => {
  event.context.requestStartedAt = Date.now()
})
```

API 응답은 실제 server route에서 반환하도록 둔다.

## 요청을 막아야 하는 경우

특정 요청을 막아야 한다면 오류를 던질 수 있다.

```ts
export default defineEventHandler((event) => {
  const path = getRequestURL(event).pathname

  if (path.startsWith('/api/admin')) {
    const isAdmin = false

    if (!isAdmin) {
      throw createError({
        statusCode: 403,
        statusMessage: '관리자 권한이 필요합니다.'
      })
    }
  }
})
```

다만 모든 요청마다 실행되므로 로직은 가볍게 유지하는 것이 좋다.

## 자주 하는 실수

서버 미들웨어에 무거운 API 호출이나 복잡한 작업을 넣는 실수를 조심해야 한다.

서버 미들웨어는 많은 요청에서 반복 실행될 수 있다. 느린 작업이 들어가면 전체 응답 시간이 느려진다.

또 페이지 접근 제어를 서버 미들웨어로만 처리하려고 하면 사용자 경험이 어색할 수 있다. 페이지 이동 제어는 라우트 미들웨어, 서버 요청 보호는 서버 미들웨어나 API 내부 검증을 함께 사용한다.

## 정리

서버 미들웨어는 `server/middleware` 폴더에 만들며, 서버 요청이 API보다 먼저 실행된다. 요청 로깅, 공통 context 추가, 인증 확인 같은 서버 공통 처리에 사용한다.
