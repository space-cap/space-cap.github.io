# 서버와 클라이언트 데이터 요청 차이

## 이번 장에서 배울 것

- Nuxt에서 데이터 요청이 서버와 클라이언트 어디에서 실행되는지
- SSR과 hydration에서 중복 요청이 생기는 이유
- `useFetch`가 중복 요청을 줄이는 방식
- `server: false` 옵션의 의미

## Nuxt 코드는 어디에서 실행될까

Nuxt는 서버에서도 실행되고 브라우저에서도 실행될 수 있다.

페이지를 처음 요청하면 서버가 Vue 컴포넌트를 실행해 HTML을 만들 수 있다. 이후 브라우저는 JavaScript를 내려받고 같은 화면을 Vue 앱으로 연결한다.

이 과정 때문에 데이터 요청도 서버에서 실행될 수 있고, 클라이언트에서 실행될 수도 있다.

## 서버에서 먼저 가져오는 데이터

`useFetch`를 기본 설정으로 사용하면 Nuxt는 서버 렌더링 과정에서 데이터를 가져올 수 있다.

```vue
<script setup>
const { data: posts } = await useFetch('/api/posts')
</script>
```

서버는 게시글 데이터를 가져와 HTML을 만들고, 그 데이터를 Nuxt payload에 담아 브라우저로 보낸다.

브라우저는 payload에 담긴 데이터를 이어받아 같은 요청을 다시 하지 않도록 할 수 있다.

## hydration과 중복 요청

hydration은 서버에서 받은 HTML에 브라우저의 JavaScript 동작을 연결하는 과정이다.

만약 서버에서도 데이터를 가져오고 브라우저에서도 같은 데이터를 다시 가져오면 중복 요청이 된다.

Nuxt의 `useFetch`와 `useAsyncData`는 요청 결과를 payload에 담아 서버에서 클라이언트로 전달한다. 덕분에 hydration 과정에서 같은 데이터를 다시 요청하는 일을 줄일 수 있다.

## $fetch만 사용할 때 주의점

페이지 초기 데이터에 `$fetch`만 사용하면 Nuxt의 async data 관리 흐름을 충분히 활용하지 못할 수 있다.

```vue
<script setup>
const posts = await $fetch('/api/posts')
</script>
```

이 방식은 단순해 보이지만, SSR과 hydration 사이의 데이터 전달을 직접 관리하지 않는다.

그래서 페이지 초기 데이터에는 보통 `useFetch`나 `useAsyncData`를 우선 사용한다.

## 클라이언트에서만 요청하기

어떤 데이터는 서버에서 가져오지 않고 브라우저에서만 가져오고 싶을 수 있다.

예를 들어 브라우저 전용 정보에 의존하거나, SEO와 상관없는 개인화 데이터일 수 있다.

이럴 때 `server: false` 옵션을 사용할 수 있다.

```vue
<script setup>
const { data, status } = await useFetch('/api/client-only', {
  server: false
})
</script>
```

이 경우 서버 렌더링 중에는 요청하지 않고, 클라이언트에서 hydration이 끝난 뒤 요청이 시작될 수 있다.

## server: false의 주의점

`server: false`를 사용하면 첫 HTML에는 해당 데이터가 없다.

따라서 화면에서 로딩 상태를 잘 처리해야 한다.

```vue
<template>
  <p v-if="status === 'pending'">불러오는 중...</p>
  <pre v-else>{{ data }}</pre>
</template>
```

SEO가 중요한 콘텐츠라면 `server: false`를 신중하게 사용해야 한다. 검색 엔진이 처음 받은 HTML에서 내용을 보지 못할 수 있기 때문이다.

## 서버 내부 API 호출

Nuxt 서버에서 자신의 `server/api` 엔드포인트를 호출할 때는 `$fetch`가 내부적으로 효율적인 방식으로 처리될 수 있다.

하지만 페이지 데이터 흐름에서는 여전히 `useFetch`나 `useAsyncData`를 통해 Nuxt payload와 상태 관리를 활용하는 것이 좋다.

## 선택 기준

처음에는 다음 기준을 기억하자.

| 상황 | 추천 |
| --- | --- |
| 페이지 초기 데이터 | `useFetch` |
| 복잡한 비동기 데이터 조합 | `useAsyncData` |
| 버튼 클릭 후 요청 | `$fetch` |
| 클라이언트에서만 필요한 데이터 | `useFetch` + `server: false` |
| 늦게 불러와도 되는 부가 데이터 | `useLazyFetch` |

## 자주 하는 실수

서버에서 실행되는 코드 안에서 `window`, `document`, `localStorage`를 바로 사용하는 실수가 많다.

데이터 요청 로직도 마찬가지다. 브라우저 전용 값이 필요한 요청이라면 클라이언트에서만 실행되도록 처리해야 한다.

## 정리

Nuxt의 데이터 요청은 서버와 클라이언트 양쪽 흐름을 이해해야 한다. `useFetch`와 `useAsyncData`는 서버에서 가져온 데이터를 payload로 전달해 hydration 중복 요청을 줄이는 데 도움을 준다.
