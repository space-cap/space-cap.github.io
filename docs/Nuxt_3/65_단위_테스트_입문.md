# 단위 테스트 입문

## 이번 장에서 배울 것

- 단위 테스트가 무엇인지
- Nuxt에서 Vitest와 Nuxt Test Utils를 설정하는 방법
- 순수 함수 테스트 작성하기
- Nuxt 환경이 필요한 테스트와 일반 테스트의 차이

## 단위 테스트란

단위 테스트는 작은 코드 조각이 기대한 대로 동작하는지 확인하는 테스트다.

예를 들어 다음 대상은 단위 테스트에 어울린다.

- 날짜 포맷 함수
- 가격 계산 함수
- 검색 필터 함수
- composable의 작은 로직
- API 응답 가공 함수

테스트는 코드를 고친 뒤에도 기존 기능이 깨지지 않았는지 확인하는 안전망이다.

## 테스트 도구 설치

Nuxt 공식 문서는 `@nuxt/test-utils`와 Vitest를 사용한 테스트 흐름을 안내한다.

```bash
npm install --save-dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```

프로젝트에 필요한 범위에 따라 의존성을 조정할 수 있다. 처음에는 Vitest와 Nuxt Test Utils 중심으로 시작한다.

## Nuxt 테스트 모듈 등록

개발 중 Nuxt DevTools와 테스트 통합을 사용하고 싶다면 모듈을 등록할 수 있다.

`nuxt.config.ts`

```ts
export default defineNuxtConfig({
  modules: [
    '@nuxt/test-utils/module'
  ]
})
```

이 설정은 필수라기보다 Nuxt 테스트 경험을 편하게 해 주는 선택지에 가깝다.

## Vitest 설정

간단한 설정은 `vitest.config.ts`에 작성한다.

```ts
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt'
  }
})
```

모든 테스트를 Nuxt 환경에서 실행하는 단순 설정이다.

더 큰 프로젝트에서는 일반 unit 테스트와 Nuxt runtime 테스트를 분리할 수 있다.

## 테스트 명령 추가

`package.json`

```json
{
  "scripts": {
    "test": "vitest",
    "test:run": "vitest run"
  }
}
```

개발 중에는 watch 모드로 실행한다.

```bash
npm run test
```

CI나 최종 확인에서는 한 번만 실행한다.

```bash
npm run test:run
```

## 순수 함수 테스트

먼저 Nuxt와 상관없는 순수 함수를 테스트해 보자.

`utils/formatPrice.ts`

```ts
export const formatPrice = (price: number) => {
  return `${price.toLocaleString()}원`
}
```

`test/unit/formatPrice.test.ts`

```ts
import { describe, expect, it } from 'vitest'
import { formatPrice } from '~/utils/formatPrice'

describe('formatPrice', () => {
  it('숫자를 원화 문자열로 변환한다', () => {
    expect(formatPrice(12000)).toBe('12,000원')
  })
})
```

테스트는 입력과 기대 결과가 분명해야 한다.

## composable 테스트

Nuxt runtime이 필요한 composable은 Nuxt 테스트 환경에서 실행한다.

`composables/useCounter.ts`

```ts
export const useCounter = () => {
  const count = ref(0)

  const increase = () => {
    count.value++
  }

  return {
    count,
    increase
  }
}
```

`test/nuxt/useCounter.test.ts`

```ts
import { describe, expect, it } from 'vitest'

describe('useCounter', () => {
  it('increase를 호출하면 count가 증가한다', () => {
    const { count, increase } = useCounter()

    increase()

    expect(count.value).toBe(1)
  })
})
```

## 무엇을 테스트할까

처음부터 모든 것을 테스트하려고 하면 부담스럽다.

다음 기준으로 시작하자.

- 계산 로직
- 조건 분기
- 오류가 나면 치명적인 로직
- 여러 곳에서 재사용하는 composable
- 한 번 깨지면 발견하기 어려운 로직

단순히 Vue가 이미 보장하는 기능까지 테스트할 필요는 없다.

## 자주 하는 실수

구현 방식만 그대로 확인하는 테스트는 가치가 낮다.

좋은 테스트는 "어떻게 구현했는지"보다 "어떤 동작을 보장해야 하는지"에 집중한다.

또 테스트끼리 전역 상태를 공유하면 순서에 따라 결과가 달라질 수 있다. `useState`나 Pinia 상태를 바꾼다면 테스트 후 초기화 전략을 생각해야 한다.

## 정리

단위 테스트는 작은 코드 조각의 동작을 확인하는 테스트다. Nuxt에서는 Vitest와 `@nuxt/test-utils`를 사용해 일반 함수와 Nuxt runtime이 필요한 코드를 테스트할 수 있다.
