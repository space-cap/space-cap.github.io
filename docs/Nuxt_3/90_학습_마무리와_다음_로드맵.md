## 포트폴리오 프로젝트 아이디어

Nuxt로 만들기 좋은 포트폴리오 프로젝트는 다음과 같다.

- 개인 기술 블로그
- Markdown 문서 사이트
- 게시판
- 로그인 회원 서비스
- 쇼핑몰 상품 목록
- 관리자 대시보드
- 예약 시스템
- Todo와 캘린더 앱
- 작은 SaaS 랜딩 페이지
- 영화나 책 검색 서비스

포트폴리오에서는 기능 개수보다 완성도가 중요하다.

다음 요소를 챙기면 좋다.

- README
- 설치와 실행 방법
- 주요 기능 설명
- 배포 URL
- 테스트 또는 빌드 확인
- 반응형 화면
- 기본 SEO
- 에러 상태 처리
- 빈 상태 처리
- 접근성 기본

## 학습 전략

Nuxt를 잘 배우려면 문서를 읽는 것만으로는 부족하다.

작게 만들고, 깨지고, 고치면서 배워야 한다.

추천 흐름은 다음과 같다.

1. 작은 페이지를 만든다.
2. 라우트를 하나 추가한다.
3. API를 하나 만든다.
4. 데이터를 가져와 화면에 표시한다.
5. 폼을 만든다.
6. 에러 처리를 추가한다.
7. 배포한다.
8. 다시 구조를 정리한다.

처음부터 완벽한 구조를 만들려고 하지 않아도 된다.

## 실무 감각을 키우는 질문

기능을 만들 때 다음 질문을 습관처럼 해 보자.

- 이 코드는 서버에서 실행되는가, 브라우저에서 실행되는가?
- 이 데이터는 사용자마다 다른가?
- 이 페이지는 SEO가 중요한가?
- 이 값은 public으로 노출되어도 되는가?
- 실패했을 때 사용자에게 무엇을 보여 줄 것인가?
- 배포 환경에서 이 기능이 동작하는가?
- 테스트로 보장해야 하는 핵심 동작은 무엇인가?

이 질문들이 Nuxt 실무의 좋은 나침반이 된다.

## 마지막 정리

Nuxt 3를 배운다는 것은 Vue 컴포넌트를 만드는 것에서 끝나지 않는다.

페이지를 나누고, 데이터를 가져오고, 서버 API를 만들고, 인증을 처리하고, SEO와 배포를 챙기며, 실제 사용자에게 안정적으로 전달하는 전체 흐름을 배우는 일이다.

이제 작은 프로젝트를 하나 정해 끝까지 만들어 보자. 끝까지 만든 프로젝트 하나가 읽은 문서 열 개보다 더 많은 것을 알려 준다.
