# 인증 흐름 입문

## 이번 장에서 배울 것

- 인증과 인가의 차이
- Nuxt에서 로그인 흐름을 구성하는 기본 방식
- 서버 API와 쿠키를 이용한 로그인 예시
- 토큰 저장 시 주의할 점

## 인증과 인가

인증은 사용자가 누구인지 확인하는 일이다.

예를 들어 이메일과 비밀번호로 로그인해 "이 사용자는 홍길동이다"라고 확인하는 과정이 인증이다.

인가는 인증된 사용자가 어떤 행동을 할 수 있는지 결정하는 일이다.

예를 들어 일반 사용자는 자신의 글만 수정할 수 있고, 관리자는 모든 글을 수정할 수 있게 하는 것이 인가다.

## 기본 로그인 흐름

가장 단순한 로그인 흐름은 다음과 같다.

1. 사용자가 로그인 폼에 이메일과 비밀번호를 입력한다.
2. 클라이언트가 `/api/auth/login`으로 요청을 보낸다.
3. 서버가 이메일과 비밀번호를 확인한다.
4. 서버가 세션 쿠키를 설정한다.
5. 클라이언트는 `/api/auth/me`로 현재 사용자 정보를 가져온다.
6. 보호된 페이지는 로그인 여부를 확인한다.

학습용 예제에서는 실제 DB 대신 간단한 조건으로 설명한다.

## 로그인 API 만들기

`server/api/auth/login.post.ts`

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  if (body.email !== 'user@example.com' || body.password !== 'password') {
    throw createError({
      statusCode: 401,
      statusMessage: '이메일 또는 비밀번호가 올바르지 않습니다.'
    })
  }

  setCookie(event, 'session', 'demo-session', {
    httpOnly: true,
    sameSite: 'lax',
    path: '/'
  })

  return {
    ok: true
  }
})
```

실제 서비스에서는 비밀번호를 평문으로 비교하지 않는다. 안전한 해시 검증과 DB 조회가 필요하다.

## 현재 사용자 API 만들기

`server/api/auth/me.get.ts`

```ts
export default defineEventHandler((event) => {
  const session = getCookie(event, 'session')

  if (session !== 'demo-session') {
    throw createError({
      statusCode: 401,
      statusMessage: '로그인이 필요합니다.'
    })
  }

  return {
    id: 1,
    name: '홍길동',
    email: 'user@example.com'
  }
})
```

쿠키가 유효하면 현재 사용자 정보를 반환한다.

## 로그아웃 API 만들기

`server/api/auth/logout.post.ts`

```ts
export default defineEventHandler((event) => {
  deleteCookie(event, 'session', {
    path: '/'
  })

  return {
    ok: true
  }
})
```

로그아웃은 서버에서 세션 쿠키를 제거하는 흐름으로 만들 수 있다.

## 클라이언트 로그인 처리

로그인 페이지에서 API를 호출한다.

```vue
<script setup>
const email = ref('')
const password = ref('')
const errorMessage = ref('')

const login = async () => {
  errorMessage.value = ''

  try {
    await $fetch('/api/auth/login', {
      method: 'POST',
      body: {
        email: email.value,
        password: password.value
      }
    })

    await navigateTo('/dashboard')
  } catch {
    errorMessage.value = '로그인에 실패했습니다.'
  }
}
</script>
```

로그인 성공 후 보호된 페이지로 이동한다.

## 사용자 상태 관리

사용자 정보는 `useState`나 Pinia로 관리할 수 있다.

간단한 예시는 `useState`로 충분하다.

```ts
export const useAuthUser = () => {
  return useState('auth-user', () => null)
}
```

사용자 정보를 불러오는 composable을 만들 수도 있다.

```ts
export const useAuth = () => {
  const user = useAuthUser()

  const fetchUser = async () => {
    user.value = await $fetch('/api/auth/me')
  }

  const clearUser = () => {
    user.value = null
  }

  return {
    user,
    fetchUser,
    clearUser
  }
}
```

규모가 커지면 Pinia store로 옮겨도 된다.

## 토큰 저장 주의

토큰이나 세션 식별자는 매우 민감하다.

브라우저 JavaScript에서 읽을 수 있는 localStorage나 일반 쿠키에 저장하면 XSS 공격에 노출될 수 있다.

보안이 중요한 서비스에서는 서버가 설정하는 `httpOnly` 쿠키 기반 세션을 우선 검토한다.

단, `httpOnly` 쿠키를 사용해도 CSRF, SameSite, HTTPS, 서버 검증 같은 보안 설계를 함께 해야 한다.

## 자주 하는 실수

로그인 여부를 클라이언트 상태만 보고 판단하는 실수가 많다.

클라이언트 상태는 사용자가 조작할 수 있다. 중요한 데이터 접근 권한은 반드시 서버 API에서도 검증해야 한다.

예를 들어 관리자 페이지 버튼을 숨기는 것은 UX일 뿐이다. 실제 관리자 API는 서버에서 권한을 다시 확인해야 한다.

## 정리

인증은 사용자가 누구인지 확인하는 일이고, 인가는 사용자가 무엇을 할 수 있는지 결정하는 일이다. Nuxt에서는 서버 API, 쿠키, 상태 관리, 라우트 미들웨어를 조합해 로그인 흐름을 구성할 수 있다.
