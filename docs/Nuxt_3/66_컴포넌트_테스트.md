## 컴포넌트 테스트란

컴포넌트 테스트는 Vue 컴포넌트를 실제로 렌더링해 보고, 화면에 기대한 내용이 나오는지 확인하는 테스트다.

예를 들어 다음을 확인할 수 있다.

- props를 받으면 텍스트가 표시되는가?
- 버튼을 누르면 이벤트가 발생하는가?
- 로딩 상태가 표시되는가?
- API 결과가 렌더링되는가?
- 조건에 따라 다른 UI가 보이는가?

단위 테스트보다 화면에 가까운 테스트다.

## 테스트할 컴포넌트 만들기

`components/PostCard.vue`

```vue
<script setup lang="ts">
defineProps<{
  title: string
  description?: string
}>()
</script>

<template>
  <article>
    <h2>{{ title }}</h2>
    <p v-if="description">{{ description }}</p>
  </article>
</template>
```

## mountSuspended 사용하기

Nuxt Test Utils는 `mountSuspended`를 제공한다.

`mountSuspended`는 Nuxt 환경에서 컴포넌트를 mount할 수 있게 해 준다. async setup, 자동 import, Nuxt plugin 같은 Nuxt 기능을 고려해 테스트할 수 있다.

`test/nuxt/PostCard.test.ts`

```ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { describe, expect, it } from 'vitest'
import PostCard from '~/components/PostCard.vue'

describe('PostCard', () => {
  it('제목과 설명을 표시한다', async () => {
    const wrapper = await mountSuspended(PostCard, {
      props: {
        title: 'Nuxt 테스트',
        description: '컴포넌트 테스트 예시입니다.'
      }
    })

    expect(wrapper.text()).toContain('Nuxt 테스트')
    expect(wrapper.text()).toContain('컴포넌트 테스트 예시입니다.')
  })
})
```

`wrapper.text()`는 렌더링된 텍스트를 확인한다.

## 이벤트 테스트

버튼 컴포넌트를 테스트해 보자.

`components/BaseButton.vue`

```vue
<template>
  <button type="button">
    <slot />
  </button>
</template>
```

테스트 파일:

```ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { describe, expect, it } from 'vitest'
import BaseButton from '~/components/BaseButton.vue'

describe('BaseButton', () => {
  it('버튼 텍스트를 표시한다', async () => {
    const wrapper = await mountSuspended(BaseButton, {
      slots: {
        default: '저장'
      }
    })

    expect(wrapper.text()).toContain('저장')
  })
})
```

복잡한 이벤트가 있다면 `trigger('click')`을 사용해 클릭을 시뮬레이션할 수 있다.

## API 요청 mock하기

컴포넌트가 `/api/posts`를 호출한다면 실제 API 대신 테스트용 응답을 등록할 수 있다.

Nuxt Test Utils의 `registerEndpoint`를 사용할 수 있다.

```ts
import { mountSuspended, registerEndpoint } from '@nuxt/test-utils/runtime'
import { describe, expect, it } from 'vitest'
import PostList from '~/components/PostList.vue'

registerEndpoint('/api/posts', () => [
  { id: 1, title: '테스트 글' }
])

describe('PostList', () => {
  it('API 결과를 표시한다', async () => {
    const wrapper = await mountSuspended(PostList)

    expect(wrapper.text()).toContain('테스트 글')
  })
})
```

외부 API나 서버 상태에 의존하지 않고 안정적으로 테스트할 수 있다.

## 무엇을 확인해야 할까

컴포넌트 테스트에서는 사용자가 보는 결과를 중심으로 확인한다.

좋은 확인:

- 제목이 보인다.
- 오류 메시지가 보인다.
- 버튼 클릭 후 결과가 바뀐다.
- 리스트 항목이 렌더링된다.

피하면 좋은 확인:

- 내부 변수 이름을 확인한다.
- 구현 세부 DOM 구조에 과하게 의존한다.
- 스타일 클래스만 지나치게 확인한다.

## 자주 하는 실수

테스트가 컴포넌트 내부 구현에 너무 강하게 묶이는 경우가 많다.

HTML 구조를 조금만 바꿔도 테스트가 깨진다면 테스트가 너무 세부 구현에 의존하는지 확인해야 한다.

또 API를 실제 서버에 의존하면 테스트가 느리고 불안정해질 수 있다. 컴포넌트 테스트에서는 mock을 활용하는 것이 좋다.

## 정리

컴포넌트 테스트는 Vue 컴포넌트를 렌더링하고 사용자에게 보이는 결과를 확인하는 테스트다. Nuxt에서는 `mountSuspended`와 `registerEndpoint`를 사용해 Nuxt 환경과 API mock을 함께 다룰 수 있다.
