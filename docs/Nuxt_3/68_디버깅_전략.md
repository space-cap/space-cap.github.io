# 디버깅 전략

## 이번 장에서 배울 것

- Nuxt 앱에서 오류를 찾는 기본 순서
- 브라우저 개발자 도구와 Nuxt DevTools 활용법
- 서버 오류와 클라이언트 오류 구분하기
- sourcemap과 Node inspector의 기본 개념

## 디버깅이란

디버깅은 코드가 예상대로 동작하지 않을 때 원인을 찾고 수정하는 과정이다.

Nuxt는 서버와 클라이언트가 함께 동작하는 프레임워크다. 그래서 오류가 어디에서 발생했는지 구분하는 것이 중요하다.

오류는 보통 다음 위치에서 발생한다.

- Vue 컴포넌트 렌더링
- 클라이언트 이벤트 핸들러
- 라우트 미들웨어
- 서버 API
- plugin 초기화
- 데이터 fetching
- 빌드 과정

## 먼저 확인할 곳

문제가 생기면 다음 순서로 확인한다.

1. 브라우저 화면의 오류 메시지
2. 브라우저 Console 탭
3. 브라우저 Network 탭
4. 터미널의 Nuxt 로그
5. Nuxt DevTools
6. 관련 파일의 최근 변경 사항

이 순서만 지켜도 많은 문제를 빠르게 좁힐 수 있다.

## 서버 오류와 클라이언트 오류

Nuxt에서는 코드가 서버에서 실행될 수도 있고 브라우저에서 실행될 수도 있다.

서버 오류는 터미널에 먼저 보이는 경우가 많다.

예를 들어 `server/api`에서 오류가 나면 개발 서버 터미널에 stack trace가 출력될 수 있다.

클라이언트 오류는 브라우저 Console에 보이는 경우가 많다.

예를 들어 버튼 클릭 이벤트에서 `undefined` 값을 읽으면 브라우저 Console에 오류가 출력될 수 있다.

## Network 탭 확인하기

API 요청이 실패했다면 브라우저 개발자 도구의 Network 탭을 확인한다.

확인할 항목은 다음과 같다.

- 요청 URL이 맞는가?
- HTTP 메서드가 맞는가?
- status code가 무엇인가?
- request payload가 올바른가?
- response body에 오류 메시지가 있는가?

많은 데이터 fetching 문제는 Network 탭에서 방향을 잡을 수 있다.

## Nuxt DevTools 활용하기

Nuxt DevTools에서는 Nuxt 앱의 구조를 확인할 수 있다.

다음 상황에서 유용하다.

- `pages` 파일이 라우트로 잘 등록되었는지 확인
- 컴포넌트 자동 등록 확인
- auto imports 확인
- server routes 확인
- modules 확인
- payload와 상태 확인

Nuxt의 "자동으로 연결되는 것들"이 헷갈릴 때 DevTools를 열어 보면 좋다.

## console.log를 잘 쓰기

`console.log`는 여전히 좋은 디버깅 도구다.

다만 Nuxt에서는 로그가 어디에 찍히는지 확인해야 한다.

- 서버에서 실행되는 로그: 터미널
- 브라우저에서 실행되는 로그: 브라우저 Console

예를 들어 `server/api` 안의 `console.log`는 브라우저 Console이 아니라 터미널에 출력된다.

## sourcemap

sourcemap은 빌드된 코드와 원본 코드를 연결해 주는 정보다.

Nuxt는 개발 중에는 디버깅하기 쉽게 sourcemap을 제공한다. 필요하다면 `nuxt.config.ts`에서 더 명시적으로 설정할 수 있다.

```ts
export default defineNuxtConfig({
  sourcemap: {
    server: true,
    client: true
  }
})
```

운영 환경에서 sourcemap을 공개할지 여부는 신중하게 판단해야 한다. 소스 코드 구조가 노출될 수 있기 때문이다.

## Node inspector

서버 쪽 Nuxt 코드를 깊게 디버깅해야 한다면 Node inspector를 사용할 수 있다.

```bash
nuxt dev --inspect
```

이렇게 실행하면 Chrome DevTools나 IDE에서 서버 사이드 코드를 디버깅할 수 있다.

초보 단계에서는 자주 필요하지 않지만, 서버 API나 plugin 초기화 문제를 깊게 추적할 때 도움이 된다.

## 에러 처리 도구

Nuxt는 오류 처리를 위한 여러 도구를 제공한다.

- `error.vue`: 전체 에러 페이지
- `createError`: 상태 코드가 있는 오류 생성
- `showError`: 전체 에러 페이지 표시
- `clearError`: 에러 상태 정리
- `<NuxtErrorBoundary>`: 컴포넌트 일부 오류 처리
- `vue:error` hook: 전역 Vue 오류 처리

처음에는 `createError`, `error.vue`, `clearError`부터 익히면 된다.

## 자주 하는 실수

브라우저 Console만 보고 서버 오류를 놓치는 경우가 많다.

Nuxt는 full-stack 프레임워크이므로 터미널 로그도 함께 확인해야 한다.

또 `window is not defined` 오류가 나면 서버에서 브라우저 전용 객체를 사용한 것이다. `window`, `document`, `localStorage`는 클라이언트에서만 사용할 수 있다는 점을 기억하자.

## 정리

Nuxt 디버깅은 서버와 클라이언트 실행 위치를 구분하는 것에서 시작한다. 브라우저 Console, Network 탭, 터미널 로그, Nuxt DevTools를 함께 사용하면 문제 원인을 더 빠르게 찾을 수 있다.
