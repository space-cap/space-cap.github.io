# 에러 처리와 빈 상태 UI

## 이번 장에서 배울 것

- 데이터 요청 실패를 화면에 표시하는 방법
- 빈 데이터 상태를 구분하는 방법
- 재시도 버튼 만들기
- 사용자에게 친절한 메시지를 보여 주는 방법

## 좋은 데이터 화면의 조건

API 데이터를 보여 주는 화면은 성공 상태만 생각하면 부족하다.

실제 서비스에서는 다음 상태를 모두 고려해야 한다.

- 아직 요청 전
- 요청 중
- 요청 성공
- 요청 성공했지만 데이터 없음
- 요청 실패

이 상태를 구분하지 않으면 사용자는 화면이 멈춘 것인지, 데이터가 없는 것인지, 오류가 난 것인지 알 수 없다.

## 기본 에러 처리

`useFetch`는 `error` 값을 제공한다.

```vue
<script setup>
const { data: posts, status, error } = await useFetch('/api/posts', {
  default: () => []
})
</script>

<template>
  <p v-if="status === 'pending'">불러오는 중...</p>
  <p v-else-if="error">게시글을 불러오지 못했습니다.</p>
  <ul v-else>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

오류가 발생하면 사용자가 이해할 수 있는 메시지를 보여 준다.

## 빈 상태 처리

요청은 성공했지만 데이터가 없을 수 있다.

```vue
<template>
  <p v-if="status === 'pending'">불러오는 중...</p>
  <p v-else-if="error">게시글을 불러오지 못했습니다.</p>
  <p v-else-if="posts.length === 0">아직 게시글이 없습니다.</p>
  <ul v-else>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

오류와 빈 상태는 다르다.

- 오류: 데이터를 가져오지 못함
- 빈 상태: 가져오기는 성공했지만 보여 줄 항목이 없음

이 둘을 구분해야 사용자 경험이 좋아진다.

## 재시도 버튼

요청이 실패했을 때 사용자가 다시 시도할 수 있게 만들자.

```vue
<script setup>
const { data: posts, status, error, refresh } = await useFetch('/api/posts', {
  default: () => []
})
</script>

<template>
  <div v-if="error">
    <p>게시글을 불러오지 못했습니다.</p>
    <button @click="refresh">다시 시도</button>
  </div>

  <p v-else-if="status === 'pending'">불러오는 중...</p>

  <p v-else-if="posts.length === 0">아직 게시글이 없습니다.</p>

  <ul v-else>
    <li v-for="post in posts" :key="post.id">
      {{ post.title }}
    </li>
  </ul>
</template>
```

`refresh`를 호출하면 같은 요청을 다시 실행한다.

## 오류 메시지를 그대로 보여 주지 않기

API 오류 객체에는 개발자를 위한 메시지가 들어 있을 수 있다.

사용자에게 내부 오류 내용을 그대로 보여 주면 보안상 좋지 않거나, 너무 어렵게 느껴질 수 있다.

좋은 메시지는 다음처럼 사용자의 다음 행동을 돕는다.

- 데이터를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요.
- 네트워크 연결을 확인해 주세요.
- 권한이 필요한 페이지입니다. 로그인 후 다시 시도해 주세요.

## 상태별 UI를 컴포넌트로 분리하기

여러 화면에서 같은 로딩, 오류, 빈 상태를 사용한다면 컴포넌트로 분리할 수 있다.

```txt
components/
  LoadingMessage.vue
  ErrorMessage.vue
  EmptyMessage.vue
```

예를 들어 `components/ErrorMessage.vue`를 만들 수 있다.

```vue
<script setup>
defineProps({
  message: {
    type: String,
    default: '오류가 발생했습니다.'
  }
})
</script>

<template>
  <p>{{ message }}</p>
</template>
```

처음부터 복잡하게 분리할 필요는 없지만, 반복이 보이면 컴포넌트화를 고려하자.

## 자주 하는 실수

가장 흔한 실수는 `data`가 항상 있다고 가정하는 것이다.

```vue
<li v-for="post in posts" :key="post.id">
  {{ post.title }}
</li>
```

`posts`가 `null`이면 오류가 날 수 있다. 배열을 기대한다면 `default: () => []`를 설정하거나, 템플릿에서 존재 여부를 먼저 확인한다.

## 정리

데이터 화면은 성공 상태만 있지 않다. 로딩, 오류, 빈 상태를 구분해야 한다. `useFetch`의 `status`, `error`, `refresh`, `default`를 사용하면 기본적인 상태 처리를 깔끔하게 만들 수 있다.
