# E2E 테스트

## 이번 장에서 배울 것

- E2E 테스트가 무엇인지
- Playwright로 Nuxt 앱을 테스트하는 기본 흐름
- `webServer` 설정으로 테스트 전에 서버를 실행하는 방법
- 어떤 사용자 흐름을 E2E로 테스트하면 좋은지

## E2E 테스트란

E2E는 End-to-End의 줄임말이다.

E2E 테스트는 사용자가 실제 브라우저에서 앱을 사용하는 흐름을 자동으로 확인하는 테스트다.

예를 들어 다음 흐름을 테스트할 수 있다.

- 홈 페이지에 접속한다.
- 로그인 페이지로 이동한다.
- 이메일과 비밀번호를 입력한다.
- 로그인 버튼을 누른다.
- 대시보드로 이동했는지 확인한다.

단위 테스트가 작은 로직을 확인한다면, E2E 테스트는 전체 사용자 흐름을 확인한다.

## Playwright 설치

Playwright Test를 설치한다.

```bash
npm install --save-dev @playwright/test
```

브라우저를 설치한다.

```bash
npx playwright install
```

Nuxt Test Utils와 함께 Playwright를 사용할 수도 있지만, 초보 단계에서는 Playwright Test의 기본 흐름부터 이해하는 것이 좋다.

## Playwright 설정

`playwright.config.ts`

```ts
import { defineConfig } from '@playwright/test'

export default defineConfig({
  testDir: './tests/e2e',
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI
  },
  use: {
    baseURL: 'http://localhost:3000'
  }
})
```

`webServer`는 테스트를 실행하기 전에 Nuxt 개발 서버를 실행하게 한다.

이미 로컬 서버가 떠 있다면 `reuseExistingServer` 설정으로 재사용할 수 있다.

운영 빌드 결과를 테스트하고 싶다면 `npm run build`와 `npm run preview` 흐름을 별도로 구성할 수 있다.

## 첫 E2E 테스트

`tests/e2e/home.spec.ts`

```ts
import { expect, test } from '@playwright/test'

test('홈 페이지에 제목이 보인다', async ({ page }) => {
  await page.goto('/')

  await expect(page.getByRole('heading', { name: 'Nuxt 3 학습' })).toBeVisible()
})
```

실행한다.

```bash
npx playwright test
```

`package.json`에 명령을 추가해도 좋다.

```json
{
  "scripts": {
    "test:e2e": "playwright test"
  }
}
```

## 로그인 흐름 테스트 예시

```ts
import { expect, test } from '@playwright/test'

test('로그인 후 대시보드로 이동한다', async ({ page }) => {
  await page.goto('/login')

  await page.getByLabel('이메일').fill('user@example.com')
  await page.getByLabel('비밀번호').fill('password')
  await page.getByRole('button', { name: '로그인' }).click()

  await expect(page).toHaveURL(/\/dashboard/)
  await expect(page.getByRole('heading', { name: '대시보드' })).toBeVisible()
})
```

E2E 테스트는 사용자가 실제로 보는 label, button, heading을 기준으로 작성하면 좋다.

## 좋은 E2E 테스트 대상

모든 것을 E2E로 테스트할 필요는 없다.

E2E 테스트는 느리고 환경 영향을 많이 받는다. 핵심 사용자 흐름 위주로 작성한다.

좋은 대상은 다음과 같다.

- 회원가입
- 로그인과 로그아웃
- 상품 검색과 상세 보기
- 장바구니 담기
- 결제 직전 흐름
- 게시글 작성
- 관리자 주요 작업

## 단위 테스트와 E2E 테스트의 균형

테스트는 여러 층으로 나누어 생각한다.

| 테스트 | 특징 |
| --- | --- |
| 단위 테스트 | 빠르고 작은 로직 확인 |
| 컴포넌트 테스트 | 화면 조각 확인 |
| E2E 테스트 | 실제 사용자 흐름 확인 |

가능하면 많은 로직은 단위 테스트로 빠르게 확인하고, 정말 중요한 흐름만 E2E로 확인한다.

## 자주 하는 실수

E2E 테스트에서 CSS 선택자에 과하게 의존하는 실수가 많다.

```ts
await page.locator('.btn-login').click()
```

가능하면 사용자가 인식하는 역할과 이름으로 찾는 것이 좋다.

```ts
await page.getByRole('button', { name: '로그인' }).click()
```

이 방식은 접근성에도 좋은 영향을 준다.

## 정리

E2E 테스트는 실제 브라우저에서 사용자 흐름을 확인하는 테스트다. Playwright의 `webServer` 설정을 사용하면 테스트 전에 Nuxt 서버를 실행하고, `baseURL`로 상대 경로 테스트를 쉽게 작성할 수 있다.
