## 공통 컴포넌트란

공통 컴포넌트는 여러 화면에서 반복해서 사용하는 UI 조각이다.

예를 들어 다음은 공통 컴포넌트로 만들기 좋다.

- 버튼
- 입력 필드
- 체크박스
- 모달
- 탭
- 카드
- 페이지 제목
- 로딩 표시
- 에러 메시지

공통 컴포넌트를 잘 만들면 UI 일관성이 높아지고, 수정 비용이 줄어든다.

## Base 컴포넌트

Base 컴포넌트는 앱 전체에서 재사용하는 가장 낮은 수준의 UI다.

```txt
components/
  base/
    BaseButton.vue
    BaseInput.vue
    BaseModal.vue
```

Base 컴포넌트는 특정 도메인에 의존하지 않는 것이 좋다.

예를 들어 `BaseButton`은 게시글, 상품, 관리자 같은 단어를 몰라야 한다.

## 도메인 컴포넌트

도메인 컴포넌트는 특정 기능에 가까운 컴포넌트다.

```txt
components/
  posts/
    PostCard.vue
    PostEditor.vue
  products/
    ProductCard.vue
```

`PostCard`는 게시글 제목, 작성일, 태그 같은 게시글 도메인 정보를 알아도 된다.

Base 컴포넌트와 도메인 컴포넌트를 구분하면 역할이 선명해진다.

## BaseButton 예시

```vue
<script setup lang="ts">
withDefaults(defineProps<{
  type?: 'button' | 'submit' | 'reset'
  variant?: 'primary' | 'secondary' | 'danger'
  disabled?: boolean
}>(), {
  type: 'button',
  variant: 'primary',
  disabled: false
})
</script>

<template>
  <button
    :type="type"
    :disabled="disabled"
    :class="['button', `button--${variant}`]"
  >
    <slot />
  </button>
</template>
```

버튼 텍스트는 slot으로 받는다.

```vue
<BaseButton variant="primary">
  저장
</BaseButton>
```

## props를 늘리기 전에 생각하기

공통 컴포넌트에 props를 너무 많이 넣으면 복잡해진다.

예를 들어 버튼에 다음 props가 계속 늘어날 수 있다.

```txt
color
size
rounded
shadow
icon
loading
block
outline
```

props가 많아지면 사용법이 어려워진다.

정말 자주 쓰는 변형만 props로 만들고, 복잡한 조합은 별도 컴포넌트나 slot으로 해결하는 것이 좋다.

## BaseInput 예시

```vue
<script setup lang="ts">
defineProps<{
  label: string
  error?: string
}>()

const model = defineModel<string>()
</script>

<template>
  <label>
    <span>{{ label }}</span>
    <input v-model="model" />
  </label>
  <p v-if="error">{{ error }}</p>
</template>
```

사용 예시:

```vue
<script setup>
const email = ref('')
</script>

<template>
  <BaseInput
    v-model="email"
    label="이메일"
    error="이메일을 입력해 주세요."
  />
</template>
```

입력 컴포넌트는 접근성과 폼 검증 메시지를 함께 고려해야 한다.

## Modal 설계

모달은 slot을 적극 활용하는 것이 좋다.

```vue
<script setup lang="ts">
defineProps<{
  open: boolean
}>()

defineEmits<{
  close: []
}>()
</script>

<template>
  <div v-if="open" class="modal">
    <div class="modal__panel">
      <header>
        <slot name="title" />
      </header>

      <section>
        <slot />
      </section>

      <footer>
        <slot name="footer" />
      </footer>
    </div>
  </div>
</template>
```

모달은 키보드 접근성, 포커스 이동, ESC 닫기, 배경 스크롤 잠금까지 고려해야 한다.

실무에서는 Headless UI 같은 접근성 중심 라이브러리를 사용하는 것도 좋다.

## 공통 컴포넌트 문서화

공통 컴포넌트가 많아지면 사용법을 문서화해야 한다.

문서에 포함할 내용은 다음과 같다.

- 컴포넌트 목적
- props 목록
- slot 목록
- 사용 예시
- 금지된 사용법

작은 프로젝트라면 README나 간단한 Markdown 문서만으로도 충분하다.

## 자주 하는 실수

너무 이른 추상화가 자주 생긴다.

한 번만 쓰는 UI를 공통 컴포넌트로 만들면 오히려 복잡해진다.

반복이 보이고, 역할이 분명해졌을 때 공통 컴포넌트로 분리하는 것이 좋다.

또 공통 컴포넌트에 특정 페이지 로직이 들어가면 재사용성이 떨어진다.

## 정리

공통 컴포넌트는 UI 일관성과 재사용성을 높인다. Base 컴포넌트는 도메인에 의존하지 않게 만들고, 도메인 컴포넌트는 특정 기능의 맥락을 담는다. props는 필요한 만큼만 열고, 내용 확장은 slot으로 처리하면 유연하다.
