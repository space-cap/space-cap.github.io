# 라우트 미들웨어

## 이번 장에서 배울 것

- 라우트 미들웨어가 무엇인지
- 페이지 이동 전에 조건을 검사하는 방법
- named middleware와 global middleware의 차이
- 로그인 페이지 보호의 기본 흐름

## 라우트 미들웨어란

라우트 미들웨어는 페이지로 이동하기 전에 실행되는 함수다.

예를 들어 사용자가 `/dashboard`로 이동하려고 할 때, 로그인했는지 먼저 확인하고 싶을 수 있다.

- 로그인 상태라면 `/dashboard`로 이동
- 로그인하지 않았다면 `/login`으로 이동

이런 일을 라우트 미들웨어로 처리할 수 있다.

## middleware 폴더

Nuxt에서는 프로젝트 루트에 `middleware` 폴더를 만들고 미들웨어 파일을 넣는다.

```txt
middleware/
  auth.ts
```

`middleware/auth.ts`를 작성해 보자.

```ts
export default defineNuxtRouteMiddleware((to, from) => {
  const isLoggedIn = false

  if (!isLoggedIn) {
    return navigateTo('/login')
  }
})
```

이 예제에서는 항상 로그인하지 않은 상태로 처리하므로 `/login`으로 이동한다.

## 페이지에 미들웨어 적용하기

보호하고 싶은 페이지에서 `definePageMeta`를 사용한다.

```vue
<script setup>
definePageMeta({
  middleware: 'auth'
})
</script>

<template>
  <main>
    <h1>대시보드</h1>
    <p>로그인한 사용자만 볼 수 있는 페이지입니다.</p>
  </main>
</template>
```

여기서 `'auth'`는 `middleware/auth.ts` 파일을 의미한다.

## inline middleware

간단한 조건은 페이지 안에 직접 작성할 수도 있다.

```vue
<script setup>
definePageMeta({
  middleware: (to, from) => {
    const canAccess = false

    if (!canAccess) {
      return navigateTo('/')
    }
  }
})
</script>
```

하지만 여러 페이지에서 재사용할 조건이라면 `middleware` 폴더로 분리하는 것이 좋다.

## global middleware

모든 라우트 이동마다 실행하고 싶은 미들웨어는 파일 이름에 `.global`을 붙인다.

```txt
middleware/
  logging.global.ts
```

```ts
export default defineNuxtRouteMiddleware((to, from) => {
  console.log('이동할 주소:', to.path)
})
```

전역 미들웨어는 모든 페이지 이동에서 실행되므로 가볍게 작성해야 한다.

## 미들웨어에서 자주 하는 일

라우트 미들웨어에서는 다음 일을 자주 한다.

- 로그인 여부 확인
- 관리자 권한 확인
- 잘못된 접근 리다이렉트
- 특정 페이지 접근 로그 기록
- 온보딩 완료 여부 확인

단, 무거운 API 호출이나 복잡한 계산을 모든 이동마다 실행하면 페이지 이동이 느려질 수 있다.

## 자주 하는 실수

미들웨어 안에서 브라우저 전용 기능을 바로 사용하는 실수를 조심해야 한다.

Nuxt의 미들웨어는 서버 렌더링 과정에서도 실행될 수 있다. 그래서 `window`, `localStorage` 같은 브라우저 전용 객체를 사용할 때는 클라이언트에서만 실행되도록 주의해야 한다.

또 `navigateTo`를 호출할 때는 `return navigateTo(...)`처럼 반환하는 습관이 좋다.

## 정리

라우트 미들웨어는 페이지로 이동하기 전에 조건을 검사하는 기능이다. 로그인 보호, 권한 확인, 리다이렉트 처리에 자주 사용한다.
