# 환경별 설정 관리

## 이번 장에서 배울 것

- development, staging, production의 차이
- `.env` 파일의 역할과 한계
- runtimeConfig와 환경 변수 연결
- 공개 설정과 비밀 설정을 구분하는 방법

## 환경이란

웹 앱은 보통 여러 환경에서 실행된다.

| 환경 | 의미 |
| --- | --- |
| development | 개발자 로컬 환경 |
| staging | 운영 전 검증 환경 |
| production | 실제 사용자 운영 환경 |

환경마다 API 주소, 로그 수준, 인증 키, 외부 서비스 설정이 달라질 수 있다.

## .env 파일

개발 중에는 `.env` 파일에 환경 변수를 적을 수 있다.

```txt
NUXT_PUBLIC_API_BASE=http://localhost:3001
NUXT_API_SECRET=local-secret
```

Nuxt CLI는 개발, build, generate 과정에서 `.env` 파일을 읽을 수 있다.

하지만 중요한 점이 있다.

빌드된 서버를 운영 환경에서 실행할 때 `.env` 파일이 자동으로 읽히는 것은 아니다.

운영 환경에서는 배포 플랫폼의 환경 변수 설정을 사용해야 한다.

## runtimeConfig에 정의하기

Nuxt에서 환경 값을 앱에 노출하려면 `runtimeConfig`에 구조를 정의한다.

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '',
    public: {
      apiBase: ''
    }
  }
})
```

환경 변수 이름은 이 구조와 맞춰야 한다.

```txt
NUXT_API_SECRET=secret-value
NUXT_PUBLIC_API_BASE=https://api.example.com
```

Nuxt는 `NUXT_`로 시작하고 구조에 맞는 환경 변수를 runtime config에 연결할 수 있다.

## 공개 설정과 비밀 설정

`runtimeConfig.public` 안의 값은 클라이언트에도 노출될 수 있다.

```ts
runtimeConfig: {
  public: {
    apiBase: ''
  }
}
```

반대로 public 밖의 값은 서버 전용으로 다룬다.

```ts
runtimeConfig: {
  apiSecret: ''
}
```

API secret, DB 비밀번호, private token은 public 안에 넣으면 안 된다.

## 환경별 값 예시

development:

```txt
NUXT_PUBLIC_API_BASE=http://localhost:3001
```

staging:

```txt
NUXT_PUBLIC_API_BASE=https://staging-api.example.com
```

production:

```txt
NUXT_PUBLIC_API_BASE=https://api.example.com
```

같은 코드라도 환경 변수 값이 달라지면 다른 API 서버를 바라보게 만들 수 있다.

## process.env를 직접 쓰는 문제

Nuxt 앱 코드에서 `process.env.MY_VALUE`를 직접 많이 사용하는 것은 피하는 것이 좋다.

특히 runtime에 바뀌어야 하는 값은 `runtimeConfig`를 통해 접근한다.

```ts
const config = useRuntimeConfig()

const apiBase = config.public.apiBase
```

공식 문서에서도 runtime config에 정의된 값과 `NUXT_` 접두사 환경 변수를 연결하는 방식을 권장한다.

## 서버 API에서 runtimeConfig 읽기

서버 route에서는 `event`를 전달해 runtime config를 읽을 수 있다.

```ts
export default defineEventHandler((event) => {
  const config = useRuntimeConfig(event)

  return {
    apiBase: config.public.apiBase
  }
})
```

서버 route에서는 런타임에 덮어쓴 환경 변수를 정확히 반영하기 위해 `event`를 전달하는 방식이 권장된다.

## 배포 플랫폼에서 설정하기

Vercel, Netlify 같은 플랫폼은 대시보드에서 환경 변수를 등록한다.

보통 환경별로 다르게 설정할 수 있다.

- Development
- Preview
- Production

운영 배포 전에 Preview 환경에서 값이 올바르게 들어갔는지 확인하는 것이 좋다.

## 자주 하는 실수

로컬 `.env` 파일을 만들었으니 운영에서도 자동 적용될 것이라고 생각하는 실수가 많다.

운영 환경에서는 플랫폼의 환경 변수 설정을 사용해야 한다.

또 비밀 값을 `NUXT_PUBLIC_` 접두사로 등록하는 실수도 위험하다. `NUXT_PUBLIC_` 값은 클라이언트로 노출될 수 있다.

## 정리

환경별 설정은 `runtimeConfig`와 `NUXT_` 환경 변수를 중심으로 관리한다. 로컬 `.env`는 개발과 빌드에 도움을 주지만, 운영 런타임에서는 배포 플랫폼의 환경 변수 설정을 사용해야 한다.
