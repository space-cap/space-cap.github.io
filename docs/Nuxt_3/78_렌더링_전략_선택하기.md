# 렌더링 전략 선택하기

## 이번 장에서 배울 것

- Universal Rendering, CSR, SSG, ISR의 차이
- 페이지 성격에 맞는 렌더링 전략
- `routeRules` 사용 예시
- 잘못된 렌더링 전략 선택에서 생기는 문제

## 렌더링 전략이 중요한 이유

Nuxt는 여러 렌더링 방식을 지원한다.

하지만 모든 페이지에 같은 방식이 최선은 아니다.

예를 들어 블로그 글은 미리 만들어 두면 빠르고 좋다. 하지만 사용자별 마이페이지를 미리 만들어 두면 안 된다. 사용자마다 내용이 다르기 때문이다.

렌더링 전략은 페이지의 성격에 맞게 선택해야 한다.

## Universal Rendering

Nuxt의 기본 렌더링 방식은 Universal Rendering이다.

서버가 먼저 HTML을 만들고, 브라우저가 JavaScript를 받아 hydration을 수행한다.

장점은 다음과 같다.

- 첫 화면에 내용이 빨리 보일 수 있다.
- SEO에 유리하다.
- 서버에서 데이터가 준비된 HTML을 줄 수 있다.

주의할 점도 있다.

- 코드는 서버와 클라이언트 양쪽에서 실행될 수 있다.
- `window`, `document`, `localStorage` 같은 브라우저 전용 API를 조심해야 한다.
- 서버 운영 비용이 생길 수 있다.

## CSR

CSR은 Client-Side Rendering이다.

브라우저에서 JavaScript가 실행된 뒤 화면을 만든다.

Nuxt 전체를 CSR로 바꾸려면 다음처럼 설정한다.

```ts
export default defineNuxtConfig({
  ssr: false
})
```

특정 route만 CSR로 만들 수도 있다.

```ts
export default defineNuxtConfig({
  routeRules: {
    '/admin/**': {
      ssr: false
    }
  }
})
```

관리자 페이지처럼 SEO가 중요하지 않고 브라우저 기능 중심인 화면에 사용할 수 있다.

## SSG

SSG는 빌드 시점에 HTML을 미리 만드는 방식이다.

정적인 공개 페이지에 잘 어울린다.

```ts
export default defineNuxtConfig({
  routeRules: {
    '/': {
      prerender: true
    },
    '/about': {
      prerender: true
    }
  }
})
```

블로그, 문서, 회사 소개 페이지처럼 모든 사용자에게 같은 내용을 보여 주는 페이지에 적합하다.

## ISR

ISR은 Incremental Static Regeneration의 개념이다.

정적 페이지처럼 캐시하면서, 일정 시간이 지나면 다시 생성할 수 있다.

```ts
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': {
      isr: 3600
    }
  }
})
```

이 예시는 블로그 페이지를 일정 시간 동안 캐시하고, 시간이 지나면 새로 생성하는 전략으로 볼 수 있다.

ISR 지원 여부와 동작 방식은 배포 플랫폼에 따라 달라질 수 있다.

## routeRules 예시

한 앱 안에서 여러 전략을 섞을 수 있다.

```ts
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },
    '/blog/**': { isr: 3600 },
    '/admin/**': { ssr: false },
    '/api/**': {
      headers: {
        'cache-control': 'no-store'
      }
    }
  }
})
```

이런 방식을 하이브리드 렌더링이라고 이해할 수 있다.

Nuxt의 강점은 페이지마다 다른 전략을 선택할 수 있다는 점이다.

## 페이지별 선택 기준

| 페이지 | 추천 전략 |
| --- | --- |
| 홈 | SSG 또는 SSR |
| 회사 소개 | SSG |
| 블로그 글 | SSG 또는 ISR |
| 상품 목록 | SSR, ISR, CSR 중 요구사항에 따라 선택 |
| 상품 상세 | SSR 또는 ISR |
| 관리자 페이지 | CSR |
| 마이페이지 | SSR 또는 CSR |
| 로그인 페이지 | SSR 또는 CSR |

정답은 프로젝트마다 다르다. 데이터가 얼마나 자주 바뀌는지, 사용자별 내용인지, SEO가 중요한지에 따라 결정한다.

## 선택 질문

렌더링 전략을 고르기 전에 다음 질문을 해 보자.

- 이 페이지는 검색 엔진에 노출되어야 하는가?
- 모든 사용자에게 같은 내용을 보여 주는가?
- 데이터가 자주 바뀌는가?
- 로그인한 사용자만 보는 페이지인가?
- 첫 화면 속도가 중요한가?
- 서버 비용을 줄여야 하는가?

이 질문의 답이 렌더링 전략을 결정하는 데 도움이 된다.

## 자주 하는 실수

로그인 사용자별 페이지를 정적으로 생성하는 실수를 조심해야 한다.

정적 HTML은 모든 사용자에게 같은 결과를 제공한다. 사용자별 데이터는 서버에서 매번 검증하거나 클라이언트에서 인증 후 가져오는 방식이 필요하다.

또 SEO가 중요한 블로그를 CSR로만 만들면 검색 노출에 불리할 수 있다.

## 정리

Nuxt는 Universal Rendering, CSR, SSG, ISR 같은 여러 렌더링 전략을 지원한다. `routeRules`를 사용하면 페이지별로 전략을 다르게 적용할 수 있다. 페이지의 데이터 성격과 SEO 요구사항에 맞게 선택해야 한다.
