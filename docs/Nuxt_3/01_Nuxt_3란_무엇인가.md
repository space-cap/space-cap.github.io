# Nuxt 3란 무엇인가

## 이번 장에서 배울 것

- Nuxt 3가 무엇인지
- Nuxt가 Vue와 어떤 관계인지
- Nuxt를 사용하면 무엇이 편해지는지
- Vue만 사용할 때와 Nuxt를 사용할 때의 차이

## Nuxt 3를 한 문장으로 말하면

Nuxt 3는 Vue.js로 웹 애플리케이션을 더 쉽게 만들 수 있게 도와주는 프레임워크다.

Vue는 화면을 컴포넌트로 만들고 반응형 데이터를 다루는 데 강하다. 하지만 실제 서비스를 만들다 보면 화면만으로는 부족하다.

- 페이지 주소를 어떻게 나눌까?
- 서버에서 미리 HTML을 만들어야 할까?
- 검색 엔진에 잘 보이게 하려면 어떻게 해야 할까?
- API 서버는 어디에 만들까?
- 로그인 상태는 어떻게 유지할까?
- 배포할 때는 무엇을 빌드해야 할까?

Nuxt는 이런 문제를 미리 정리해 둔 Vue 기반의 애플리케이션 프레임워크다.

## 라이브러리와 프레임워크

처음에는 "라이브러리"와 "프레임워크"라는 말이 헷갈릴 수 있다.

라이브러리는 내가 필요할 때 가져다 쓰는 도구에 가깝다. Vue도 화면을 만드는 핵심 기능만 놓고 보면 라이브러리처럼 사용할 수 있다.

프레임워크는 애플리케이션을 만드는 큰 틀을 제공한다. 어디에 페이지를 만들고, 어디에 컴포넌트를 두고, 서버 코드는 어디에 쓰는지 같은 구조를 정해 준다.

Nuxt는 Vue를 기반으로 하면서 프로젝트 구조, 라우팅, 서버 렌더링, 데이터 가져오기, 서버 API, 배포 방식까지 한 번에 다루는 프레임워크다.

## Nuxt가 해결해 주는 일

Nuxt를 사용하면 다음과 같은 기능을 기본 흐름 안에서 사용할 수 있다.

- 파일을 만들면 주소가 자동으로 생기는 파일 기반 라우팅
- 공통 화면 구조를 관리하는 레이아웃
- 컴포넌트 자동 등록
- 서버에서 미리 HTML을 만드는 SSR
- 정적 페이지를 미리 만들어 두는 SSG
- API 서버를 만들 수 있는 서버 라우트
- SEO를 위한 메타 태그 관리
- 환경 변수와 런타임 설정
- 모듈을 통한 기능 확장
- 배포 환경에 맞춘 빌드

Vue로도 이런 기능을 직접 구성할 수 있다. 하지만 Nuxt는 자주 쓰는 구성을 한곳에 모아 두었기 때문에 시작 속도가 빠르고 프로젝트 구조가 일정해진다.

## Nuxt 3의 핵심 특징

Nuxt 3는 Vue 3를 기반으로 한다. 그래서 `<script setup>`, Composition API, Vue의 반응성 시스템을 자연스럽게 사용한다.

또한 Nuxt 3는 Nitro라는 서버 엔진을 사용한다. Nitro 덕분에 Nuxt 앱은 Node 서버, 서버리스, 엣지 환경, 정적 사이트 등 여러 배포 방식에 대응할 수 있다.

초보자 입장에서 가장 먼저 기억할 특징은 다음 세 가지다.

- `pages` 폴더에 파일을 만들면 페이지 주소가 자동으로 생긴다.
- 서버에서 HTML을 미리 만들 수 있어 SEO와 초기 로딩에 유리하다.
- `server` 폴더 안에 API를 만들 수 있어 작은 풀스택 앱도 만들 수 있다.

## 언제 Nuxt를 사용하면 좋을까

Nuxt는 다음과 같은 프로젝트에 잘 어울린다.

- 블로그, 문서 사이트, 회사 소개 사이트처럼 검색 노출이 중요한 사이트
- 게시판, 쇼핑몰, 관리자 페이지처럼 여러 페이지가 있는 서비스
- Vue를 쓰면서 라우팅, SEO, 배포 구조를 한 번에 정리하고 싶은 프로젝트
- 프론트엔드와 간단한 서버 API를 한 프로젝트 안에서 만들고 싶은 경우

반대로 아주 작은 위젯 하나만 만들거나, 기존 페이지 일부에 Vue를 살짝 붙이는 정도라면 Nuxt까지 필요하지 않을 수 있다.

## 정리

Nuxt 3는 Vue 3 기반의 웹 애플리케이션 프레임워크다. Vue가 화면을 잘 만들게 해 준다면, Nuxt는 그 화면들을 실제 서비스 구조로 묶어 준다.

라우팅, 렌더링, 데이터 가져오기, 서버 API, SEO, 배포처럼 서비스에 필요한 반복적인 결정을 Nuxt가 기본 구조로 제공한다.
