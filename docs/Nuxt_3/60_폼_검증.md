# 폼 검증

## 이번 장에서 배울 것

- 폼 검증이 필요한 이유
- 클라이언트 검증과 서버 검증의 차이
- 간단한 직접 검증 예시
- VeeValidate 같은 검증 라이브러리 선택 기준

## 폼 검증이란

폼 검증은 사용자가 입력한 값이 올바른지 확인하는 과정이다.

예를 들어 회원가입 폼에는 다음 검증이 필요할 수 있다.

- 이메일 형식이 올바른가?
- 비밀번호가 너무 짧지 않은가?
- 필수 입력값이 비어 있지 않은가?
- 비밀번호와 비밀번호 확인이 같은가?
- 이미 사용 중인 이메일은 아닌가?

검증을 잘하면 사용자가 실수를 빨리 고칠 수 있고, 서버도 잘못된 데이터를 덜 받게 된다.

## 클라이언트 검증과 서버 검증

검증은 클라이언트와 서버 양쪽에서 해야 한다.

클라이언트 검증은 사용자 경험을 위한 것이다.

사용자가 제출하기 전에 바로 오류를 보여 줄 수 있다.

서버 검증은 보안을 위한 것이다.

브라우저 코드는 사용자가 조작할 수 있으므로 서버는 클라이언트 검증을 믿으면 안 된다.

| 구분 | 목적 |
| --- | --- |
| 클라이언트 검증 | 빠른 피드백, UX 개선 |
| 서버 검증 | 데이터 보호, 보안, 최종 검증 |

## 직접 검증 예시

작은 폼은 직접 검증해도 된다.

```vue
<script setup>
const email = ref('')
const password = ref('')
const errors = ref({})

const validate = () => {
  const nextErrors = {}

  if (!email.value) {
    nextErrors.email = '이메일을 입력해 주세요.'
  } else if (!email.value.includes('@')) {
    nextErrors.email = '이메일 형식이 올바르지 않습니다.'
  }

  if (!password.value) {
    nextErrors.password = '비밀번호를 입력해 주세요.'
  } else if (password.value.length < 8) {
    nextErrors.password = '비밀번호는 8자 이상이어야 합니다.'
  }

  errors.value = nextErrors

  return Object.keys(nextErrors).length === 0
}

const submit = async () => {
  if (!validate()) {
    return
  }

  await $fetch('/api/auth/register', {
    method: 'POST',
    body: {
      email: email.value,
      password: password.value
    }
  })
}
</script>

<template>
  <form @submit.prevent="submit">
    <label>
      이메일
      <input v-model="email" type="email" />
    </label>
    <p v-if="errors.email">{{ errors.email }}</p>

    <label>
      비밀번호
      <input v-model="password" type="password" />
    </label>
    <p v-if="errors.password">{{ errors.password }}</p>

    <button type="submit">가입</button>
  </form>
</template>
```

초보 단계에서는 이 방식만으로도 검증의 흐름을 이해할 수 있다.

## 서버에서도 검증하기

서버 API에서도 같은 핵심 검증을 해야 한다.

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  if (!body.email || !body.email.includes('@')) {
    throw createError({
      statusCode: 400,
      statusMessage: '이메일 형식이 올바르지 않습니다.'
    })
  }

  if (!body.password || body.password.length < 8) {
    throw createError({
      statusCode: 400,
      statusMessage: '비밀번호는 8자 이상이어야 합니다.'
    })
  }

  return {
    ok: true
  }
})
```

서버 검증은 절대 생략하면 안 된다.

## VeeValidate

폼이 복잡해지면 직접 검증 코드가 길어진다.

이럴 때 VeeValidate 같은 검증 라이브러리를 사용할 수 있다.

Nuxt 통합 모듈은 다음처럼 설치할 수 있다.

```bash
npm i @vee-validate/nuxt
```

`nuxt.config.ts`에 등록한다.

```ts
export default defineNuxtConfig({
  modules: ['@vee-validate/nuxt']
})
```

VeeValidate Nuxt 모듈은 VeeValidate 컴포넌트와 composable 자동 import를 제공한다.

## 스키마 검증

실무에서는 Zod, Yup, Valibot 같은 스키마 검증 라이브러리를 함께 쓰는 경우가 많다.

스키마 검증은 입력값의 규칙을 객체 형태로 정의하고, 클라이언트와 서버에서 비슷한 규칙을 공유하는 데 도움이 된다.

예를 들어 다음 같은 규칙을 만들 수 있다.

```ts
const registerSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8)
})
```

이 문서에서는 개념만 소개한다. 실제 도입은 사용하는 검증 라이브러리의 공식 문서를 확인하며 진행한다.

## 좋은 오류 메시지

검증 오류 메시지는 사용자가 바로 고칠 수 있게 작성한다.

좋지 않은 메시지:

```txt
Invalid value
```

좋은 메시지:

```txt
이메일 형식이 올바르지 않습니다.
비밀번호는 8자 이상이어야 합니다.
```

오류 메시지는 짧고 구체적이어야 한다.

## 자주 하는 실수

클라이언트 검증만 하고 서버 검증을 생략하는 실수가 가장 위험하다.

또 검증 오류를 alert로만 보여 주면 사용자가 어떤 필드를 고쳐야 하는지 찾기 어렵다. 가능하면 입력 필드 가까이에 오류 메시지를 보여 준다.

## 정리

폼 검증은 클라이언트와 서버 양쪽에서 필요하다. 작은 폼은 직접 검증해도 되고, 복잡한 폼은 VeeValidate나 스키마 검증 라이브러리를 사용할 수 있다. 서버 검증은 보안을 위해 반드시 필요하다.
