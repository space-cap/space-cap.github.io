# ERP 기본과 업무 프로세스

> 목표: ERP가 무엇을 관리하는 시스템인지 이해하고, 수주·발주·재고·생산·회계의 기본 흐름을 익힌다.

## 1. ERP란 무엇인가

ERP는 `Enterprise Resource Planning`의 약자다. 한국어로는 전사적 자원관리라고 부른다.

쉽게 말하면 회사의 돈, 물건, 사람, 거래, 생산 정보를 하나의 기준으로 관리하는 시스템이다.

ERP가 없으면 부서마다 엑셀을 따로 관리하게 된다.

- 영업팀은 수주 엑셀
- 물류팀은 출고 엑셀
- 구매팀은 발주 엑셀
- 생산팀은 생산계획 엑셀
- 회계팀은 매출과 입금 엑셀

처음에는 괜찮아 보이지만 회사가 커질수록 숫자가 맞지 않는다. ERP는 이 문제를 줄이기 위해 업무 데이터를 한곳에 모은다.

## 2. ERP의 핵심은 기준정보다

ERP에서 가장 먼저 잡아야 할 것은 기준정보다. 기준정보는 다른 업무 데이터의 기준이 되는 정보다.

| 기준정보 | 의미 | 예시 |
| --- | --- | --- |
| 거래처 | 물건을 사고파는 상대 | 고객사, 공급사, 대리점 |
| 품목 | 판매하거나 구매하거나 생산하는 물건 | 원자재, 반제품, 완제품, 상품 |
| 창고 | 재고가 존재하는 장소 | 본사창고, 공장창고, 매장창고 |
| 사원 | 시스템 사용자 또는 담당자 | 영업담당, 구매담당, 생산담당 |
| 계정과목 | 회계 처리 기준 | 매출, 매입, 외상매출금, 부가세 |
| 부서 | 조직 단위 | 영업팀, 생산팀, 구매팀 |
| 단가 | 거래 가격 기준 | 거래처별 단가, 품목별 단가 |

기준정보가 틀리면 이후 모든 업무 데이터가 흔들린다.

예를 들어 품목 코드가 중복되면 재고가 나뉘어 보이고, 거래처가 중복되면 미수금이 나뉘어 보인다.

## 3. 영업 흐름: 견적에서 수금까지

ERP의 대표 흐름은 영업 흐름이다.

```text
견적 -> 수주 -> 출고 -> 매출 -> 세금계산서 -> 수금
```

### 3.1 견적

고객에게 판매 조건과 가격을 제시하는 단계다.

주요 데이터는 다음과 같다.

- 거래처
- 품목
- 수량
- 단가
- 납기
- 유효기간

### 3.2 수주

고객이 실제 주문한 내용을 등록하는 단계다.

수주는 이후 출고, 생산계획, 구매계획의 출발점이 될 수 있다.

### 3.3 출고

창고에서 고객에게 물건을 내보내는 단계다.

출고가 되면 보통 재고가 줄어든다. 택배 연동이 있으면 송장번호도 함께 관리한다.

### 3.4 매출

출고한 물건을 회계상 매출로 인식하는 단계다.

업무 방식에 따라 출고와 매출이 동시에 처리되기도 하고, 별도 승인 후 매출 처리되기도 한다.

### 3.5 수금

고객이 돈을 입금한 것을 등록하는 단계다.

매출은 발생했지만 아직 돈을 받지 못한 금액을 `미수금`이라고 한다.

## 4. 구매 흐름: 발주에서 지급까지

구매 흐름은 회사가 필요한 물건을 사는 과정이다.

```text
구매요청 -> 발주 -> 입고 -> 매입 -> 지급
```

### 4.1 발주

공급사에게 품목, 수량, 단가, 납기를 정해 구매를 요청한다.

### 4.2 입고

공급사에서 물건이 들어오면 입고 처리한다. 입고가 되면 재고가 늘어난다.

### 4.3 매입

입고된 물건을 회계상 매입으로 인식한다.

### 4.4 지급

공급사에게 대금을 지급한다. 매입은 되었지만 아직 돈을 지급하지 않은 금액을 `미지급금`이라고 한다.

## 5. 재고 흐름

재고는 ERP에서 가장 민감한 영역 중 하나다.

재고는 단순히 현재 수량만 보는 것이 아니라, 왜 늘고 줄었는지를 함께 봐야 한다.

| 재고 이벤트 | 재고 변화 | 설명 |
| --- | --- | --- |
| 구매 입고 | 증가 | 공급사에서 물건이 들어옴 |
| 판매 출고 | 감소 | 고객에게 물건이 나감 |
| 창고 이동 | 한 창고 감소, 다른 창고 증가 | 장소만 바뀜 |
| 생산 투입 | 원자재 감소 | 생산에 원자재 사용 |
| 생산 입고 | 완제품 증가 | 생산 완료품 입고 |
| 실사 조정 | 증가 또는 감소 | 실제 수량에 맞춤 |
| 반품 | 증가 또는 감소 | 판매 반품, 구매 반품 |

재고 문의가 들어오면 "현재 수량이 얼마인가"보다 "어떤 이벤트 때문에 이 수량이 되었는가"를 추적해야 한다.

## 6. 생산 흐름

제조업 ERP에서는 생산 흐름이 중요하다.

```text
BOM 등록 -> 생산계획 -> 작업지시 -> 자재출고 -> 생산실적 -> 제품입고 -> 원가계산
```

### 6.1 BOM

`BOM(Bill of Materials)`은 제품을 만들기 위해 필요한 자재 목록이다.

예를 들어 완제품 A를 만들기 위해 원자재 B 2개, 원자재 C 3개가 필요하다면 이것이 BOM이다.

### 6.2 생산계획

언제, 어떤 제품을, 얼마나 만들지 계획한다.

수주를 기반으로 생산계획을 만들 수도 있고, 예상 판매량을 기반으로 만들 수도 있다.

### 6.3 작업지시

현장에 실제 작업을 지시한다.

MES가 있는 회사라면 ERP의 생산계획이나 작업지시가 MES로 내려가고, MES의 생산실적이 ERP로 올라오는 구조가 많다.

### 6.4 생산실적

실제로 얼마나 생산했는지 등록한다.

생산실적은 재고, 원가, 품질, 납기 분석에 영향을 준다.

## 7. 회계 흐름

ERP에서 회계는 모든 업무의 결과를 돈의 언어로 정리하는 영역이다.

개발자가 회계 전문가가 될 필요는 없지만, 기본 용어는 알아야 한다.

| 용어 | 의미 |
| --- | --- |
| 전표 | 회계 거래를 기록하는 단위 |
| 계정과목 | 거래를 분류하는 회계 항목 |
| 매출 | 상품이나 서비스를 팔아 발생한 금액 |
| 매입 | 상품이나 원재료를 사며 발생한 금액 |
| 미수금 | 받을 돈 |
| 미지급금 | 줄 돈 |
| 부가세 | 거래에 붙는 세금 |
| 결산 | 일정 기간의 회계 결과를 확정하는 작업 |

ERP에서는 영업, 구매, 재고, 생산 데이터가 회계 전표와 연결될 수 있다. 그래서 업무 데이터가 틀리면 회계 결과도 틀어질 수 있다.

## 8. ERP 개발자가 자주 만나는 화면

입사 초기에 다음 화면 이름을 자주 보게 될 수 있다.

- 거래처 등록
- 품목 등록
- 견적 등록
- 수주 등록
- 출고 등록
- 매출 등록
- 발주 등록
- 입고 등록
- 재고 현황
- 거래처별 원장
- 매입매출장
- 생산계획 등록
- 작업지시 등록
- 생산실적 등록
- 전표 입력
- 세금계산서 조회

화면을 볼 때는 이 화면이 `기준정보`, `업무 이벤트`, `조회/집계`, `출력/연동` 중 어디에 속하는지 분류해 보면 이해가 빨라진다.

## 9. ERP 개발자가 자주 만나는 요청

### 9.1 검색 조건 추가

"거래처명으로도 검색되게 해 주세요", "출고일 기준으로 조회되게 해 주세요" 같은 요청이다.

확인할 것은 다음이다.

- 검색 조건이 DB 컬럼에 있는가
- 인덱스가 필요한가
- 날짜 기준이 등록일인지 처리일인지 전표일자인지
- 권한에 따라 조회 범위가 달라지는지

### 9.2 항목 추가

"품목에 유통기한 관리 여부를 추가해 주세요" 같은 요청이다.

화면만 바꾸면 끝나지 않는다.

- DB 컬럼
- 저장 로직
- 조회 화면
- 엑셀 다운로드
- 출력물
- 연동 데이터
- 기존 데이터 기본값

영향 범위를 같이 봐야 한다.

### 9.3 숫자가 안 맞는다는 문의

"재고가 안 맞아요", "미수금이 안 맞아요"는 ERP에서 가장 흔한 문의다.

이때는 최종 집계 결과보다 원천 데이터를 먼저 봐야 한다.

- 어떤 기간인가
- 어떤 거래처인가
- 어떤 품목인가
- 어떤 창고인가
- 마감 이후 수정이 있었는가
- 삭제나 취소 데이터가 있는가
- 반품이나 조정 전표가 있는가

## 10. 이 문서에서 꼭 가져갈 것

ERP는 회사의 업무 이벤트를 하나의 데이터 흐름으로 연결하는 시스템이다.

입사 초기에는 모든 메뉴를 외우기보다 다음 흐름을 먼저 익히는 것이 좋다.

```text
영업: 견적 -> 수주 -> 출고 -> 매출 -> 수금
구매: 발주 -> 입고 -> 매입 -> 지급
재고: 입고/출고/이동/조정
생산: BOM -> 계획 -> 지시 -> 실적 -> 입고
회계: 업무 결과 -> 전표 -> 결산
```

ERP 개발자는 이 흐름이 DB와 화면과 출력물에서 어떻게 표현되는지 계속 연결해서 봐야 한다.
