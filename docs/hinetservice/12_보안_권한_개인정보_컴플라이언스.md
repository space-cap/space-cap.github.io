# 보안·권한·개인정보·컴플라이언스

> 목표: ERP/MES/CRM 업무 시스템에서 개발자가 반드시 조심해야 할 보안과 권한, 개인정보 이슈를 이해한다.

## 1. 업무 시스템 보안이 중요한 이유

ERP, MES, CRM에는 회사의 핵심 데이터가 들어 있다.

- 매출과 매입
- 거래처 정보
- 고객 개인정보
- 생산 원가
- 재고 수량
- 품질 이력
- 세금계산서
- 급여와 인사 정보

이 데이터가 유출되거나 잘못 수정되면 금전 손실, 법적 문제, 고객 신뢰 하락으로 이어질 수 있다.

## 2. 권한 관리

업무 시스템에서 권한은 단순히 로그인 가능 여부가 아니다.

권한은 보통 다음으로 나뉜다.

| 권한 | 설명 |
| --- | --- |
| 메뉴 권한 | 어떤 메뉴를 볼 수 있는가 |
| 조회 권한 | 어떤 데이터를 조회할 수 있는가 |
| 입력 권한 | 데이터를 등록할 수 있는가 |
| 수정 권한 | 기존 데이터를 수정할 수 있는가 |
| 삭제 권한 | 데이터를 삭제하거나 취소할 수 있는가 |
| 승인 권한 | 결재나 마감을 승인할 수 있는가 |
| 출력 권한 | 출력물이나 엑셀 다운로드가 가능한가 |

개발자는 기능을 만들 때 "누구나 쓰면 되는가"를 반드시 확인해야 한다.

## 3. 데이터 권한

메뉴가 보여도 모든 데이터를 보면 안 되는 경우가 있다.

예를 들어 영업사원은 자기 거래처만 볼 수 있고, 지점 사용자는 자기 창고 재고만 볼 수 있으며, 인사 담당자만 급여 정보를 볼 수 있다.

데이터 권한 조건은 조회 쿼리, 엑셀 다운로드, 리포트 출력에도 동일하게 적용되어야 한다.

## 4. 개인정보

CRM과 ERP에는 개인정보가 포함될 수 있다.

자주 등장하는 개인정보는 다음과 같다.

- 이름
- 휴대폰 번호
- 이메일
- 주소
- 계좌번호
- 상담 이력
- 구매 이력
- AS 이력

개발 시 주의할 점은 다음과 같다.

- 필요한 사람에게만 보여준다.
- 엑셀 다운로드 권한을 제한한다.
- 로그에 개인정보를 남기지 않는다.
- 테스트 데이터로 실제 개인정보를 사용하지 않는다.
- 화면 공유나 캡처 시 개인정보를 가린다.
- 퇴사자 계정을 비활성화한다.

## 5. 계정과 비밀번호

업무 시스템에서 계정 공유는 위험하다.

계정을 공유하면 누가 데이터를 수정했는지 알 수 없다.

개발자는 다음 기본을 지켜야 한다.

- 개인 계정을 사용한다.
- 비밀번호를 메신저나 문서에 평문으로 공유하지 않는다.
- 운영 서버 접속 계정은 최소 권한으로 사용한다.
- 퇴사자와 외부 인력 계정은 정리한다.
- 원격접속 기록을 남긴다.

## 6. 운영 DB 접근

운영 DB는 매우 조심해야 한다.

조회 권한과 수정 권한을 분리하는 것이 좋다.

운영 DB 수정이 필요한 경우에는 다음 절차를 따른다.

1. 수정 사유 확인
2. 영향 범위 확인
3. 고객 또는 내부 승인
4. 수정 전 백업
5. 수정 SQL 리뷰
6. 트랜잭션 처리
7. 수정 후 검증
8. 작업 기록 보관

## 7. 공공기관·외부 연동 주의점

하이네트서비스 공개 서비스에는 국세청, 식약처 공급내역 보고, 축산물이력제 같은 공공 성격의 연동이 포함되어 있다.

이런 연동은 단순 편의 기능이 아니라 법적 신고나 증빙과 연결될 수 있다.

주의할 점은 다음과 같다.

- 신고 기한
- 필수 항목
- 인증서 또는 API 키 관리
- 전송 성공 여부
- 실패 재처리
- 신고 이력 보관
- 수정 신고 가능 여부

전송 실패를 조용히 무시하면 고객이 법적 불이익을 받을 수 있다.

## 8. 감사 추적

감사 추적은 누가, 언제, 무엇을 변경했는지 남기는 것이다.

중요 데이터는 다음 이력이 필요할 수 있다.

- 등록자
- 등록일시
- 수정자
- 수정일시
- 삭제자
- 삭제일시
- 변경 전 값
- 변경 후 값
- 변경 사유

특히 금액, 재고, 권한, 마감, 세금 관련 데이터는 이력이 중요하다.

## 9. 개발자가 지켜야 할 보안 습관

- 운영 DB 정보를 개인 메모장에 평문 저장하지 않는다.
- 고객 데이터를 외부 서비스에 업로드하지 않는다.
- 로그에 주민번호, 전화번호, 토큰을 남기지 않는다.
- API 키를 소스에 직접 넣지 않는다.
- 권한 체크를 화면에서만 하지 않고 서버에서도 한다.
- 엑셀 다운로드는 권한과 마스킹을 확인한다.
- 테스트 후 임시 계정과 임시 파일을 정리한다.

## 10. 이 문서에서 꼭 가져갈 것

ERP/MES/CRM 보안은 특별한 해킹 대응만을 뜻하지 않는다.

권한을 잘못 열어주는 것, 운영 DB를 무심코 수정하는 것, 개인정보가 들어간 엑셀을 잘못 공유하는 것 모두 보안 사고가 될 수 있다. 입사 초기부터 조심하는 습관을 만들어야 한다.
