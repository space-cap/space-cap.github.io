# 입사 초기 90일 학습 로드맵

> 목표: 하이네트서비스 입사 후 첫 3개월 동안 무엇을 어떤 순서로 익히면 좋을지 정리한다.

## 1. 전체 방향

입사 초기에는 모든 것을 한 번에 잘하려고 하기보다, 업무 시스템의 흐름을 놓치지 않는 것이 중요하다.

첫 90일의 목표는 다음과 같다.

1. 회사 제품명과 메뉴 구조를 익힌다.
2. ERP의 기본 흐름을 이해한다.
3. MES의 현장 데이터를 이해한다.
4. DB와 화면, 출력물, 연동의 관계를 익힌다.
5. 고객 문의를 업무 흐름으로 해석하는 습관을 만든다.
6. 작은 수정 개발이나 데이터 확인 업무를 독립적으로 처리할 준비를 한다.

## 2. 1주차: 회사와 제품 이름 익히기

첫 주에는 깊이보다 지도가 중요하다.

### 해야 할 일

- 하이네트서비스 공식 제품명 익히기
- `HIPRO`, `WINPOWER`, `HIPRO-MES`, 그룹웨어의 차이 이해하기
- 고객지원 게시판, FAQ, 자료실에 어떤 내용이 있는지 훑어보기
- 회사에서 사용하는 개발 도구와 협업 도구 설치하기
- 소스 저장소 구조 파악하기
- 테스트 또는 데모 계정으로 주요 메뉴 눌러보기

### 꼭 물어볼 질문

- 현재 가장 많이 유지보수하는 제품은 무엇인가?
- 신규 프로젝트와 유지보수 업무 비율은 어느 정도인가?
- 고객 문의는 어떤 채널로 들어오는가?
- 개발자가 직접 고객 응대를 하는가?
- 배포는 누가, 언제, 어떻게 하는가?
- 실수하면 큰일 나는 운영 작업은 무엇인가?

### 1주차 목표

제품 이름을 들었을 때 대략 어떤 업무 시스템인지 말할 수 있으면 된다.

예를 들어 "HIPRO는 유통·제조 ERP, HIPRO-MES는 제조 현장 실행 시스템, 그룹웨어는 내부 결재와 협업 시스템" 정도로 설명할 수 있으면 좋다.

## 3. 2~4주차: ERP 기본 흐름 익히기

두 번째 단계에서는 ERP 흐름을 집중적으로 익힌다.

### 집중 학습 주제

- 거래처
- 품목
- 창고
- 수주
- 출고
- 매출
- 수금
- 발주
- 입고
- 매입
- 재고
- 전표

### 실습하면 좋은 시나리오

가능하다면 테스트 환경에서 다음 흐름을 직접 해 본다.

```text
거래처 등록
-> 품목 등록
-> 수주 등록
-> 출고 처리
-> 매출 확인
-> 수금 등록
-> 거래처별 원장 확인
```

구매 흐름도 해 본다.

```text
공급사 등록
-> 발주 등록
-> 입고 처리
-> 매입 확인
-> 재고 증가 확인
```

### DB 관점으로 볼 것

화면을 누른 뒤 DB에서 어떤 데이터가 생기는지 확인한다.

- 헤더와 상세 테이블이 나뉘는가?
- 전표번호나 문서번호는 어떻게 생성되는가?
- 삭제는 실제 삭제인가, 상태값 변경인가?
- 취소 데이터는 어떻게 남는가?
- 등록일, 수정일, 사용자 정보가 남는가?

### 1개월차 목표

ERP의 기본 흐름을 설명할 수 있어야 한다.

특히 다음 질문에 답할 수 있으면 좋다.

- 수주와 매출은 무엇이 다른가?
- 입고와 매입은 무엇이 다른가?
- 출고하면 재고는 어떻게 변하는가?
- 미수금은 언제 생기고 언제 줄어드는가?
- 품목코드가 중복되면 어떤 문제가 생기는가?

## 4. 2개월차: MES와 현장 연동 이해하기

두 번째 달에는 MES를 익힌다.

### 집중 학습 주제

- 생산계획
- 작업지시
- 공정
- 설비
- 작업자
- 생산실적
- LOT
- 불량
- 검사
- 바코드
- PDA
- POP

### 실습하면 좋은 시나리오

```text
ERP에서 작업지시 생성
-> MES에서 작업지시 조회
-> 작업 시작
-> 자재 투입
-> 생산실적 등록
-> 검사 결과 등록
-> 완제품 입고
-> ERP 재고 반영 확인
```

### 현장 관점으로 볼 것

MES는 현장성이 중요하다.

- 작업자가 장갑을 끼고도 사용할 수 있는 화면인가?
- 바코드 스캔 실패 시 수동 입력이 가능한가?
- 생산 도중 네트워크가 끊기면 어떻게 되는가?
- 같은 작업을 여러 명이 동시에 처리할 수 있는가?
- 불량을 등록하면 재고와 실적에 어떻게 반영되는가?
- LOT 추적은 어느 단계까지 가능한가?

### 2개월차 목표

ERP와 MES의 차이를 말할 수 있어야 한다.

예를 들어 "ERP는 생산계획과 재고/원가를 관리하고, MES는 현장 작업지시와 공정실적, 설비, 품질, LOT 이력을 관리한다"라고 설명할 수 있으면 좋다.

## 5. 3개월차: 작은 업무를 독립적으로 처리하기

세 번째 달에는 작은 수정과 문의 대응을 맡을 준비를 한다.

### 맡아볼 만한 업무

- 조회 조건 추가
- 화면 컬럼 추가
- 엑셀 다운로드 항목 추가
- 출력물 문구 수정
- 간단한 코드성 데이터 추가
- 고객 문의 로그 확인
- 재고나 매출 집계 쿼리 분석
- 테스트 시나리오 작성
- 릴리스 노트 초안 작성

### 업무 처리 순서

작은 요청이라도 다음 순서로 처리한다.

1. 요청 내용을 자신의 말로 다시 정리한다.
2. 관련 화면과 업무 흐름을 확인한다.
3. 영향 범위를 본다.
4. 수정 대상 파일과 테이블을 확인한다.
5. 테스트 데이터를 준비한다.
6. 수정한다.
7. 정상 케이스와 예외 케이스를 테스트한다.
8. 변경 내용을 기록한다.
9. 배포나 운영 반영 절차를 따른다.

### 3개월차 목표

작은 수정 개발이나 데이터 확인 업무를 선배 검토 아래 처리할 수 있으면 된다.

아직 모든 것을 혼자 해결하지 않아도 된다. 대신 문제를 구조화해서 질문할 수 있어야 한다.

좋은 질문은 이런 형태다.

```text
수주 등록 화면에서 납기일 검색 조건을 추가하는 요청입니다.
화면에는 조건을 추가했고, 조회 쿼리에는 SO_DUE_DATE 컬럼을 조건으로 넣으려고 합니다.
다만 기존 쿼리가 출고일 기준으로도 사용되는 것 같아 영향 범위를 확인하고 싶습니다.
```

## 6. 매주 반복 체크리스트

매주 금요일마다 다음을 점검한다.

- 이번 주에 새로 배운 업무 용어 5개를 적었는가?
- 이번 주에 본 화면 3개를 업무 흐름으로 설명할 수 있는가?
- 이번 주에 본 테이블 3개의 역할을 설명할 수 있는가?
- 고객 문의를 하나라도 원인 흐름으로 추적해 보았는가?
- 선배에게 물어본 질문과 답변을 정리했는가?
- 다음 주에 배울 주제를 하나 정했는가?

## 7. 개인 학습 과제

### 과제 1. ERP 흐름 그림 그리기

아래 흐름을 손으로 그려 본다.

```text
거래처 -> 수주 -> 출고 -> 매출 -> 수금
품목 -> 발주 -> 입고 -> 매입 -> 지급
품목 -> 생산계획 -> 작업지시 -> 생산실적 -> 제품입고
```

각 단계에서 어떤 테이블이나 화면이 관련되는지 옆에 적는다.

### 과제 2. 용어사전 만들기

회사에서 들은 낯선 용어를 매일 3개씩 적는다.

형식은 다음과 같이 한다.

```text
용어:
들은 문장:
내가 이해한 뜻:
선배에게 확인한 뜻:
관련 화면/테이블:
```

### 과제 3. 고객 문의 분석 연습

FAQ나 과거 문의를 하나 골라서 다음을 정리한다.

- 고객이 말한 증상
- 실제 업무 흐름
- 가능한 원인
- 확인해야 할 화면
- 확인해야 할 데이터
- 임시 조치
- 재발 방지 방법

## 8. 하면 좋은 습관

- 모르는 용어를 부끄러워하지 말고 바로 적는다.
- 고객 말을 개발 용어로 번역하기 전에 업무 흐름으로 먼저 이해한다.
- 운영 DB를 볼 때는 조회부터 하고, 수정은 절차를 확인한다.
- 화면 하나를 수정할 때 출력물과 엑셀 다운로드도 같이 생각한다.
- "왜 이 기능이 필요한가"를 계속 묻는다.
- 배운 내용을 짧게 문서로 남긴다.

## 9. 피해야 할 실수

- 화면만 보고 DB 흐름을 확인하지 않는 것
- DB만 보고 실제 업무 흐름을 확인하지 않는 것
- 고객 요청을 영향 분석 없이 바로 가능하다고 말하는 것
- 운영 데이터 수정 전 백업과 승인 여부를 확인하지 않는 것
- 오류를 고쳤지만 원인을 기록하지 않는 것
- 선배에게 질문할 때 자신이 확인한 내용을 정리하지 않는 것

## 10. 90일 후 기대 상태

90일이 지나면 다음 정도를 목표로 한다.

- 하이네트서비스 제품군의 역할을 설명할 수 있다.
- ERP 기본 흐름을 업무 관점으로 설명할 수 있다.
- MES 기본 흐름과 ERP 연동 관계를 설명할 수 있다.
- 주요 용어를 듣고 어느 업무 영역인지 구분할 수 있다.
- 작은 화면 수정이나 조회 쿼리 수정의 영향 범위를 생각할 수 있다.
- 고객 문의를 증상이 아니라 업무 흐름으로 분석하려고 시도한다.
- 선배에게 구체적인 질문을 할 수 있다.

처음 90일의 핵심은 완벽함이 아니라 방향감각이다. 업무 시스템은 오래 볼수록 연결이 보이는 분야다. 처음에는 낯선 단어가 많지만, 수주·출고·재고·생산·실적 같은 흐름을 잡으면 나머지 용어들이 자리를 찾기 시작한다.
