# 실무 면담·온보딩 질문 체크리스트

> 목표: 입사 초기에 선배, PM, 개발 리더에게 물어볼 질문을 정리해 빠르게 업무 맥락을 잡는다.

## 1. 회사 제품 구조 질문

- 현재 회사의 주력 제품은 무엇인가?
- `HIPRO`, `WINPOWER`, `HIPRO-MES`는 각각 어떤 고객이 주로 쓰는가?
- 제품별로 소스와 DB가 분리되어 있는가?
- 고객별 커스터마이징은 어떤 방식으로 관리하는가?
- 공통 기능과 고객별 기능을 어떻게 구분하는가?
- 제품 버전 관리는 어떻게 하는가?
- 그룹웨어는 ERP와 어떤 방식으로 연동되는가?

## 2. 고객과 업종 질문

- 가장 많은 고객 업종은 무엇인가?
- 제조와 유통 중 어느 쪽 비중이 큰가?
- 식품, 축산, 케이블, 도소매처럼 특화된 업종이 있는가?
- 신규 구축 고객과 오래된 유지보수 고객의 비율은 어느 정도인가?
- 고객사가 가장 자주 요청하는 기능은 무엇인가?
- 고객이 가장 불편해하는 지점은 무엇인가?

## 3. 개발 환경 질문

- 주 개발 언어와 프레임워크는 무엇인가?
- IDE는 무엇을 사용하는가?
- 로컬 개발 환경은 어떻게 구성하는가?
- 테스트 DB나 데모 DB가 있는가?
- 소스 형상관리는 무엇을 사용하는가?
- 브랜치 전략이나 배포 브랜치 규칙이 있는가?
- 코드 리뷰를 하는가?
- 공통 라이브러리나 공통 프레임워크가 있는가?

## 4. DB 질문

- 주로 사용하는 DB는 무엇인가?
- 고객별 DB가 분리되어 있는가?
- 테이블 명명 규칙이 있는가?
- 마스터 테이블과 트랜잭션 테이블을 구분하는 기준은 무엇인가?
- 운영 DB 조회 권한은 어떻게 받는가?
- 운영 DB 수정 절차는 무엇인가?
- 백업 정책은 어떻게 되는가?
- 절대 직접 수정하면 안 되는 테이블은 무엇인가?
- 자주 보는 핵심 테이블은 무엇인가?

## 5. 배포와 운영 질문

- 배포는 누가 담당하는가?
- 배포 시간은 주로 언제인가?
- 고객 서버에 직접 접속하는가?
- 배포 전 체크리스트가 있는가?
- 배포 실패 시 롤백 절차가 있는가?
- 패치 이력은 어디에 기록하는가?
- 고객 공지는 누가 하는가?
- 운영 로그는 어디에서 확인하는가?

## 6. 고객지원 질문

- 고객 문의는 어떤 채널로 들어오는가?
- 개발자가 직접 고객과 통화하는가?
- 문의 접수부터 처리 완료까지 흐름은 어떻게 되는가?
- 긴급 장애 기준은 무엇인가?
- 자주 들어오는 문의 유형은 무엇인가?
- 고객에게 답변할 때 정해진 양식이 있는가?
- 원격지원 도구는 무엇을 사용하는가?
- 장애 보고서는 어떤 경우에 작성하는가?

## 7. 프로젝트 산출물 질문

- 요구사항정의서 양식이 있는가?
- 화면설계서는 어떤 도구로 작성하는가?
- ERD는 최신 상태로 관리되는가?
- 인터페이스 정의서 샘플이 있는가?
- 테스트 결과서는 어떻게 작성하는가?
- 정부지원사업 산출물 템플릿이 있는가?
- 완료보고서나 검수확인서 양식이 있는가?

## 8. ERP 업무 질문

- 수주, 출고, 매출 흐름은 제품에서 어떻게 연결되는가?
- 발주, 입고, 매입 흐름은 어떻게 연결되는가?
- 재고는 어떤 이벤트에서 증가하고 감소하는가?
- 마감 이후 수정은 어떻게 제한하는가?
- 미수금과 원장은 어떤 기준으로 계산되는가?
- 세금계산서나 국세청 연동은 어느 범위까지 지원하는가?
- 거래처별 단가나 품목별 단가 정책은 어떻게 처리하는가?

## 9. MES 업무 질문

- ERP 작업지시가 MES로 어떻게 내려가는가?
- MES 생산실적은 ERP에 어떻게 반영되는가?
- LOT 관리는 어느 단계까지 하는가?
- 바코드 라벨은 어디에서 출력하는가?
- PDA나 POP 화면은 어떤 방식으로 개발하는가?
- 설비 연동 경험이 있는가?
- 불량과 검사 데이터는 어떻게 관리하는가?
- 현장 방문 시 개발자가 확인해야 할 것은 무엇인가?

## 10. 연동 질문

- 가장 많이 하는 외부 연동은 무엇인가?
- 쇼핑몰 주문 수집은 어떤 방식으로 하는가?
- 오픈마켓 송장 전송은 어떻게 처리하는가?
- 택배사 연동 실패 시 재처리는 어떻게 하는가?
- 은행이나 국세청 연동 인증 정보는 어떻게 관리하는가?
- 알림톡 발송 이력은 어디에 남는가?
- 연동 로그를 볼 수 있는 관리자 화면이 있는가?

## 11. 보안과 권한 질문

- 메뉴 권한과 데이터 권한은 어떻게 관리하는가?
- 엑셀 다운로드 권한은 따로 있는가?
- 개인정보 마스킹 정책이 있는가?
- 운영 DB 접속 기록을 남기는가?
- 고객 서버 접속 계정은 어떻게 관리하는가?
- 퇴사자 계정 정리는 누가 하는가?
- 로그에 개인정보가 남지 않도록 하는 규칙이 있는가?

## 12. 하지 말아야 할 실수 질문

입사 초기에는 "무엇을 해야 하는가"만큼 "무엇을 하면 안 되는가"를 아는 것이 중요하다.

선배에게 다음을 꼭 물어본다.

- 운영 DB에서 절대 하면 안 되는 작업은 무엇인가?
- 고객에게 바로 답하면 안 되는 유형의 질문은 무엇인가?
- 배포 전에 반드시 확인해야 하는 것은 무엇인가?
- 과거에 큰 장애가 났던 원인은 무엇인가?
- 초보자가 자주 실수하는 기능은 무엇인가?
- 수정 전 반드시 백업해야 하는 테이블은 무엇인가?
- 고객별로 특별히 조심해야 하는 업무 규칙이 있는가?

## 13. 질문할 때 좋은 형식

막연히 "이거 모르겠습니다"라고 묻기보다 자신이 확인한 내용을 함께 말하면 답변을 받기 쉽다.

```text
수주 등록 화면에서 출고 예정일을 추가하는 요청을 확인했습니다.
현재 화면과 조회 쿼리는 찾았고, 저장 테이블 후보는 SO_HEADER로 보입니다.
다만 출고 화면에서도 이 값을 쓰는지 모르겠습니다.
영향 범위를 어디까지 확인하면 될까요?
```

좋은 질문에는 다음이 들어간다.

- 어떤 업무인지
- 어떤 화면인지
- 자신이 어디까지 확인했는지
- 막힌 지점이 무엇인지
- 어떤 결정을 받아야 하는지

## 14. 개인 온보딩 기록 양식

입사 초기에는 매일 짧게 기록한다.

```text
날짜:
오늘 본 화면:
오늘 본 테이블:
새로 배운 용어:
처리한 업무:
막힌 점:
선배에게 들은 답변:
내일 확인할 것:
```

이 기록은 1개월 뒤 큰 자산이 된다.

## 15. 이 문서에서 꼭 가져갈 것

입사 초기는 질문을 잘하는 사람이 빨리 성장한다.

좋은 질문은 무지를 드러내는 것이 아니라, 문제를 정리해서 다음 단계로 나아가려는 태도다. 제품 구조, DB, 배포, 고객지원, ERP/MES 흐름, 보안, 하지 말아야 할 실수를 빠르게 확인하면 실무 적응 속도가 훨씬 빨라진다.
