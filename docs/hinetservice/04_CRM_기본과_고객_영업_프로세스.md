# CRM 기본과 고객·영업 프로세스

> 목표: CRM이 ERP와 어떻게 다르고, 고객 접점 업무를 시스템으로 관리할 때 무엇을 봐야 하는지 이해한다.

## 1. CRM이란 무엇인가

CRM은 `Customer Relationship Management`의 약자다. 고객관계관리라고 부른다.

ERP가 거래와 재고, 회계처럼 이미 발생한 업무를 정확히 처리하는 데 강하다면, CRM은 고객과의 관계와 영업 활동을 관리하는 데 초점이 있다.

CRM은 다음 질문에 답한다.

- 이 고객은 누구인가?
- 어떤 문의와 상담 이력이 있었는가?
- 어떤 상품에 관심이 있는가?
- 견적은 어디까지 진행되었는가?
- 계약 가능성은 어느 정도인가?
- AS나 클레임 이력이 있는가?
- 어떤 알림이나 메시지를 보냈는가?

## 2. ERP의 거래처와 CRM의 고객은 다르다

ERP의 거래처는 보통 매출, 매입, 세금계산서, 미수금 같은 거래 처리를 위한 기준정보다.

CRM의 고객은 거래 전 단계까지 포함한다. 아직 매출이 발생하지 않은 잠재 고객, 상담만 한 고객, 전시회에서 명함을 받은 고객도 관리 대상이 될 수 있다.

| 구분 | ERP 거래처 | CRM 고객 |
| --- | --- | --- |
| 목적 | 거래 처리와 회계 | 관계 관리와 영업 |
| 시점 | 거래가 발생한 이후가 많음 | 거래 전부터 관리 |
| 핵심 데이터 | 사업자번호, 청구처, 단가, 미수금 | 담당자, 상담이력, 관심상품, 영업단계 |
| 주요 사용자 | 영업, 회계, 물류 | 영업, 고객지원, 마케팅, AS |

실무에서는 CRM 고객이 계약 후 ERP 거래처로 전환되거나, ERP 거래처의 상담·AS 이력을 CRM 성격으로 관리하는 구조가 많다.

## 3. 고객, 거래처, 담당자, 리드

CRM에서 자주 나오는 기본 개념은 다음과 같다.

| 용어 | 의미 |
| --- | --- |
| 리드 | 아직 거래 가능성을 검토 중인 잠재 고객 |
| 고객 | 제품이나 서비스에 관심이 있거나 구매한 대상 |
| 거래처 | 실제 거래가 발생하는 회사나 사업자 |
| 담당자 | 거래처 내부의 연락 대상자 |
| 영업기회 | 계약 가능성이 있는 구체적인 판매 건 |
| 캠페인 | 문자, 알림톡, 이메일, 행사 등 고객 접촉 활동 |

예를 들어 전시회에서 만난 A회사 김대리의 명함은 처음에는 리드다. 상담 후 견적을 보내면 영업기회가 생긴다. 계약이 되면 ERP 거래처로 등록되고, 이후 매출과 수금이 ERP에서 관리된다.

## 4. 영업 프로세스

일반적인 CRM 영업 흐름은 다음과 같다.

```text
리드 등록 -> 상담 -> 니즈 파악 -> 견적 -> 제안 -> 계약 -> ERP 거래 처리 -> 사후관리
```

### 4.1 상담

고객과 통화하거나 방문 상담한 기록을 남긴다.

상담이력에는 다음 정보가 들어간다.

- 상담일시
- 상담자
- 고객명
- 담당자
- 문의 내용
- 조치 내용
- 다음 할 일

### 4.2 영업기회

구체적인 매출 가능성이 생기면 영업기회로 관리한다.

주요 항목은 다음과 같다.

- 예상 매출 금액
- 예상 계약일
- 영업 단계
- 성공 가능성
- 경쟁사
- 담당 영업사원

### 4.3 견적과 계약

CRM에서 견적을 만들고, 계약이 확정되면 ERP의 수주나 거래처 정보로 연결될 수 있다.

이때 중요한 것은 같은 고객을 중복 등록하지 않는 것이다.

## 5. 고객지원, AS, 클레임

CRM은 신규 영업뿐 아니라 기존 고객 지원에도 쓰인다.

| 업무 | 설명 |
| --- | --- |
| 문의 | 사용법, 가격, 배송, 제품 정보 질문 |
| AS | 제품 판매 후 수리나 점검 요청 |
| 클레임 | 불만, 불량, 지연, 오배송 등 문제 제기 |
| 재문의 | 과거 문의와 연결되는 반복 문의 |
| 만족도 | 처리 결과에 대한 고객 반응 |

업무 시스템에서는 고객지원 이력이 ERP 거래와 연결될 때 가치가 커진다.

예를 들어 특정 제품 LOT에서 클레임이 반복되면 MES의 생산·검사 이력과 연결해 원인을 추적할 수 있다.

## 6. 전화연동, 알림톡, 문자

하이네트서비스의 공개 서비스에는 전화연동과 카카오 알림톡이 포함되어 있다. 이런 기능은 CRM 성격의 고객 접점 기능이다.

### 6.1 전화연동

전화가 오면 발신번호로 고객 정보를 찾아 화면에 보여줄 수 있다.

개발자가 볼 포인트는 다음과 같다.

- 전화번호 형식이 통일되어 있는가
- 같은 전화번호를 여러 거래처가 쓰는가
- 담당자 전화와 회사 대표번호를 구분하는가
- 통화 이력을 저장하는가
- 개인정보 접근 권한을 제한하는가

### 6.2 알림톡과 문자

배송 안내, AS 처리 안내, 입금 요청, 예약 알림 등을 보낼 수 있다.

주의할 점은 다음과 같다.

- 발송 템플릿 승인 여부
- 수신자 번호 정확성
- 발송 실패 재처리
- 야간 발송 제한
- 수신 동의 여부
- 발송 이력 보관

## 7. 개인정보 주의점

CRM은 개인정보를 많이 다룬다.

다음 정보는 특히 조심해야 한다.

- 이름
- 휴대폰 번호
- 이메일
- 주소
- 상담 내용
- 구매 이력
- AS 이력

개발자는 화면에 보여주는 정보, 엑셀 다운로드, 로그 출력, 테스트 데이터 사용을 모두 주의해야 한다.

특히 운영 데이터를 로컬 개발 환경에 복사하거나, 고객 전화번호가 포함된 로그를 외부에 공유하는 일은 피해야 한다.

## 8. ERP·MES와 CRM이 연결되는 지점

CRM은 혼자 떨어져 있으면 가치가 제한적이다. ERP와 MES 데이터와 연결될 때 고객 대응 속도가 빨라진다.

| CRM 질문 | 연결되는 시스템 |
| --- | --- |
| 이 고객에게 최근 무엇을 팔았는가 | ERP 매출, 출고 |
| 배송이 어디까지 진행됐는가 | ERP 출고, 택배 연동 |
| 클레임 제품은 언제 생산됐는가 | MES 생산실적, LOT |
| AS 대상 제품의 시리얼은 무엇인가 | ERP 출고, MES 생산 이력 |
| 미수금이 있는 고객인가 | ERP 수금, 미수금 |

## 9. 개발자가 자주 만나는 CRM 요청

- 상담이력 검색 조건 추가
- 고객 전화번호 중복 체크
- 알림톡 템플릿 추가
- 고객별 매출 이력 조회
- AS 처리 상태 추가
- 클레임 유형 코드 추가
- 영업 담당자별 실적 조회
- 엑셀 다운로드 개인정보 마스킹

CRM 요청은 화면상으로 단순해 보여도 개인정보와 권한이 걸려 있는 경우가 많다.

## 10. 이 문서에서 꼭 가져갈 것

CRM은 고객과의 접점을 관리하는 시스템이다. ERP가 거래 결과를 관리한다면 CRM은 관계와 과정을 관리한다.

입사 초기에는 고객, 거래처, 담당자, 상담이력, 영업기회, AS, 클레임, 알림톡, 전화연동이라는 단어를 먼저 익히면 된다.
